# Changelog

All notable changes to Controls are documented here.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses [Semantic Versioning](https://semver.org/spec/v2.0.0.html). Each phase ships a minor release (`0.N.0`); fixes ship as patches. The save-format `schemaVersion` and the `catalogVersion` are versioned independently and recorded in [`docs/history.md`](docs/history.md).

## [Unreleased]

### Added

- **Batteries that run down, and two bench power supplies** (F2.4 part 1, [simulation architecture](docs/architecture/simulation.md#power-sources-f24)). The battery's voltage now follows how charged it is: a new 12 V 7 Ah sealed lead-acid battery rests at 12.9 V, falls towards 11.8 V as it empties, and the simulator counts the charge it delivers (or takes) every millisecond, kept in the save. Two new devices in the catalogue: a **Brindlecore BX-217 bench supply** (0–30 V, 0–5 A) whose voltage, current limit and output switch you set with `device.operate`, which holds its voltage until the load asks for more than the limit and then holds the current, crossing over cleanly with no flicker between the two; and a **Railwick RW-24-5 24 V 5 A DIN-rail supply** with a 6 A limit that, on a short or a sustained overload, switches off for a second and retries ("hiccup"), raising `hiccup` sim events. Every value has a cited source or says it is a game-design choice.
- **Batteries can't run forever or overfill** (F2.4 review). A flat battery's voltage collapses over its last 2 % of charge, so a load left on it stops; and a nearly full one needs more voltage to keep charging (up to its 14.4 V gassing voltage), so a 13.8 V float charger's current tapers to nothing.
- **Saves can't set a supply out of range** (F2.4 review): loading checks each control (a setpoint, a current limit) against the device's range, and refuses a save outside it as invalid device state.
- **The sources scenario** (`apps/sim-cli/scenarios/sources.console`, F2.4): a DIN PSU hiccuping, a bench supply in current limit and a battery discharging, with hashes pinned in Node and in the browser, and its save `fixtures/v2/ctrl/sources-engine-4.ctrl`.
- **Mains supplies behind a real transformer impedance** (F2.4 part 2, headless). Three utility services in the catalogue: a **120/240 V split-phase** service from a 25 kVA pole transformer, with L1, L2 and the neutral as separate terminals, and **208Y/120 V** (150 kVA) and **480Y/277 V** (1000 kVA) three-phase services, each behind an impedance worked out from its kVA, percent impedance and X/R ratio, so shorting one draws its real available fault current (about 5.2 kA, 10.4 kA and 20.9 kA). Plus a portable generator **stub** (7.5 kVA, 120/240 V) with no engine dynamics. They're driven from scripts and `sim-cli` for now; the service entrance and load centre come in P4.
- **ANSI C84.1 voltage ranges** (F2.4). The NEC region profile gains Range A and Range B, at the service and at the utilization point, as fractions of nominal (114–126 V for Range A service on 120 V).
- **The mains scenario** (`apps/sim-cli/scenarios/mains.console`, F2.4 part 2): a split-phase service loaded unevenly, with its hashes pinned in Node and in the browser (the series inductance's phasors, byte for byte).
- **Device readings say when they aren't readings** (ADR 0011 §5.4, amended). The battery and supplies publish snapshot records (EMF, terminal voltage, current, state of charge; output volts, amps and mode) with a `status` field: a reading only on a solved circuit, `unsettled` when the solver didn't settle, never a 0 V or 0 A that isn't real.
- **The battery, the bench supply and the DIN-rail supply have 3D models** (F2.4): procedural recipes sized from their catalogue entries, with coloured terminals and their fictional brand and model as the label, so they can be placed on the bench (`entity.place`, with an orientation).
- Developer (F2.4): `sim-core` device models in `devices/` (`BUILTIN_DEVICE_MODELS`, `BUILTIN_DEVICE_OUTPUTS`, `batteryEmfV`, the CV/CC `regulate`), two engine hooks (a bank's `afterSolve`, and a re-solve within the step when a layer changes a value, not only the topology) and `LayerContext.islandStatus`; catalogue kinds `supply.bench` and `supply.dinPsu` (a new kind is no `schemaVersion` bump; the battery's keys are unchanged); test helpers (`SourceHost`, a rheostat and fixed resistors) in `@controls/sim-core/testing`.

- **The simulator runs off the main thread in the game** (F2.3b part 2, [ADR 0011](docs/decisions/0011-sim-worker-contract.md)). Each game gets its own sim worker: New sandbox starts one, paused; a load or a new game replaces it; the main menu has none. Every command is forwarded with its tick, and sim time is paced from the wall clock in whole ticks, capped by what the worker has shown, so a heavy circuit slows down instead of piling up work. A hidden window suspends the sim, and console scripts hold it while they run. If the worker fails or stops responding for 3 s, the sim pauses with a notification and a **Restart simulation** button, which replays the session into a new worker; your world is never touched, but saving is refused until then.
- **Loading a save is checked in the sim worker** (F2.3b part 2): its replay log is replayed in a worker, never on the page, while the game shows "Checking save…". The same rule as `sim-cli` decides which saves are checked (another simulator version or more than 10 s of sim time: not checked, the log restarts).
- **The sim worker and its snapshot transport** (F2.3b part 1, [simulation architecture](docs/architecture/simulation.md#the-sim-worker-and-snapshot-transport-f23b), [ADR 0011](docs/decisions/0011-sim-worker-contract.md)). `@controls/sim-worker` can now run the simulator off the main thread: a module worker entry that follows the game's commands on a mirror bus (any mismatch is reported as a desync), steps the engine to each target in slices of at most 8 ms of wall time, and publishes snapshots into a `SharedArrayBuffer` through a seqlock after every solve (at most one per 4 ms), on every topology change and whenever it catches up, or by `postMessage` with identical bytes when the page isn't cross-origin isolated (`?sab=0`). It checks the protocol version first and refuses another one, refuses a big-endian platform, answers `state` and `snapshot` queries in order, and turns uncaught errors, unhandled rejections and CSP violations in its own scope into error messages. `@controls/sim-protocol` gains the buffer header and diagnostics area, `SnapshotWriter`, `SnapshotReader` and `SnapshotView`, the topology descriptor and `DescriptorIndex`, the message schemas, the pacing policy (`Pacer`, `SpeedMeter`), the transport's timing constants and `islandStatus`; `SimEngine` gains `topologyDescriptor()`, `encodeInto()` and `snapshotBytes()`, and reports island status through `islandStatus`. The game still runs the engine in-process until `SimHost` (part 2) drives the worker.
- **The AC circuit solver** (F2.2 part 2, [simulation architecture](docs/architecture/simulation.md#the-phasor-solver-f22-part-2)). `@controls/sim-core` can now solve mains circuits: `AcSolver` works out every voltage and current of an AC island as a **phasor** (an RMS magnitude and a phase) at the region's 60 Hz, by modified nodal analysis in complex arithmetic, with a complex dense LU for small islands and a complex sparse LU (the same AMD ordering and factorisation cache as DC) from 64 unknowns. It handles resistors, inductors (−j/ωL), capacitors (jωC) and phasor voltage sources behind an internal resistance, at 0°, 180° and ±120°, the angles of a split-phase or three-phase supply, taken from exact constants so results are bit-identical in Node and Chromium. Inductance and capacitance are value modes of an ordinary resistive branch, so no netlist or `topologyHash` changes. DC and AC islands share one solution record (DC first, then AC); an island holding both kinds of source stays a diagnostic and is not solved, since P2 has no converters. Two ideal sources in parallel are flagged `singular`, exactly as in DC. Checked against hand calculations (a series RL circuit at 60 Hz, an unbalanced 120/240 V split-phase load whose neutral carries the phasor sum of the line currents, and a balanced 208Y/120 V wye load whose neutral carries about nothing), by property tests (Kirchhoff's current law with complex magnitudes, the real-power balance and the reactive-power bookkeeping, linearity and superposition, dense against sparse), and **against ngspice on all 500 AC oracle circuits**, the worst value using 1.8e-5 of the allowed error for volts and 5.0e-4 for amps, on both LU paths. The dense and sparse paths' bits are pinned by new SHA-256 goldens. Not wired into the game yet (F2.3a; the utility and three-phase sources come in F2.4).
- **Region profiles** (F2.2 part 2). `@controls/catalog` gains `RegionProfile`: a region's supply frequency and nominal system voltages, each with a cited source. The NEC region is 60 Hz with 120/240 V split-phase, 208Y/120 V and 480Y/277 V three-phase services. Pending `electrical-realism-reviewer` sign-off.
- **The sim clock and engine loop** (F2.3a, [simulation architecture](docs/architecture/simulation.md#the-engine-loop-f23a), [ADR 0011](docs/decisions/0011-sim-worker-contract.md)). The simulator now runs: `SimEngine` in `@controls/sim-core` follows every command at its tick and lets sim time pass at 1 tick = 1 ms. Each tick it solves the circuit every 10 ticks, then runs the device layers in a fixed order (discrete, then continuous, such as a filament heating or a battery discharging, then protection, such as a fuse melting); a command that changes the circuit (closing a switch, connecting a lead) is solved at once, and a fuse that blows is re-solved in the same tick. Devices plug in as banks of preallocated state, rebuilt from their saved state at every change, with per-device tolerances drawn from the world's seed; the real battery, lamp and fuse models arrive in F2.4 and F2.5, so the hooks are proven with synthetic test devices. In scripts and console files: `game.advance(ms)`, `game.advanceTo(tick)` and `sim.step` let time pass (time passing is never undone and never logged), `game.probe('1:pos', '1:neg')` reads an ideal voltmeter between two terminals, `game.islands()` says which circuits are solved, `game.snapshot()` gives the simulation's published bytes, and `game.on('sim')` reports events (a fuse blowing, a circuit becoming singular or failing to settle). Circuits are never shown as a believable reading when they aren't one: two terminals on separate circuits read `floating`, ideal sources fighting read `singular`, a solve that didn't settle reads `unsettled`, and circuits the simulator can't solve yet (AC until the phasor solver, anything holding the lamp until its filament model) read `unsolved`. Saves and `world.hash` now hold the simulator's state, so a save at any tick loads and runs on exactly like the original, and the same seed and log give byte-identical snapshots in two runs, in a replay, and in Node and the browser (pinned by `apps/sim-cli/scenarios/sim-step.console` in both). The sim time commands `sim.setSpeed`, `sim.resume` and `sim.step` are now registered (there is no `sim.pause`: speed 0 pauses); pacing and the time controls arrive with the sim worker (F2.3b). `sim bench` gates one tick's device layers at the spec's 0.3 ms (about 0.015 ms for 250 loops of synthetic test devices). `@controls/sim-protocol` holds the snapshot codec, sim events and `materialiseWorld`.
- **The engine solves AC circuits** (F2.3a with F2.2 part 2's phasor solver). Every solve runs the DC solver, then the phasor solver for AC islands into the same record, at the region's 60 Hz. `game.probe` reads an AC circuit as its RMS voltage (what a meter shows by default) and the phasor, with a phase angle for display only (it never enters `world.hash`). A load on an AC circuit heats by its RMS current. Device models give AC values through a new `acValue` hook.
- **Saves from other simulator versions load, never refused** (decision D8). `engineCompatible(manifest, build)` decides whether a save's replay log is checked: a save from this engine and catalogue is replayed and compared as before; a migrated P1 save is checked but falls back to a new log if it doesn't match; any other version loads `world.json` as saved and starts a new log (`replay.status: 'restarted'`, reason `engine-changed`, an information toast in the game, never refused by the `refuse` policy). A save from this simulator version whose simulation state doesn't fit its circuit is refused with a plain reason (`start-failed`); one from another version has that state dropped and re-solved at the save's tick, never refused.
- **Loading never hangs on a long replay log.** A save's log is replayed to check it only if it covers at most `MAX_VERIFY_TICKS` (10 000 ticks, 10 s of sim time, chosen from `sim bench`'s new `plant-advance-1000-ticks` case: 45 ms per 1,000 ticks of the 2,000-node plant locally, so about 1.5 s on the slowest CI runner). A longer one, including a crafted `endTick` of 1e12, loads its world as saved with a new log (`too-long-to-verify`, an information toast, never refused). Whether long logs are later checkpointed so they can still be checked is an open decision in the plan.
- **The DC circuit solver** (F2.2 part 1, [simulation architecture](docs/architecture/simulation.md#the-dc-solver-f22-part-1)). `@controls/sim-core` can now work out the voltage at every terminal and the current in every lead, cell and lamp of a DC circuit: `DcSolver` solves each separate circuit (island) of the netlist by modified nodal analysis, with a dense LU factorisation using partial pivoting. It handles resistances, voltage sources with internal resistance (a battery's 23 mΩ) and current sources. A lamp left dangling off a battery, or one sitting on its own, reads 0 V across and 0 A through it, as it should. Two ideal sources wired straight across each other have no solution: that circuit is flagged `singular` and shows zeros instead of garbage, while other circuits on the bench still solve. Every result is reproducible bit for bit, in the netlist's canonical order, ready for the save's solution record. Values come from a hook that the battery and lamp models (F2.4, F2.5) will fill; until then a battery uses its nominal 12 V. Checked against hand calculations (a divider, a Wheatstone bridge, a battery into a lamp, two unequal batteries in parallel, floating circuits) and by property tests that Kirchhoff's current law and the power balance hold on random circuits. Not wired into the game yet (F2.3a).
- **Sparse LU, the factorisation cache and the nonlinear outer loop** (F2.2 part 3, [simulation architecture](docs/architecture/simulation.md#sparse-lu-and-the-factorisation-cache-f22-part-3)). Large circuits now solve fast enough for a plant: an island of 64 or more unknowns is solved by a sparse LU factorisation (Gilbert–Peierls, with threshold partial pivoting) in an approximate-minimum-degree (AMD) column order, both written from the published papers; smaller ones stay on the dense solver, bit for bit as before (the pinned 300-solve hash is unchanged). Each island's symbolic factorisation (its matrix pattern, the AMD order and a recorded stamp program) is kept in a **factorisation cache** keyed by `topologyHash`, a 16-topology least-recently-used cache: flipping a switch back to a position the cache has seen, or changing only values (a lamp's resistance, a supply's setpoint), skips rebuilding it, and the numeric factorisation replays the previous pivot sequence whenever the pivot rule would choose the same rows. Results are bit-identical whether the cache is cold, warm, shared or thrashed, and across solver instances, including after values change (sources switching between ideal and non-ideal); counters (`cache.stats`, `sparse.replays`) show the hits. The sparse path's bits are pinned by their own SHA-256 over 60 seeded large solves, beside the dense path's 300-solve pin. `DcSolver.solveNonlinear` adds the **outer loop** that F2.4's CV/CC supply and F2.5's lamp R(T) will use: a value hook per iteration, a warm start from the previous solution record, damping that halves on oscillation and recovers, a 50-iteration cap, and the island's `nonConverged` flag when it doesn't settle. Each current must settle to its own rounding (per branch, so a small current on a stiff busbar island isn't let off early). A `nonConverged` island's values are the last solve's and look real, so later features must show it as unsettled. Checked by property tests: dense and sparse agree (residuals on every circuit, values to 1e-9 on well-conditioned ones, up to 260 nodes), the DC oracle passes on both paths, floating clusters stay structurally pinned on the sparse path, the cache matches a reference LRU model, and the loop reaches closed-form fixed points and stays within 40 iterations (median 16) on random bench worlds with self-heating lamps. On the 2,000-node bench plant a re-solve after a switch toggle (compile, values and solve) takes about 1.5 ms locally with a warm cache and 4.6 ms for a topology never seen; `sim bench` reports both (median and p90), and the 2 ms gate stays reported-only: CI measured 2.12, 3.74 and 4.77 ms (Ubuntu, macOS, Windows), so the recompile is optimised next and the gate then switches on as a ratio to a calibration loop timed in the same process (plan F2.2 part 3b).
- **The ngspice oracle corpus and the 2,000-node bench plant** (F2.7, [ADR 0012](docs/decisions/0012-oracle-corpus.md), accepted for DC; [oracle guide](docs/guides/oracle.md)). The circuit solver will be checked against ngspice, a long-established circuit simulator, on 1,000 random circuits: 500 DC (resistors, batteries with internal resistance, current sources) and 500 AC at 60 Hz (resistors, inductors, capacitors and phasor sources at 0°, 180° and ±120°), each with 2 to 30 nodes and built so that every element shares a loop with a source (about 99 % of branches carry real current). A seeded generator in `@controls/sim-core/oracle` writes each circuit both as a SPICE deck and as a sim-core netlist, so the two can't describe different circuits. The decks and ngspice 47's results (17 significant digits, Sparse solver, `gmin` matched) are checked in under `libs/domain/sim-core/oracle/` (about 3.4 MB of text), so `pnpm verify` never needs ngspice: it checks that the decks regenerate byte for byte from the pinned seeds, that the results came from those exact decks, and that ngspice's answers satisfy every element's equation and Kirchhoff's current law in sim-core's netlist (worst residual 3e-9). `pnpm sim oracle regen` regenerates the corpus with an installed ngspice and fails clearly without one. The proposed tolerance is 1e-6 relative plus a floor of 1e-7 of the circuit's largest value, set by ngspice's own error of about 3e-9 against exact solutions; to be confirmed when the solver lands. `regen` runs ngspice with `-n` (no `.spiceinit`), writes into a staging folder and swaps the new corpus in only when every circuit has solved, stops at the first failure and times out a stuck run. **The DC solver is now checked against it in `pnpm verify`:** on all 500 DC circuits every node voltage and branch current agrees with ngspice, the worst using about a thousandth of the allowed error, and sim-core's own Kirchhoff checks hold on the same solutions. The AC solver is checked against the AC half the same way (F2.2 part 2). `pnpm sim bench` now builds a seeded 2,000-node plant (8 battery feeders, mostly radial trees of switches and lamps with some tie loops and open switches) and reports a from-scratch compile and the recompile after one switch is opened; the spec's budgets (2 ms re-solve after a topology change, 0.3 ms per tick) are listed as pending until the solver (F2.2 part 3) and the engine loop (F2.3a) exist.
- **The netlist compiler** (F2.1, [simulation architecture](docs/architecture/simulation.md)). `@controls/sim-core` now turns what is wired on the bench into the circuit the simulator will solve: `compileNetlist(world, catalog)` gives the **nodes** (terminals joined with no resistance, such as both sides of a closed switch), the **branches** (each test lead, battery cell and lamp filament) and the **islands** (separate circuits, each marked DC, AC or unpowered). It reads only connections, the catalogue's terminals and each device's state: a lamp set down touching a battery but not connected to it stays dark, and deleting a device takes its leads with it. Each test lead is one resistance, computed from copper's resistivity, its length and cross-section at a 20 °C bench plus 10 mΩ of clip contact at each end (about 41 mΩ for the 1 m lead). An open switch leaves its two terminals apart; a closed one joins them. Numbering is a pure function of the world, so the same bench always gives the same netlist, whatever order things were built or undone in. `topologyHash` fingerprints the circuit's shape but not its values, so swapping a lead for a longer one, or changing a setpoint, keeps it; toggling a switch changes it. `NetlistCompiler` recompiles incrementally after each edit, and a property test checks that it always matches a from-scratch compile, including when several edits arrive between compiles (an undo, then a reconnect that reuses the lead's id). `formatNetlist` prints the netlist as text for the coming `netlist.dump` console command. No solving yet (F2.2).
- **Test leads and operating devices** (P2 kickoff, decision D2, [ADR 0013](docs/decisions/0013-world-document-v2.md)). Three new commands, in the palette, the console and scripts: `lead.connect {ref, a, b}` joins two device terminals with a test lead (`lead.connect --ref.id lead.quillfern-test-1m --ref.version 1 --a.entity 1 --a.terminal pos --b.entity 2 --b.terminal a`), `lead.disconnect {id}` removes one, and `device.operate {id, control, value}` sets a device's control (`device.operate 2 closed true` closes the switch). All three can be undone: undoing a disconnect brings the lead back with the same id. Connecting is refused, changing nothing, for an entity or a terminal that doesn't exist, a prop, the same terminal twice, or two terminals that already have a lead between them; operating is refused for a control the device doesn't have or a value it doesn't take. Operating a device only records what the player did: it never looks at what the simulator has made of the device (a blown fuse, a battery's charge), so replay stays exact. No simulation runs yet; the leads and the switch position are saved and replayed. A new scenario, `apps/sim-cli/scenarios/bench-leads.{console,ts}`, places the battery, switch and lamp, connects three leads and operates the switch, and reaches one pinned hash headless, through `sim run --save`, from a checked-in v2 save and in the in-game console (`BENCH_LEADS_HASH`).
- The palette's argument forms take a value that may be `true`/`false`, a number or text in one field (`device.operate`'s `value`), typed like a console word.
- The argument schemas of the sim time commands (`sim.setSpeed {speed: 0|1|10|60}`, `sim.resume {}`, `sim.step {ticks}` with `MAX_STEP_TICKS` 600 000 and a 1 000-tick default; ADR 0011 §13) in `@controls/commands`, ahead of the commands themselves (F2.3a). Every logged command's arguments, these included, are now frozen as JSON Schema in `libs/domain/world-model/json-schema/command-args/`, with a staleness check: changing a command's arguments fails `pnpm verify` until the file is regenerated (and a changed shape needs a `schemaVersion` bump and a replay-log migration).
- **Save format `schemaVersion` 2: the world document for the circuit engine** (P2 kickoff, decision D3, [ADR 0013](docs/decisions/0013-world-document-v2.md)). A world now holds **connections** (test leads between device terminals, with their own `nextConnectionId` counter) and, on every entity, two **device state bags**: `state`, written only by commands (a switch's position), and `sim`, written only by the simulator (a battery's charge), checked against the device's model kind when a save loads. It also holds the simulator's last **solution record** (`sim`, or `null`), so a save made between two solves continues exactly. The manifest gains `simEngineVersion` and records the device catalogue's version; the replay log gains `firstSeq` (a rebased or restarted log keeps its command numbering) and `endTick` (where the log ends; an earlier one is refused). Every P1 save and fixture still loads: the v1 → v2 migration gives entities empty bags, worlds no connections and no solution, and logs `firstSeq` 0. A placed battery, switch or lamp starts with its model's initial state, and deleting a device removes its leads (undo puts them back). A save whose device state doesn't match the catalogue is refused with a plain reason (`invalid-device-state`). A restarted replay log now continues the dropped log's numbering. Rebasing a replay log onto a mid-session world (`rebaseReplayLog`) replays to the same hash. New fixtures under `libs/domain/save-format/fixtures/v2/`, and `*.v2.schema.json` JSON Schema exports.
- **Device catalogue v1** (P2 kickoff, decision D4). A new library, `@controls/catalog`, loads and validates the device catalogue in `content/devices/*.json`, one file per device: a 12 V 7 Ah sealed lead-acid battery, a 12 V 5 W incandescent lamp, an SPST toggle switch and a 1 m 18 AWG test lead with crocodile clips, all under fictional brands. Each entry gives its identity, brand and model name, category, size, terminals (id, label, position), electrical model (`kind` and parameters) and controls, and every number in it cites a `source`; loading refuses an entry with an unsourced value. The test lead's resistance is computed from copper's resistivity, its length and its cross-section (18 AWG, from the AWG diameter formula) with a temperature coefficient (`leadResistanceOhm`), never taken from a table, plus 10 mΩ of clip contact at each end: about 41 mΩ at 20 °C. `MODEL_KINDS` declares each model kind's parameters, terminals and state keys (who owns each key, commands or the simulator, its schema and its initial value); the state keys are save format, exported as `libs/domain/catalog/json-schema/device-state.<kind>.schema.json` with a staleness check. `catalogVersion` 1 is recorded in `docs/history.md`. Reviewed by `electrical-realism-reviewer`.
- Developer: P2 boundary and gate hardening (kickoff step 6). Three empty `type:domain` libs for the circuit engine, `@controls/sim-core`, `@controls/sim-protocol` and `@controls/catalog`, and `@controls/sim-worker` under a new `type:worker` tag that may depend only on domain libs (nothing but an app may depend on it; the renderer and features read snapshot types from `sim-protocol`). The determinism lint now covers `libs/sim-worker` except its `src/lib/pacing/` module. A new lint (decision D6; ADR 0014, to be written in F2.1) bans engine-dependent `Math` functions (`exp`, `log*`, `pow`, trigonometric and hyperbolic functions, `hypot`, `cbrt`) and `**` in `sim-core` source, so the engine gives byte-identical results in Node and Chromium. `pnpm sim bench` runs performance cases (warm-up, then the median of N runs) and prints a JSON report, exiting 1 when a case is over budget or not deterministic; the Nx `bench` target runs it from the built bundle as part of `pnpm verify`. It started with one placeholder case with no budget, which F2.7 replaced with the 2,000-node plant cases. Each new rule is proven to fire by `apps/sim-cli/src/lint-boundary.spec.ts` and `lint-determinism.spec.ts`.

### Changed

- **`SIM_PROTOCOL_VERSION` 2 → 3** (F2.3b, on F2.4): the battery's, bench supply's and DIN PSU's snapshot records are registered in `sim-protocol`'s `DEVICE_OUTPUT_SCHEMAS` (with `RECORD_STATUS_VALUES`), and a spec keeps them equal to what the models write. Nothing hashed changed: `SIM_ENGINE_VERSION` stays 4.
- **The DC per-tick path allocates almost nothing** (F2.4): the dense stamp and the outer loop's self-consistency check no longer box values into heap numbers, with bit-identical results (no golden moved). A battery into a load went from about 21 bytes a step to under 1. The per-tick allocation gates moved to their own spec file (`sim-core`'s `engine/allocation.spec.ts`), measure with V8's sampling heap profiler and gate on a median of windows, with tighter gates (DC 4, DIN PSU 6 and 10.5 bytes a step). Beside `engine.spec.ts`'s other tests they failed in 2–3 % of runs under load. The AC solver's stamp passes no values either, and both solvers loop over islands, nodes and branches by index (a `for…of`'s array iterator was allocated whenever the loop wasn't fully optimized): values cross the per-solve hooks by slot, not as arguments (V8 boxes a double passed to a call it doesn't inline, and a process with every device kind inlines less), and a layer's value-only change (a PSU's hiccup) re-solves without recompiling the world. The engine looks each branch's device hooks up once per rebuild rather than on every solve (a new device kind no longer deoptimizes the solve's value fill). Mixed worlds of several device kinds in one engine, as the game runs them, went from 28 bytes a step to under 4 and have gates of their own (6), as does a DIN PSU hiccuping into a heating load (from 70 to under 1); the AC gate went from 36 to 6, the split-phase service's from 38 to 6 (it measures under 2 bytes a step) and the shorted PSU's from 10.5 to 6. The gates run in their own uncovered Vitest run inside sim-core's `test` target (coverage made them 4–5× slower, past the 5 s timeout on CI).
- **Review fixes (F2.3b part 2, #58):** a save is never refused because the simulator crashed or was slow while checking it: the log restarts from the save's world instead (a new restart reason, `verify-unavailable`, shown as "couldn't check", never refused by policy), the check's deadline grows with the log, and a simulator that fails to start a save is given a second, slower chance before the load fails. Only a real mismatch between a save's solution record and its circuit refuses it as damaged; any other simulator failure says so (`sim-failed`). `SIM_PROTOCOL_VERSION` 1 → 2: a `start-failed` error carries its reason (nothing hashed changed). "Unsaved changes" counts only commands of this session (a continued and a restarted load of the same save now agree), and a file opened from outside the save directory is always unsaved until copied in. Trip and blow toasts forget their window on a new game.

- **Tool belt (F1.4).** Keys 1–9 select a tool-belt slot through the new `toolbelt.select {slot}` command (logged, no world change), and the HUD shows the active slot and the prop it holds. The viewport places the active slot's prop (F1.7).
- **Rebindable movement keys.** WASD, sprint, selection cycling, clear selection and (F1.7) the place and pick-up keys are input actions you can rebind. They still run in the renderer and never enter the replay log, and the viewport's accessible name lists the current keys.
- **Scripting API and `sim-cli` (F1.6).** A new framework-free library, `@controls/scripting-api`, gives scripts a typed `Game`: `createGame({ seed })` or `createGame({ world })`, then `exec`, `execOrThrow`, read-only `world()` snapshots, `hash()`, the replay log and `on('executed')`. `game.probe()` (P2) and `game.tag()` (P10) are reserved and throw a clear "not available" error. The game's `Session` now runs on the same `Game`, so the UI and scripts run identical code. A new headless app, `apps/sim-cli`, runs it in plain Node: `pnpm sim run <script>` runs a TypeScript module (bundled with esbuild at run time; it may import only domain libs) or a console-line file and prints `world.hash`, `pnpm sim replay <log>` replays a replay log and `pnpm sim hash <world>` hashes a world document; `--log` saves a run's replay log and `--expect` checks a hash. Until the `.ctrl` container lands they read the JSON documents a save holds. The four-surface scenario runs through the API, a script, console lines and a replay to one pinned hash as part of `pnpm verify`. [Scripting guide](docs/guides/scripting.md), [ADR 0008](docs/decisions/0008-console-and-scripts.md).
- **Console-line grammar.** `@controls/commands` gains the `verb.noun --flag value` parser shared by `sim-cli` and the upcoming in-game console: dotted command ids, positional arguments, dotted `--flag value` pairs mapped onto the command's Zod arguments, bare `--flag` for true, quoted strings, numbers and `#` comments, with every error pointing at a column. `formatConsoleLine` writes a command back as a console line, and any recorded session can be re-run as console lines to the same hash (property-tested).
- **Command system (F1.2).** A new framework-free library, `@controls/commands`, holds the one command registry behind the palette, keybindings, console and scripting API that are still to come. Commands have Zod-validated arguments, and an invalid or refused command returns a typed error and changes nothing. Undo and redo (`edit.undo`, `edit.redo`) are themselves commands. Every successful command, including undo, redo and view actions, is appended to the replay log, and replaying the log from its starting world reproduces the session exactly. `when` context expressions are parsed by a small hand-written parser (no `eval`). The semantics are in [ADR 0006](docs/decisions/0006-command-system.md).
- **World model (F1.2).** `@controls/world-model` adds the first world commands: `entity.place`, `entity.move`, `entity.rotate` and `entity.delete`. They use integer millimetres and millidegrees, take ids from the world's counter and are undoable (undoing a delete brings the entity back with the same id). It also adds `world.hash`, a SHA-256 of the world's canonical JSON written in plain TypeScript from FIPS 180-4, which gives the same value in Node and in Chromium (both are tested). Seeded randomness uses sfc32 with per-command and per-entity streams derived from the world seed. Property tests check that undoing everything restores the initial hash, that every change inverts exactly, and that replay reaches the live hash.
- `@controls/feature-session`, the Angular adapter: the world as a signal with its hash, `exec`, context keys for `when`, and a `?e2e=1` test hook. A new Playwright test checks the Node golden hashes in Chromium.
- Viewport cameras (F1.7, part 1). **Work mode** focuses the backplate or a DIN rail and orbits and pans within limits. **Walk mode** is first person, with WASD, mouse look under pointer lock (Esc releases it) and the room bounds. Press V to toggle between them and F to focus the selection (the `view.mode` and `view.focus` commands since F1.7). Movement goes through rebindable input actions, not Commands (ADR 0006).
- Hover and click selection in the viewport, using BVH picking (three-mesh-bvh). Keyboard users can cycle the selection with `[` and `]` and clear it with Esc. Selection is view state, not world state. The viewport shows the mode and the selected object, and a frame-time HUD in dev builds or with `?hud`.
- Pure, GPU-free snap maths in integer millimetres for TS35 DIN rails (17.5 mm modules since F1.9), the backplate grid and 16 in stud walls, with a cited `source` for every real-world dimension. Placement uses it since F1.7.
- `mm()`, `metresToMm()`, `roundMm()`, `inchesToMm()` and `isIntegerMm()` in `@controls/units`.
- A `?e2e=1` test hook on the viewport and Playwright tests for mode switching, focus, keyboard and mouse selection, and no GPU geometry leaks from selection churn, on the forced WebGL2 path.
- **Game shell (F1.1).** The game now opens on a main menu (New sandbox, Continue, Load, Settings, About, Quit) drawn over the live 3D view. Continue and Load are visible but disabled until saving lands, and Quit appears only in the desktop app. Escape returns to the menu, which offers Resume.
- **Docking workspace.** New sandbox opens the 3D viewport with an Inspector panel on the right and a Console panel at the bottom (the console itself arrives later). Panels resize with the mouse or keyboard (focus a splitter, then use the arrow keys, Home/End, or Enter to collapse), toggle from the toolbar, and Reset layout restores the defaults. [ADR 0005](docs/decisions/0005-docking-workspace.md) records why these are custom split panes and not dockview.
- **HUD** over the viewport, showing the interaction mode, a selection summary and an **Assisted** badge, which will appear once cheat commands exist.
- **Settings screen** with Interface (theme, reduce motion), Graphics (renderer backend, pixel-ratio cap), Audio (volumes, stored for when sound arrives), Controls (look sensitivity, invert Y), Units (imperial or metric), Difficulty (default for new games) and Region (NEC only, shown disabled). Settings are saved: to `settings.json` in the app's user-data folder on desktop (written atomically) and to browser storage in the web harness, and they survive a restart. A settings file that is corrupt, from another program or from a newer version is replaced by the defaults, with a warning. The panel layout is saved with them.
- **Notifications:** screen-reader-announced toasts (polite for info, assertive for warnings and errors). Each can be dismissed from the keyboard, and none disappears while you are reading it.
- **Light and dark themes** that follow the system setting or a choice in Settings, plus reduced motion when the system or Settings asks for it.
- **Keyboard-first accessibility:** every menu, dialog, panel and notification works without a mouse, focus is always visible, and focus returns to where it was when a dialog closes. New Playwright tests drive the whole shell by keyboard in the web harness, and the Electron smoke test checks the shell under the real CSP.
- New libraries `@controls/ui` (design tokens, buttons, dialog, focus trap, splitter, toasts), `@controls/feature-shell`, `@controls/feature-workspace` and `@controls/feature-settings`. `@controls/platform-api` gains `Platform.settings` (a `SettingsService` over the `@controls/save-format` settings schema, implemented for Electron and the web harness) and `Platform.canQuit`/`quit()`.
- IPC channels `settings:get`, `settings:set` and `app:quit`. `settings:set` is checked against the `app://` origin, size-capped at 1 MiB, validated as a current-version settings document, and refused with a reason only (the payload is never echoed). Quit now works on macOS too.
- `@testing-library/dom` and `@testing-library/user-event` (dev only) for role- and label-based component tests.
- `fast-check` (dev dependency) for property tests in domain libs, and a 90 % Vitest coverage gate for every `type:domain` lib, run by its `test` target and therefore by `pnpm verify`.
- A `scope:headless` module-boundary tag for the upcoming `apps/sim-cli`: it may depend only on `type:domain` libs.
- The save format's first version (`schemaVersion` 1) in a new framework-free library, `@controls/save-format` (F1.8a, [ADR 0007](docs/decisions/0007-world-document-v1.md)). It defines Zod schemas for the save manifest, the world document (seed, sim tick, entity id counter, region, difficulty, the "assisted" flag, entities by catalogue reference with integer-millimetre positions and millidegree orientations, and an `extensions` bag) and the replay log. A settings document (`settingsVersion` 1) with `defaultSettings()` covers graphics, audio, controls, keybinding overrides, palette and console history, display, gameplay defaults, workspace layout, autosave and the tool belt. Loading validates untrusted JSON, migrates it through a total migration chain and refuses saves from newer builds with a clear error. Every document round-trips losslessly through JSON (fast-check property tests). Fixtures for every version must keep loading, and JSON Schema exports are checked in and kept in sync by a test. Saving and loading in the game arrive with the `.ctrl` container (F1.8b).

### Changed

- **The 3D viewport draws only when something changes.** It used to draw every frame, even behind the main menu and with nothing moving; now it draws on input, world, selection, hover, camera and size changes, keeps drawing while an animation runs (walking with a key held, the camera settling after an orbit), and otherwise sits idle. Behind the main menu it draws once. This saves battery and GPU time, and under software rendering it made the web end-to-end suite more than twice as fast (1.9 min to 42 s locally), because each test step no longer waits for a frame. The dev frame-time HUD now shows what each frame costs, with a frame rate only while frames run back to back, and reads "idle" when nothing is being drawn. Save thumbnails are drawn on request, so they still work while the viewport is idle.
- `release.yml` now grants `contents: write` only to the packaging job that uploads to the draft release; the workflow default, and the `verify` job, are read-only.
- The web harness's Open picker clicks its file input one task later: Chromium showed no file chooser for a click made inside a key handler (Ctrl+O).
- `ShellState.newSandbox()` is now `enterGame()`: it is also how a loaded save enters the workspace.
- `sim-cli` TypeScript scripts: the import allow-list now applies to the script's own files. Libraries the domain libs themselves use (fflate, through `@controls/save-format`) can be bundled; a script still can't import them directly.
- `CommandBus.clearHistory()` empties the undo and redo stacks without touching the state or the log (used when a save is loaded).
- **Pull requests now run CI on Windows, macOS and Linux**, not just Linux, so a PR is green only if `main` would be. `pr.yml` and `main.yml` both call one reusable workflow, `.github/workflows/ci.yml` (`pnpm verify`, then the web and Electron e2e suites, `fail-fast: false`, Playwright output uploaded on failure), so the two can't drift. The PR check names change from `verify + e2e (ubuntu)` to `ci / verify + e2e (ubuntu)`, `(macos)` and `(windows)`.
- Long web e2e tests are split into one flow per test, each from a fresh page: the F1.1 keyboard-only walk-through (main menu, settings, about, New sandbox, Escape in the workspace), the F1.4 keybindings test (conflicts, use after rebinding, survival across a reload) and the web settings-persistence test (settings, panel layout). The single F1.1 test had hit the 30 s timeout on Windows CI. The focus helpers (`apps/game-e2e/src/support/focus.ts`, shared with the palette test) no longer use `locator.evaluate`, the web e2e runs at 960 × 540 by default (the 3D specs still pin 1280 × 720), and the keybindings test waits animation frames instead of fixed delays. Locally the longest of these tests now takes about 12 s instead of 28 s.

- **The world document gained `fixtures` (F1.9, still `schemaVersion` 1):** the level's fixed geometry, by catalogue ref and string id, which no command moves or deletes. Because every world now serialises `"fixtures":[]`, every `world.hash` changed: an empty seed-0 world, the save-format fixtures and all scenario hashes were re-pinned together in `world-model`, `sim-cli` and `game-e2e`. The scenarios themselves (and the game behind the main menu) now start from the workshop at seed 0. [ADR 0007](docs/decisions/0007-world-document-v1.md#fixtures-and-levels-f19) records why fixtures are a separate list and not entities.
- **DIN rail modules are now 17.5 mm (DIN 43880), not 18 mm.** Slot `k` starts `round(k × 17.5)` mm from the rail end, so a box dragged onto DIN rail 1 at the mouse scenario's point now lands at x = -75 mm instead of -70.
- The demo panel (`DEMO_PANEL`, `demoPanelSnapTargets()`, `buildPanelScene()`, `PANEL_ROOM_BOUNDS`) is gone: the backplate and rails are fixtures of the workshop level, in the same place. Scripts snap with `worldSnapTargets(game.world())`. Walking is bounded by the level's floor.
- Selection cycling on the workshop starts at the backboard; the viewport still starts focused on the backplate.
- A new view command, `console.toggle` (no world change; like `palette.open` it stays out of the replay log), is bound to backtick as a global binding, so the backtick key can't be typed in text fields while the console is available unless you rebind it. `@controls/commands` gains `consoleFields(schema)`, which lists the flags a command accepts (completion and `help` use it, so they match the console's argument mapping exactly). The workspace's bottom panel now lays its content out as a column so the console fills it.
- The snap maths moved from the renderer to `@controls/world-model` (`snap/`), so the 90 % domain coverage gate and the determinism lint now cover it, and scripts snap exactly like the mouse.
- V and F are no longer input actions: they are the `view.mode.walk` / `view.mode.work` and `view.focus.selection` bindings of the new commands. If you had rebound `input.toggleMode` or `input.focusSelection`, that override is now ignored (it stays in your settings file); rebind under View in Settings → Key bindings. Enter and M are new input actions for placing and picking up.
- Escape on the viewport now cancels a move or a placement before it clears the selection, and only then opens the menu.
- The scene-graph snapshot used by tests now includes each object's rotation in millidegrees.
- The renderer's default input-action keys now come from a shared table in `@controls/commands` (`INPUT_ACTIONS`), and `CommandDef.keybinding` accepts a list of chords. A new `CommandDef.globalKeybinding` flag lets the palette and console toggle work while typing. The settings `controls.keybindings` record now also holds fixed-argument and input-action bindings; its shape is unchanged.
- The determinism lint (no `Math.random`, wall clock, `performance` or `crypto`) now also covers `apps/sim-cli` and its scenario scripts, and a test lints a probe file to prove `sim-cli` can't import a non-domain library.
- World snapshots from the session are now deeply frozen; code that mutated one now throws instead of silently corrupting history.
- Reset layout now runs the `view.resetLayout` command. The command is logged but doesn't change the world hash, so the palette, keybindings and console will be able to reset the layout too. The HUD's Assisted badge now reads the world's `assisted` flag.
- The demo scene now has a floor, and the renderer is split into a GPU-free `ViewportController` (scene, cameras, input, picking) and a thin `ViewportRenderer` (GPU and frame loop), so disposal and picking are unit-tested.
- The about box moved from the top-left overlay into the main menu's About dialog. Its `about-*` test ids are unchanged.
- The 3D viewport component moved from `apps/game` to `@controls/feature-workspace`. Its mode and selection readout moved into the shell HUD (same `viewport-status` test id); the frame-time dev HUD and the walk-mode crosshair stay in the viewport. The canvas is the viewport's only focus target, and its focus ring uses the theme's focus colour.
- The F1.7 viewport e2e tests start a sandbox first, because the game now boots to the main menu with the viewport inert behind it.
- Domain libs are now provably framework-free and deterministic. Lint bans framework and UI packages (`@angular/*`, `rxjs`, `electron`, `three`, …) in `type:domain` libs, Node built-ins in domain source, and `Math.random`, `Date.now`, `new Date()`, `performance` and `crypto` in all domain code. Domain libs typecheck without the DOM lib or ambient Node types, via a shared `libs/domain/tsconfig.domain.json`. Before this, the boundary was only checked against workspace imports.
- `desktop-e2e:e2e` is explicitly never cached, so a packaged smoke run can't be replaced by a cached dev run.
- Toolchain patch updates at the Phase 1 kickoff: pnpm 11.15.0 → 11.28.8, electron-builder 26.18.0 → 26.18.1 and electron-updater 6.8.11 → 6.8.12. Nx 24.0.0 → 24.0.2 followed once it cleared pnpm's minimum release age (no `nx migrate` migrations).
- **GitHub Actions moved to their Node 24 releases**, which clears CI's "Node.js 20 is deprecated" warning: `actions/checkout` v4 → v7.0.1, `actions/setup-node` v4 → v7.1.0, `pnpm/action-setup` v4 → v6.1.0 and `actions/upload-artifact` v4 → v7.0.2. Every action is now pinned to a full commit SHA with the release tag in a comment, so a moved tag can't change what CI or the release build runs. Checkout no longer leaves a git credential on the runner (`persist-credentials: false`; nothing authenticates through git, and electron-builder publishes with `GH_TOKEN`). Release builds no longer restore the pnpm store cache: they install from the registry, as setup-node advises for workflows that hold a write token. pnpm still comes from `packageManager` (11.28.8) and Node from `.nvmrc`.

### Fixed

- **Continue resumes the game you were last in.** Loading a save over a game with unsaved changes autosaves that game first, and if you then quit without changing the loaded save, Continue used to load that newer autosave instead of the game you were playing. Continue now remembers the save you last loaded, saved or autosaved (`saves.lastPlayed` in settings, `settingsVersion` 2; older settings files migrate) and tries it first, falling back to the newest save that loads, with the usual warning if the remembered save is damaged or gone. A game opened from a file outside the save folder, or saved only with Save As, now counts as unsaved until autosave copies it into the save folder, so Continue can resume it too. Tested in unit specs for each case, and end to end in the web harness and the desktop app ([ADR 0009](docs/decisions/0009-save-io-boundary.md#continue-and-the-last-played-save)).
- **CI and release failure artifacts now contain the Playwright report and traces.** Playwright writes them under `dist/.playwright`, and `upload-artifact` skips everything inside a dot-directory by default, so failed runs uploaded nothing (`No files were found with the provided path: dist/.playwright`) and the release logs held only `builder-debug.yml`. Both uploads now set `include-hidden-files: true`, and the release artifact name carries the run id and attempt, like CI's, so re-running a failed job can't collide with the earlier attempt's artifact.

- A flaky `world-model` property test: its reference canonical-JSON builder put integer-like object keys (`"0"`) first, as JavaScript objects always do, and so disagreed with `world.hash`'s correct code-unit order on some generated worlds. The hash itself was right; the test now builds its reference string directly.
- **A setting changed just before quitting is no longer lost.** Settings are saved 300 ms after the last change, and that save was dropped if you quit (menu Quit, Cmd+Q, closing the window) inside those 300 ms. The desktop app now asks the page to finish its pending writes before a window closes or the app quits, and waits for it (up to 2 s, so a hung page can't stop you quitting). The browser harness writes pending settings when the tab is closed or reloaded. This also caused the intermittent macOS CI failure of the settings-persistence test, which now waits for both changes to be on disk and has regression tests for quitting and for closing the window straight after a change.
