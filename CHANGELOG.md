# Changelog

All notable changes to Controls are documented here.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses [Semantic Versioning](https://semver.org/spec/v2.0.0.html). Each phase ships a minor release (`0.N.0`); fixes ship as patches. The save-format `schemaVersion` and the `catalogVersion` are versioned independently and recorded in [`docs/history.md`](docs/history.md).

  - **Device records** for every engine 8 kind on main: the plug-on breakers (per-pole current, thermal fraction and pickup, the drawn opening time, `state` and `tripCause`, always written: read a trip from `state`, never the handle), the GFCI breaker (neutral current, `residualMa`, `pickupMa`, `residualIntegral`, `testHeld`, the line-side and load-side voltages), the AFCI breaker (`arcExposure`, `arcingDownstream`), the service (each drop conductor's current, the utility grounding's, the meter base's voltages) and the ground rod (its current and `touchVoltageV`, its potential rise against remote earth). The GFCI and AFCI records carry a `readings` bit field: a field is a reading only with its bit, which its schema names (`readingBit`, read through `isDeviceReading`), so a generic display shows no reading, never 0 V. The lamp's record gains `burnedOut` (status moves to byte 49, still last).
  - **Pending schemas** for the LED lamp and fixture and the dimmer (`PENDING_DEVICE_OUTPUT_SCHEMAS`), which P4 PR 12 registers without moving the fingerprint.
  - **Connection records** gain `endADegradation` and `endBDegradation` (each end's degradation factor; 104 → 120 bytes, checked at module load to stay every f64 then every u8). A cooled end that degraded now reads `degraded` in the wire readout (`degraded at end a (contact resistance 3.22× original)`, "3.22 times" in the live region; a hot one `degrading … (above the oxidation onset; contact resistance 1.8× original)`), `degraded N times` in the netlist panel and `degradation N` in `wire.info`, where before it read normal once below the oxidation onset.
  - **Events:** `lampBurnout` and `overvoltage` (schemas only: P4 PR 12 and F4.4 emit them); every kind's detail is parsed exactly on the wire, so a `tripped` event's `cause` is one of `thermal`, `magnetic`, `groundFault`, `arcFault`, `test` (`TRIP_CAUSE_VALUES`, the catalogue's `TRIP_CAUSES`), read typed with `simEventDetail`. A mismatched detail would fail the whole sim link, so sim-core's `emit` is typed by `SimEventDetails` (a wrong detail doesn't compile) and a spec parses every emitter's events with the wire schema.
  - **Allocation:** every new record writer is gated at 0 B a call; the lamp's record writer, which boxed two doubles a call, no longer does (bit-identical).

- **Breakers v2, the GFCI and the AFCI, headless** (P4 PR 10, F4.2 part 1, decisions D6–D8; [ADR 0021](docs/decisions/0021-service-grounding-and-protection-physics.md) part 2, [simulation caveats](docs/caveats/simulation.md#breakers-v2-the-gfci-and-the-afci-p4-pr-10)), on test-only catalogue entries until the content PRs.
  - **New model kinds** `breaker.plugOn1p`, `breaker.plugOn2p` (one bimetal and one pickup per pole, a common trip), `breaker.gfci1p` and `breaker.afci1p` (a pigtail neutral and a load-neutral terminal), with ADR 0019's keys unchanged and now final, `TRIP_CAUSES`, parameter schemas whose magnetic band is in absolute amperes (the DIN entry's 8–12 × can't be carried over) and their `device-state.*.schema.json`.
  - **Thermal and magnetic:** the P2 bimetal law (116.84 s, 29.72 s, 3.872 s and 0.9449 s at 135 %, 200 %, 500 % and 10 ×, inside the read bands; never at k_u I_n); above a pickup drawn in 240–400 A the breaker opens after an opening time drawn in 8–20 ms (`magneticSinceTick` persisted, so a save inside the window opens at the same tick), not within the tick.
  - **GFCI** (`gfci.ts`, shared with the receptacle to come): the residual |I_hot + I_neutral|, a drawn 4–6 mA pickup and 3–14 ms mechanism time, the region's Class A limit read as a rate (inside the limit; 10 mA opens at 2695 ticks, 100 mA at 100, a heater-element fault at the mechanism time); a test button that closes a real internal resistor (cause `test`; a 15 kΩ test entry, 8.0 mA, about 3.64 s), held for `GFCI_TEST_HOLD_TICKS` 5000 so a realistic test circuit (at most about 9 mA, still tripping at 85 % voltage, UL 943 by number) trips inside the hold; reset by the handle. Because the model trips at the Class A upper limit, a 7–9 mA plug-in tester will see 3–4 s trips (an open item for P5).
  - **AFCI** (`afci.ts`): an arcing end downstream carrying at least 5 A adds to `arcExposure` per 100 ms bucket and trips it with a seeded draw that reaches certainty by the UL 1699 limit for every seed (a fast-check property); never on an end upstream, on a glowing joint or below 5 A; a test button.
  - **Engine:** `SimDevice.parts`, `protection` and `purposeStream`; a `CommandedContext` for the `commanded` hook (the tick and the last solution, read-only); `LayerContext.arcingCount`/`arcingBranch`; the non-allocating numeric structure code for sim topology keys (`CompileOptions.simValue`, each key projected to a boolean). `intermittent-toggle-wired` unchanged (0.780 ms median against 0.781 ms).
  - **Load check:** a `tripCause` is `null` exactly when the device isn't tripped (`tripCauseProblems`). `fixtures/v4/world/protection-state.json` already held the final keys and is unchanged.
  - **Plug-on `ultimateTripRatio` is strictly below 1.35** (at 1.35 the bimetal would never trip at 135 %, UL 489's 1 h ceiling by number); the frozen DIN kind keeps its bound.
  - **Worker events after a replay start:** the sim worker now discards a replay start's events by position (until its closing advance is done) rather than by tick, so an event a command raises at the replay's end tick (an AFCI test press while paused right after a load) is delivered, as headless delivers it (ADR 0011 §4 note).
  - **No pin moved:** no `topologyHash`, snapshot or world hash of an existing scenario, fixture or e2e pin changed; `SIM_ENGINE_VERSION` 8 and `SIM_PROTOCOL_VERSION` 8 stay provisional. The new kinds' records are protocol 8's (PR 11).

- **Lighting models: wall switches, the dimmer, the lampholder, LED drivers and lamp burnout** (P4 PR 12, F4.1 part 1, decisions D10, D11; [ADR 0021](docs/decisions/0021-service-grounding-and-protection-physics.md#part-3-the-lighting-models-p4-pr-12) part 3, [simulation caveats](docs/caveats/simulation.md#lighting-switches-the-dimmer-the-led-driver-and-burnout-p4-pr-12)). The models, and the shipped catalogue entries.
  - **Shipped entries** (catalogue 3, provisional, all version 1; [content caveats](docs/caveats/content.md#lighting-entries-p4-pr-12)): Castellby `switch.castellby-1p-15a`, `-3way-15a` and `-4way-15a` (15 A 120 V; binding screws at 1.8 N·m plus a 14 AWG solid copper push-in hole on each current-carrying terminal, UL 20 by number; a green grounding screw), `dimmer.castellby-600w` (600 W 120 V, side-wired), `lampholder.castellby-keyless` and `lampholder.castellby-pull-chain` (660 W 250 V porcelain, an E26 socket with its shell on the silver screw); Lumivane `lamp.lumivane-a19-60w` and `-a19-100w` (the P3 120 V filament data; 30 ms and, from the same filament estimate, 40 ms) and `light.lumivane-led-a19-9w` (9 W, PF 0.9, dropout 90 V, restart 95 V); and the Fennisby `light.fennisby-led-wall-15w` (15 W, a wall light on a device box's yoke position, a push-in terminal block). Every wiring device and the wall light bonds its ground terminal to a metal box's chassis through a 5 mΩ strap contact; every bulb's E26 foot and shell contacts are 2 mΩ (both game-design). Sources paraphrased, no maker named; hand calculations in `lighting-entries.spec.ts`, and a sim-core golden runs the 3-way and 4-way truth tables, the dimmer, the LED and the 100 W bulb on the shipped entries beside the test-only ones. The renderer draws the eight lighting kinds with one plain recipe (a box, a label and a sphere at each landable terminal) until each has its own.
  - **New model kinds** (keys exactly as [ADR 0019](docs/decisions/0019-world-document-v4.md#sim-and-commanded-state-keys) lists them): `switch.wall1p` (`closed`), `switch.wall3way` (`position` `t1 | t2`) and `switch.wall4way` (`position` `straight | crossed`), ideal joins with a `ground` terminal for the yoke and every position closed in the wiring view; `dimmer.wall` (`on`, `level` 0–1); `lampholder.e26` (keyless: its `e26` host mount offers the centre contact on the brass screw and the shell on the silver one); `light.led` (an E26 bulb) and `light.ledFixture` (`running`, `overvoltageSinceTick`). Back-stab is a terminal method beside the binding screw, so it is entry data. Seven `device-state.*.schema.json` files.
  - **The dimmer** is a lossless series reactance X = c · R_th chosen at each solve (c = √(1/k² − 1), k the RMS fraction of a forward-phase-cut sine at its level from the tabulated `DIMMER_RMS_CURVE`, R_th fitted from two phasor solves), so a resistive load sees k of its undimmed voltage within 0.1 % and the dimmer dissipates nothing; off it is open, on DC its triac latches on.
  - **The LED driver** draws its rated power at its power factor (Y = conj(S) / |V|², a conductance and an inductive susceptance: the datasheet PF carried as a lagging displacement) within 0.1 % from dropout up, nothing below dropout, with hysteresis up to its restart voltage; `running` is committed after each solve, so a save inside the band reloads the same. A supply that can't hold it up is `nonConverged`.
  - **The phasor outer loop** (`SimDeviceBank.acIterate`): a device whose AC value depends on its own solution is valued from the warm start, then from each new solution, the AC islands re-solved while it moves, capped at `OUTER_LOOP_MAX_ITERATIONS` and flagged `nonConverged`. Only islands holding a dimmer or an LED driver iterate.
  - **Lamp burnout.** `lamp.incandescent` sets its sticky `burnedOut` the step its filament reaches `LAMP_BURNOUT_K` (3200 K, game-design: a 2700 K-rated filament gets there at 1.541 × its rated voltage, never inside ANSI C84.1 Range B), drops its filament element (a sim topology key; the engine recompiles and re-solves within the step) and never clears it. Its `lampBurnout` event and record field are protocol 8's (PR 11).
  - **Goldens** on test-only entries: the 3-way and all eight 4-way states on a bench circuit (lit exactly when the selected travellers meet, current only in the selected traveller); the dimmer's RMS fraction at 0.25, 0.5 and 0.75 within 0.1 % of its curve and its dissipation zero; the LED at 9 W within 0.2 % from 108 to 127 V, under 1 mW below dropout and at its band edges (holds at 90.5 V, stops at 89.5 V; waits at 94.5 V, starts at 95.5 V); a dimmer feeding an LED readable at 0.25–1; burnout set once at 3200 K; save-and-load and replay properties over a bench holding all of them, with bounded iterations.
  - **The pull-chain lampholder** `lampholder.e26PullChain` (decided by `save-format-guardian`; ADR 0019 amended): its own kind with one commanded key, `closed` (a toggle, `device.operate`), joining the brass screw to a sealed `centre` node the socket's centre contact lands on; the keyless `lampholder.e26` keeps no keys. Its `device-state.*.schema.json` beside the seven.
  - **Review round** (P4 PR 12): the phasor outer loop runs in stages (the dimmer fits with drivers frozen, then the drivers settle), re-solves only the islands that moved, and records each island's own phasor solves, so an LED behind a dimmer no longer stalls the shared island at the 50-pass cap; a driver that stops in a solve stays stopped for it (a blinking supply settles stopped, readable); the dimmer and the driver stamp through slots (`inductorAt`), no allocation on the tick path; the driver's displacement is carried lagging, so a dimmer-fed driver never exceeds the open-circuit voltage (leading resonated with the dimmer at 128–133 V on 120 V); the lamp bank has `simValue` for PR 10's structure code; new bench cases `lighting-resolve-topology-change` (calibrated 2 ms) and `lighting-level-change` (reported). Realism fixes: UL 20 (not UL 498) for switch push-in terminals, 0.16 mW stopped-driver leakage, 1.7 V high-end trim; the LED's `powerFactor` is the datasheet (true) power factor carried as a lagging displacement; MWBC-neutral, distortion-power and series-dimmer abstractions stated.
  - **No pinned hash moved**: no shipped world holds a new kind, and no shipped scenario drives a lamp to 3200 K. The lamp's new sim topology key costs nothing measurable with its `simValue` (ADR 0021 deviation L-e).
- **Engine 8 part 1: mounts, plugs, earth and the service** (P4 PR 9, decisions D3–D5; [ADR 0021](docs/decisions/0021-service-grounding-and-protection-physics.md) part 1, [simulation caveats](docs/caveats/simulation.md#engine-8-part-1-contacts-remote-earth-and-the-service-p4-pr-9), [simulation architecture](docs/architecture/simulation.md#engine-8-part-1-contacts-remote-earth-and-the-service-p4)). `SIM_ENGINE_VERSION` 8, provisional until 0.5.0.

- **Delete saves and see their thumbnails in the Load list** (P4 PR 25, Saves; [ADR 0009 amendment](docs/decisions/0009-save-io-boundary.md#delete-thumbnails-and-case-unique-names), [electron caveats](docs/caveats/electron.md), [UI caveats](docs/caveats/ui.md)). Each save in the Load list shows the small picture of the view it was saved with, and has a Delete button beside it (or press Delete on a save; on macOS also Backspace or Cmd+Backspace): the row asks "Delete “…”? This can’t be undone.", focused on Keep, and Escape goes back without closing the dialog. After a delete, focus moves to the save that took its place. Deleting the save of the game you are playing clears Continue's pointer and the next autosave copies the game back in. A delete through an out-of-date list deletes nothing and asks you to try again.
  - **Two new IPC channels**, each checking the `app://` sender, Zod-validated with `@controls/ipc-contract` schemas and refusing with a reason code only: `save:delete { handle }` (a manual save or an autosave slot; a file opened from or saved to outside the save directory is `read-only`; `unlink` of a regular file only, serialised with the writes) and `save:thumbnail { handle }` → PNG bytes or `null`. The thumbnail handler reads only the ZIP's end record, its central directory and the `thumbnail.png` entry (`readCtrlThumbnail` in `@controls/save-format`, a random-access reader with the container's caps and CRC-32 check), never the whole save.   - **Manual save names are unique ignoring case** on both platforms (`saveNameKey`: NFC, lower case): a write whose name differs only by case from another save's is `exists`, or with `overwrite` replaces that save under its existing spelling (where two spellings exist from 0.4.0, the Save game dialog sends the exact one it named). **Continue matches the last-played save by exact name only**, so it can no longer resume "SHOP" when the last-played "Shop" was deleted outside the game on a case-sensitive file system (the carried P1 item). - **A capped session still saves, and loads `continued`** (P4 PR 25, the carried P1 "replay log never shrinks" item; [save-format caveats](docs/caveats/save-format.md), [scripting guide](docs/guides/scripting.md)). Two additions to the P3 checkpoints, in `@controls/scripting-api`: once the entries logged since the latest checkpoint pass `LOG_CHECKPOINT_BYTES` (4 MiB, UTF-8 bytes of compact JSON, a sourced numerical constant; a loaded game counts the entries it carries), the game takes a checkpoint at the next tick time reaches, off the 10 s grid; and a log that would still put a save over the `replay.log` or container cap (time stood still, or an undo reached across the checkpoint) is rebased onto the save's own world (`rebasedAtSave`: no entries, `seq` numbering continued), which loads `continued` and replays to the same hash. ### Fixed

- **The netlist inspector keeps keyboard focus when the netlist arrives** (F2.6; [UI caveats](docs/caveats/ui.md)). Opened before the sim had published the circuit (right after a `sim.step`, or on a slow machine), the inspector focused its "The netlist is empty." hint, and the tree that replaced it a moment later dropped focus to the page, so the arrow keys did nothing. Focus now moves to the tree's first row, and back to the hint if the sim resets. The inspector also no longer takes focus back when its lazy chunk finishes loading after you have moved focus elsewhere. This was the intermittent `netlist-inspector.spec.ts` failure on CI.
- **A rare flake in the sim-core phasor property tests** (tests only; [simulation caveats](docs/caveats/simulation.md)). The F2.4 sparse property "with series inductance behind the sources" failed about once in 2,500 runs (seen on macOS CI, but not platform-specific) when every source of a small generated circuit drew ideal and so got no series inductance. The solver was not at fault: cold, warm and thrashed solves stayed bit-identical. The test generator now keeps each island's root source non-ideal under `sourceInductance`, and the counterexample is pinned. Solved values, `topologyHash`, the pinned solve hashes and `SIM_ENGINE_VERSION` are unchanged.
- **A flake in the connection-record gap property** (tests only; [simulation caveats](docs/caveats/simulation.md)). "An open record never reports a 0 V gap where the gap's two sides differ" counted the gaps it checked across its unseeded runs and required more than 20. Over 20,000 seeds the count ranged from 14 to 47 and fell to 20 or below in about 1 run in 50 (seen on Windows CI). The property itself always held. The count now comes from a fixed-seed generator-health test over the same arbitrary, which also requires gaps without a reading. The engine and its records are unchanged.
- **A flake in the snapshot-read allocation checks** (`sim bench`'s two read gates and their spec; [simulation caveats](docs/caveats/simulation.md)). The smoke-plant check read 1.024 B a read on Windows CI and 3.024 B on macOS, against a gate of under 1 B. The read itself doesn't allocate. The measure counted heap growth, which includes whatever else the process allocates, and it took the smallest of two windows, so a one-off burst could get through (seen locally in 1 run in 300). Each window's bytes are now sampled by V8's heap profiler under the reads alone. Each estimate is the difference between a window of N reads and one of 2N, so a fixed cost per window cancels; compiling the measuring loop mid-window cost about 11.5 kB every window. The gate takes the median of 7 estimates (5 in a smoke run). A read that allocates on every frame still fails, and a new test pins that a 40 kB one-off in a single window doesn't. The spec's full-plant netlist check scales its windows to that read's cost: 250 reads after a 2,500-read warm-up, about 5 s on one core where it took 25 s and timed out on macOS. The full-size gate stays in `sim bench`.
- **A flake in the "layer alone" allocation checks** (sim-core's F2.5 and breakers-v2 layers; [simulation caveats](docs/caveats/simulation.md)). `afci1p` read 1.72 B a call once in a full `verify` under load, against a gate of under 1, and passed on reruns. Each layer was measured in a single 200,000-call window, so a stretch where a layer is still tiering up, or re-optimising after a deopt, and boxes its doubles could decide the test. The lamp's layer does this in its second window in every run, at about 121 B a call. The layers now use the engine gates' rule: windows of 40,000 calls until the last four agree, then the median of the last five. A new test pins that a planted 32 B a call still fails, and that a 400 kB one-off in one window doesn't.
- **The GFCI breaker's protection layer no longer allocates 16 B a tick** (sim-core, P4 PR 10's `breaker.gfci1p`; [simulation caveats](docs/caveats/simulation.md#breakers-v2-the-gfci-and-the-afci-p4-pr-10)). `GfciSensor.step` took the residual and the step length as arguments, and V8 boxed each non-integer double into a heap number whenever it didn't inline the call: about one process in eight under load (failing the breakers-v2 "layer alone" check at 16.09 B a call on Ubuntu CI) and every process under `--no-maglev` (32 B a call with a non-zero residual). The sensor now reads both from `Float64Array` slots (`residualA[i]`, `dtS[0]`) and works out its trip rate slot to slot (`gfciTripRateInto`), and the plug-on bank reads |I|² in place instead of through a helper returning a double (which boxed under `--no-turbo-inlining`). The check now drives non-integer currents (15.3 A, a 2 mA residual), since a whole |I|² is a small integer V8 tags without a heap number and hid the helper's box. Behaviour is unchanged: every protection golden and property passes as before, a digest of trip ticks and bags over 20 seeds for all four kinds is identical, and no scenario hash moved.

#### Physics

- **Real building wire with derived resistance** (F3.1 part 1, #99; [ADR 0018](docs/decisions/0018-conductor-and-termination-physics.md), [authoring guide](docs/guides/authoring-content.md#conductors)). 21 conductors under fictional brands: copper THHN/THWN-2 from 14 AWG to 4/0, MTW from 18 to 10 AWG and aluminium XHHW-2. A landed conductor is part of the circuit, its resistance worked out from metal, size and cut length (30 m of 14 AWG copper is 0.2486 Ω at 20 °C), never looked up; ampacity is derived in free air at 30 °C, never copied from the NEC.
- **How well a wire is landed matters** (F3.3 part 1, #103; [simulation](docs/architecture/simulation.md#contact-resistance-f33-part-1)). Every landed end adds a contact resistance from how it was made: a good screw termination is 0.3 mΩ, one at 20 % of its marked torque about 85 times worse, and nicked strands, short strips, splayed strands, two conductors under a one-conductor screw or a bad crimp make it worse. A plain screwdriver lands between 15 % and 145 % of the marked torque; a torque driver lands at its setting. Three twist-on wire nuts, checked against their rated combinations.
- **Wires, leads and terminations heat up** (F3.6 part 1, #104; [simulation](docs/architecture/simulation.md#connection-thermal-bank-f36-part-1)). Every conductor and test lead carries a temperature (I²R in, cooling through its insulation by convection and radiation), and each landed end has its own hot spot, so a poor termination runs hotter than its wire: on 14 AWG at 12.5 A a screw at a fifth of its torque runs about 100 K hotter. Temperatures are saved and continue exactly after a load.
- **Bad connections degrade, flicker, arc and burn open; wires and leads fuse** (F3.6 part 2, #105; [simulation](docs/architecture/simulation.md#degradation-end-states-and-the-failure-rule-f36-part-2)). A termination above 149 °C degrades for good; with rising resistance it glows, turns intermittent, arcs and finally burns open, in seeded buckets identical across runs, saves and the worker. A conductor or lead reaching its melting point fuses, and insulation is flagged damaged at its rating + 40 K.
- **A 120 V 60 W lamp and a 1500 W heater** (D12, #106; [authoring guide](docs/guides/authoring-content.md#brands)) for the wiring demo, with screw terminals. The lamp draws about 15 times its 0.5 A when switched on cold.

- **The DC circuit solver** (F2.2 part 1, [simulation architecture](docs/architecture/simulation.md#the-dc-solver-f22-part-1)). `@controls/sim-core` can now work out the voltage at every terminal and the current in every lead, cell and lamp of a DC circuit: `DcSolver` solves each separate circuit (island) of the netlist by modified nodal analysis, with a dense LU factorisation using partial pivoting. It handles resistances, voltage sources with internal resistance (a battery's 23 mΩ) and current sources. A lamp left dangling off a battery, or one sitting on its own, reads 0 V across and 0 A through it, as it should. Two ideal sources wired straight across each other have no solution: that circuit is flagged `singular` and shows zeros instead of garbage, while other circuits on the bench still solve. Every result is reproducible bit for bit, in the netlist's canonical order, ready for the save's solution record. Values come from a hook that the battery and lamp models (F2.4, F2.5) will fill; until then a battery uses its nominal 12 V. Checked against hand calculations (a divider, a Wheatstone bridge, a battery into a lamp, two unequal batteries in parallel, floating circuits) and by property tests that Kirchhoff's current law and the power balance hold on random circuits. - **Sparse LU, the factorisation cache and the nonlinear outer loop** (F2.2 part 3, [simulation architecture](docs/architecture/simulation.md#sparse-lu-and-the-factorisation-cache-f22-part-3)). Large circuits now solve fast enough for a plant: an island of 64 or more unknowns is solved by a sparse LU factorisation (Gilbert–Peierls, with threshold partial pivoting) in an approximate-minimum-degree (AMD) column order, both written from the published papers; smaller ones stay on the dense solver, bit for bit as before (the pinned 300-solve hash is unchanged). Each island's symbolic factorisation (its matrix pattern, the AMD order and a recorded stamp program) is kept in a **factorisation cache** keyed by `topologyHash`, a 16-topology least-recently-used cache: flipping a switch back to a position the cache has seen, or changing only values (a lamp's resistance, a supply's setpoint), skips rebuilding it, and the numeric factorisation replays the previous pivot sequence whenever the pivot rule would choose the same rows. Results are bit-identical whether the cache is cold, warm, shared or thrashed, and across solver instances, including after values change (sources switching between ideal and non-ideal); counters (`cache.stats`, `sparse.replays`) show the hits. The sparse path's bits are pinned by their own SHA-256 over 60 seeded large solves, beside the dense path's 300-solve pin. `DcSolver.solveNonlinear` adds the **outer loop** that F2.4's CV/CC supply and F2.5's lamp R(T) will use: a value hook per iteration, a warm start from the previous solution record, damping that halves on oscillation and recovers, a 50-iteration cap, and the island's `nonConverged` flag when it doesn't settle. Each current must settle to its own rounding (per branch, so a small current on a stiff busbar island isn't let off early). A `nonConverged` island's values are the last solve's and look real, so later features must show it as unsettled. Checked by property tests: dense and sparse agree (residuals on every circuit, values to 1e-9 on well-conditioned ones, up to 260 nodes), the DC oracle passes on both paths, floating clusters stay structurally pinned on the sparse path, the cache matches a reference LRU model, and the loop reaches closed-form fixed points and stays within 40 iterations (median 16) on random bench worlds with self-heating lamps. On the 2,000-node bench plant a re-solve after a switch toggle (compile, values and solve) takes about 1.5 ms locally with a warm cache and 4.6 ms for a topology never seen; `sim bench` reports both (median and p90), and the 2 ms gate stays reported-only: CI measured 2.12, 3.74 and 4.77 ms (Ubuntu, macOS, Windows), so the recompile is optimised next and the gate then switches on as a ratio to a calibration loop timed in the same process (plan F2.2 part 3b).

- The F1.7 viewport e2e tests start a sandbox first, because the game now boots to the main menu with the viewport inert behind it.
- Domain libs are now provably framework-free and deterministic. Lint bans framework and UI packages (`@angular/*`, `rxjs`, `electron`, `three`, …) in `type:domain` libs, Node built-ins in domain source, and `Math.random`, `Date.now`, `new Date()`, `performance` and `crypto` in all domain code. Domain libs typecheck without the DOM lib or ambient Node types, via a shared `libs/domain/tsconfig.domain.json`. Before this, the boundary was only checked against workspace imports.
- `desktop-e2e:e2e` is explicitly never cached, so a packaged smoke run can't be replaced by a cached dev run.
- Toolchain patch updates at the Phase 1 kickoff: pnpm 11.15.0 → 11.28.8, electron-builder 26.18.0 → 26.18.1 and electron-updater 6.8.11 → 6.8.12. Nx 24.0.0 → 24.0.2 followed once it cleared pnpm's minimum release age (no `nx migrate` migrations).
- **GitHub Actions moved to their Node 24 releases**, which clears CI's "Node.js 20 is deprecated" warning: `actions/checkout` v4 → v7.0.1, `actions/setup-node` v4 → v7.1.0, `pnpm/action-setup` v4 → v6.1.0 and `actions/upload-artifact` v4 → v7.0.2. Every action is now pinned to a full commit SHA with the release tag in a comment, so a moved tag can't change what CI or the release build runs. Checkout no longer leaves a git credential on the runner (`persist-credentials: false`; nothing authenticates through git, and electron-builder publishes with `GH_TOKEN`). Release builds no longer restore the pnpm store cache: they install from the registry, as setup-node advises for workflows that hold a write token. pnpm still comes from `packageManager` (11.28.8) and Node from `.nvmrc`.

### Fixed

- **Continue resumes the game you were last in.** Loading a save over a game with unsaved changes autosaves that game first, and if you then quit without changing the loaded save, Continue used to load that newer autosave instead of the game you were playing. Continue now remembers the save you last loaded, saved or autosaved (`saves.lastPlayed` in settings, `settingsVersion` 2; older settings files migrate) and tries it first, falling back to the newest save that loads, with the usual warning if the remembered save is damaged or gone. A game opened from a file outside the save folder, or saved only with Save As, now counts as unsaved until autosave copies it into the save folder, so Continue can resume it too. Tested in unit specs for each case, and end to end in the web harness and the desktop app ([ADR 0009](docs/decisions/0009-save-io-boundary.md#continue-and-the-last-played-save)).
- **CI and release failure artifacts now contain the Playwright report and traces.** Playwright writes them under `dist/.playwright`, and `upload-artifact` skips everything inside a dot-directory by default, so failed runs uploaded nothing (`No files were found with the provided path: dist/.playwright`) and the release logs held only `builder-debug.yml`. Both uploads now set `include-hidden-files: true`, and the release artifact name carries the run id and attempt, like CI's, so re-running a failed job can't collide with the earlier attempt's artifact.

- A flaky `world-model` property test: its reference canonical-JSON builder put integer-like object keys (`"0"`) first, as JavaScript objects always do, and so disagreed with `world.hash`'s correct code-unit order on some generated worlds. The hash itself was right; the test now builds its reference string directly.
- **A setting changed just before quitting is no longer lost.** Settings are saved 300 ms after the last change, and that save was dropped if you quit (menu Quit, Cmd+Q, closing the window) inside those 300 ms. The desktop app now asks the page to finish its pending writes before a window closes or the app quits, and waits for it (up to 2 s, so a hung page can't stop you quitting). The browser harness writes pending settings when the tab is closed or reloaded. This also caused the intermittent macOS CI failure of the settings-persistence test, which now waits for both changes to be on disk and has regression tests for quitting and for closing the window straight after a change.

## [0.1.0] - 2026-10-26

Phase 0, "Hello, panel": the cross-platform walking skeleton. Nothing playable yet.

### Added

- The first desktop build: an Electron 45 window titled "Controls" showing a 3D view of a white sub-panel with two TS35 DIN rails. The view is built procedurally, uses WebGPU when available and WebGL2 otherwise, can be orbited with the mouse, and resizes with the window.
- An about box showing the app version, platform (with the Electron version), active render backend (`webgpu` or `webgl2`) and whether the page is cross-origin isolated.
- Installers for Windows (NSIS), macOS (universal dmg and zip) and Linux (AppImage, deb, rpm). They are unsigned, and packaged builds check GitHub Releases for updates (not on macOS while builds are unsigned).
- Security hardening for the desktop shell. The game is served from a custom `app://` origin with COOP/COEP and a strict CSP (no `unsafe-eval`), path traversal is refused, and the sandboxed renderer has no Node access. Navigation, pop-ups, `<webview>` and permission requests are denied, and `https://` links open in the system browser. Electron Fuses disable RunAsNode, `NODE_OPTIONS` and the inspect flags, and turn on cookie encryption and ASAR integrity. Only one instance of the app can run at a time.
- A typed, Zod-validated IPC skeleton (`@controls/ipc-contract`). One `app:info` channel, which accepts calls only from the app's own origin, is exposed to the renderer as `window.controls.getAppInfo()`. The preload imports a narrow `@controls/ipc-contract/preload` entry, so Zod stays out of it.
- A browser dev harness (`pnpm start:web`) that runs the same Angular 22 zoneless app with `@controls/platform-web` instead of the Electron bridge.
- Developer workspace: Nx 24 + pnpm 11, TypeScript 6.0 strict, ESLint flat config with module-boundary tags (`type:app`, `type:feature`, `type:ui`, `type:domain`, `type:rendering`, `type:platform`, `type:contract`, `type:e2e`), Prettier, and Node 24 pinned in `.nvmrc`.
- `pnpm verify`, which runs exactly what CI runs: Prettier check, lint, typecheck, unit tests, build and the version-sync check. `pnpm version:sync` copies the root version into the desktop app and `@controls/units`.
- End-to-end tests: `apps/game-e2e` (Playwright against the web harness, including a check that the viewport isn't blank) and `apps/desktop-e2e` (an Electron smoke suite that runs against the built app, or against a packaged binary via `CONTROLS_E2E_EXECUTABLE`).
- GitHub Actions: `pr.yml` (verify and both e2e suites on Linux), `main.yml` (the same on Windows, macOS and Linux) and `release.yml` (on a `v*.*.*` tag: check the tag matches the version, verify, package each OS, smoke-test the packaged app, and only then upload it to a **draft** GitHub Release with `latest*.yml`). All three share the `.github/actions/setup` composite action.
- Documentation skeleton: README, this changelog, the docs hub, architecture overview, caveats, ADRs 0001–0004, glossary, history, new-developer and releasing guides, `THIRD_PARTY_NOTICES.md` and the MIT licence.
- Claude Code setup: `CLAUDE.md`, the `docs-keeper`, `version-keeper`, `release-engineer`, `electron-platform-engineer` and `test-engineer` agents, and the `/verify`, `/docs-sync` and `/release` skills.
