# Changelog

All notable changes to Controls are documented here.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses [Semantic Versioning](https://semver.org/spec/v2.0.0.html). Each phase ships a minor release (`0.N.0`); fixes ship as patches. The save-format `schemaVersion` and the `catalogVersion` are versioned independently and recorded in [`docs/history.md`](docs/history.md).

## [Unreleased]

### Added

- **The workshop sandbox level (F1.9).** New sandbox now opens a workshop: an open 2×4 stud wall at 16 in centres, a plywood backboard carrying the 600 × 800 mm backplate with its two TS35 DIN rails, and a workbench, on a concrete floor. Walls, the bench, the backboard, the backplate and the rails can all be selected and focused (F, or `view.focus --target stud-wall`); the bench is framed from above. The box, crate and spool snap to the backplate grid, the DIN rails, the wall studs (boxes go flush against a stud, in the bay) and the bench top (props stand on it) from the tool belt, the palette, the console and scripts alike. The level is data, `content/levels/workshop.json`, a world document validated by the save format; the renderer draws it with procedural recipes, and `pnpm sim hash content/levels/workshop.json` hashes it headless.
- **New-game dialog.** New sandbox asks for a seed: it offers a fresh random one (New seed draws another) or takes one you type, from 0 to 4294967295, refusing anything else inline. The same seed starts the same world. Escape or Cancel goes back to the menu. Each start is a fresh history and replay log, at your default difficulty from Settings.
- `sim run <script> --world <level> --seed N` starts a new game on that level with seed N, as New sandbox does. The `sim-cli` scenarios now run on the workshop (`--world content/levels/workshop.json`).
- A pixel baseline of the workshop (Playwright, WebGL2 on SwiftShader, DPR 1, Linux) and a scene-graph snapshot of the whole level, which now records each mesh's size.
- **Command palette (F1.3).** Press Ctrl+K or Ctrl+Shift+P (Cmd on macOS) anywhere, even while typing in a field or with a dialog open, to search every registered command by title, category or id. Recent commands come first and are remembered in settings; commands that aren't available right now (Undo with nothing to undo) stay listed with the reason. Commands with arguments open a form generated from the command's own argument schema: text, whole and decimal numbers with their limits, checkboxes, choices, nested groups, optional fields and defaults, with errors from the same schema shown next to each field. Entity fields offer the selected object once the viewport selects world objects. Cheat commands ask for confirmation before they mark the world as assisted. The palette is an accessible combobox that works with the arrow keys, Enter and Esc alone, and focus returns to where it was when it closes. Opening it runs the new `palette.open` view command, which is UI chrome and is never written to the replay log. A new library, `@controls/feature-palette`.
- Commands can be marked `logged: false` for UI chrome that replay doesn't need (`palette.open`). They run and notify listeners like any command but never enter the replay log, take no `seq` and leave undo and redo alone; `exec` results and executed events now say `logged: true` with the `entry`, or `logged: false` with `entry: null`, and carry the `command` (id, tick, args) either way. The registry refuses an unlogged command that is undoable or a cheat, and `exec` refuses one that tries to change the state. Replaying an older log that still contains such a command keeps the entry and its numbering. `Game.execOrThrow` returns `null` for unlogged commands.
- A Playwright test places a prop and undoes it using only the palette and the keyboard, and checks the final `world.hash` against a new `sim-cli` scenario, `apps/sim-cli/scenarios/palette-place-undo.console`, which reaches the same pinned hash through the console-line path.
- **Dev console (F1.5).** Press backtick in a Sandbox (or any dev build) to open the console in the workspace's bottom panel, and again to close it, from inside it too; Escape also closes it. Type the same `verb.noun --flag value` lines that `sim-cli` runs: Tab completes command ids, flag names and enum values from the command registry, ↑ and ↓ recall earlier lines (saved in settings, up to 200, so they survive a restart), and a mistake is underlined at its column with the reason. `help` lists every command and `help <id>` shows its arguments, keys and whether it can be undone, all generated from the registry. `world.hash` prints the world's hash without logging anything. `run` (or the Run file button, or dropping a file on the console) runs a console-line file: every line is checked before any runs, and nothing is ever evaluated as code. Before a cheat command runs, a banner warns that it will mark the save as assisted. The console uses CodeMirror 6, loaded only when first needed, and works under the desktop app's strict CSP without changes. [ADR 0008](docs/decisions/0008-console-and-scripts.md#codemirror-6-in-the-in-game-console-f15), [architecture](docs/architecture/console.md).
- **Placing, moving and deleting objects in the viewport (F1.7).** Pick a prop with keys 1–9 and a translucent ghost follows the mouse, snapping to the DIN rails (17.5 mm modules since F1.9), the backplate's 5 mm grid, or (from the workshop level) wall studs. Click to place it. Drag a placed object to move it, or select it and press M, then Enter or click to drop it. Delete (or Backspace) deletes the selected object. Escape cancels a move, then puts the tool away, then clears the selection, then opens the menu. Each commit is exactly one `entity.place` or `entity.move` command, and dragging records nothing, so a mouse session reaches the same `world.hash` as the equivalent console lines. That is tested end to end: `apps/sim-cli/scenarios/mouse-place-move-delete.console` under `pnpm sim run`, the same file run from the in-game console, and the same steps with the mouse in Playwright (forced WebGL2) all end at one pinned hash. With the pointer off the canvas, the ghost aims at the screen-centre reticle, so placement also works from the keyboard (Enter places).
- **The viewport draws the world.** Placed objects come from the world document and are drawn by entity id: added, moved or removed as commands run, undo and redo included. Props are procedural (box, crate, spool, bench), sharing one geometry and material per prop, and removing every object returns GPU memory and picking structures to where they started.
- **`view.mode walk|work` and `view.focus --target <id>` commands.** Switching mode and focusing a target are now logged view commands that any surface can run (`view.mode walk`, `view.focus din-rail-1`). V and F run them, and the viewport publishes `mode`, `selection.id`, `selection.kind`, `selection.focusable` and `selection.entityId` as `when` context keys.
- Keybindings can take arguments from the context (the Delete key passes the selected entity's id), and a command can declare extra default bindings with fixed or context arguments (`CommandDef.bindings`). The log always records the concrete values.
- `@controls/world-model` gains `placeOnTargets()` and `snapToBest()`, so a script can aim at a point and get exactly the position the mouse would (`apps/sim-cli/scenarios/mouse-place-move-delete.ts`), plus the built-in prop table (`prop.box`, `prop.crate`, `prop.spool`, `prop.bench` at version 1, game-design sizes). Since F1.9 the snap targets come from the world's fixtures (`worldSnapTargets`). `@controls/units` gains `mdegToRadians()`.
- **Keybindings (F1.4).** Every key that runs a command now goes through one keybinding service built on the command registry. Defaults come from each command (Ctrl+Z / Cmd+Z undo, Ctrl+Shift+Z / Cmd+Shift+Z redo, `Mod` meaning Cmd on macOS and Ctrl elsewhere). **Settings → Key bindings…** lists every command binding and every movement and viewport key, captures a new key from the keyboard (Escape cancels), and can unbind, reset one or reset all. Changes are saved in settings and survive a restart. Two bindings on the same keys that could be active at once are shown as a conflict on both, never silently shadowed. Keys never run commands while you type in a text field or code editor, or while a dialog is open. Tab, Shift+Tab and Escape are reserved. The rules (chord grammar, the conservative "provably disjoint" test, resolution order) are recorded in [ADR 0006](docs/decisions/0006-command-system.md#keybindings-f14).
- **Tool belt (F1.4).** Keys 1–9 select a tool-belt slot through the new `toolbelt.select {slot}` command (logged, no world change), and the HUD shows the active slot and the prop it holds. The viewport places the active slot's prop (F1.7).
- **Rebindable movement keys.** WASD, sprint, selection cycling, clear selection and (F1.7) the place and pick-up keys are input actions you can rebind. They still run in the renderer and never enter the replay log, and the viewport's accessible name lists the current keys.
- **Scripting API and `sim-cli` (F1.6).** A new framework-free library, `@controls/scripting-api`, gives scripts a typed `Game`: `createGame({ seed })` or `createGame({ world })`, then `exec`, `execOrThrow`, read-only `world()` snapshots, `hash()`, the replay log and `on('executed')`. `game.probe()` (P2) and `game.tag()` (P10) are reserved and throw a clear "not available" error. The game's `Session` now runs on the same `Game`, so the UI and scripts run identical code. A new headless app, `apps/sim-cli`, runs it in plain Node: `pnpm sim run <script>` runs a TypeScript module (bundled with esbuild at run time; it may import only domain libs) or a console-line file and prints `world.hash`, `pnpm sim replay <log>` replays a replay log and `pnpm sim hash <world>` hashes a world document; `--log` saves a run's replay log and `--expect` checks a hash. Until the `.ctrl` container lands they read the JSON documents a save holds. The four-surface scenario runs through the API, a script, console lines and a replay to one pinned hash as part of `pnpm verify`. [Scripting guide](docs/guides/scripting.md), [ADR 0008](docs/decisions/0008-console-and-scripts.md).
- **Console-line grammar.** `@controls/commands` gains the `verb.noun --flag value` parser shared by `sim-cli` and the upcoming in-game console: dotted command ids, positional arguments, dotted `--flag value` pairs mapped onto the command's Zod arguments, bare `--flag` for true, quoted strings, numbers and `#` comments, with every error pointing at a column. `formatConsoleLine` writes a command back as a console line, and any recorded session can be re-run as console lines to the same hash (property-tested).
- **Command system (F1.2).** A new framework-free library, `@controls/commands`, holds the one command registry behind the palette, keybindings, console and scripting API that are still to come. Commands have Zod-validated arguments, and an invalid or refused command returns a typed error and changes nothing. Undo and redo (`edit.undo`, `edit.redo`) are themselves commands. Every successful command, including undo, redo and view actions, is appended to the replay log, and replaying the log from its starting world reproduces the session exactly. `when` context expressions are parsed by a small hand-written parser (no `eval`). The semantics are in [ADR 0006](docs/decisions/0006-command-system.md).
- **World model (F1.2).** `@controls/world-model` adds the first world commands: `entity.place`, `entity.move`, `entity.rotate` and `entity.delete`. They use integer millimetres and millidegrees, take ids from the world's counter and are undoable (undoing a delete brings the entity back with the same id). It also adds `world.hash`, a SHA-256 of the world's canonical JSON written in plain TypeScript from FIPS 180-4, which gives the same value in Node and in Chromium (both are tested). Seeded randomness uses sfc32 with per-command and per-entity streams derived from the world seed. Property tests check that undoing everything restores the initial hash, that every change inverts exactly, and that replay reaches the live hash.
- `@controls/feature-session`, the Angular adapter: the world as a signal with its hash, `exec`, context keys for `when`, and a `?e2e=1` test hook. A new Playwright test checks the Node golden hashes in Chromium.
- Viewport cameras (F1.7, part 1). **Work mode** focuses the backplate or a DIN rail and orbits and pans within limits. **Walk mode** is first person, with WASD, mouse look under pointer lock (Esc releases it) and the room bounds. Press V to toggle between them and F to focus the selection (the `view.mode` and `view.focus` commands since F1.7). Movement goes through rebindable input actions, not Commands (ADR 0006).
- Hover and click selection in the viewport, using BVH picking (three-mesh-bvh). Keyboard users can cycle the selection with `[` and `]` and clear it with Esc. Selection is view state, not world state. The viewport shows the mode and the selected object, and a frame-time HUD in dev builds or with `?hud`.
- Pure, GPU-free snap maths in integer millimetres for TS35 DIN rails (17.5 mm modules since F1.9), the backplate grid and 16 in stud walls, with a cited `source` for every real-world dimension. Placement uses it since F1.7.
- `mm()`, `metresToMm()`, `roundMm()`, `inchesToMm()` and `isIntegerMm()` in `@controls/units`.
- A `?e2e=1` test hook on the viewport and Playwright tests for mode switching, focus, keyboard and mouse selection, and no GPU geometry leaks from selection churn, on the forced WebGL2 path.
- **Game shell (F1.1).** The game now opens on a main menu (New sandbox, Continue, Load, Settings, About, Quit) drawn over the live 3D view. Continue and Load are visible but disabled until saving lands, and Quit appears only in the desktop app. Escape returns to the menu, which offers Resume.
- **Docking workspace.** New sandbox opens the 3D viewport with an Inspector panel on the right and a Console panel at the bottom (the console itself arrives later). Panels resize with the mouse or keyboard (focus a splitter, then use the arrow keys, Home/End, or Enter to collapse), toggle from the toolbar, and Reset layout restores the defaults. [ADR 0005](docs/decisions/0005-docking-workspace.md) records why these are custom split panes and not dockview.
- **HUD** over the viewport, showing the interaction mode, a selection summary and an **Assisted** badge, which will appear once cheat commands exist.
- **Settings screen** with Interface (theme, reduce motion), Graphics (renderer backend, pixel-ratio cap), Audio (volumes, stored for when sound arrives), Controls (look sensitivity, invert Y), Units (imperial or metric), Difficulty (default for new games) and Region (NEC only, shown disabled). Settings are saved: to `settings.json` in the app's user-data folder on desktop (written atomically) and to browser storage in the web harness, and they survive a restart. A settings file that is corrupt, from another program or from a newer version is replaced by the defaults, with a warning. The panel layout is saved with them.
- **Notifications:** screen-reader-announced toasts (polite for info, assertive for warnings and errors). Each can be dismissed from the keyboard, and none disappears while you are reading it.
- **Light and dark themes** that follow the system setting or a choice in Settings, plus reduced motion when the system or Settings asks for it.
- **Keyboard-first accessibility:** every menu, dialog, panel and notification works without a mouse, focus is always visible, and focus returns to where it was when a dialog closes. New Playwright tests drive the whole shell by keyboard in the web harness, and the Electron smoke test checks the shell under the real CSP.
- New libraries `@controls/ui` (design tokens, buttons, dialog, focus trap, splitter, toasts), `@controls/feature-shell`, `@controls/feature-workspace` and `@controls/feature-settings`. `@controls/platform-api` gains `Platform.settings` (a `SettingsService` over the `@controls/save-format` settings schema, implemented for Electron and the web harness) and `Platform.canQuit`/`quit()`.
- IPC channels `settings:get`, `settings:set` and `app:quit`. `settings:set` is checked against the `app://` origin, size-capped at 1 MiB, validated as a current-version settings document, and refused with a reason only (the payload is never echoed). Quit now works on macOS too.
- `@testing-library/dom` and `@testing-library/user-event` (dev only) for role- and label-based component tests.
- `fast-check` (dev dependency) for property tests in domain libs, and a 90 % Vitest coverage gate for every `type:domain` lib, run by its `test` target and therefore by `pnpm verify`.
- A `scope:headless` module-boundary tag for the upcoming `apps/sim-cli`: it may depend only on `type:domain` libs.
- The save format's first version (`schemaVersion` 1) in a new framework-free library, `@controls/save-format` (F1.8a, [ADR 0007](docs/decisions/0007-world-document-v1.md)). It defines Zod schemas for the save manifest, the world document (seed, sim tick, entity id counter, region, difficulty, the "assisted" flag, entities by catalogue reference with integer-millimetre positions and millidegree orientations, and an `extensions` bag) and the replay log. A settings document (`settingsVersion` 1) with `defaultSettings()` covers graphics, audio, controls, keybinding overrides, palette and console history, display, gameplay defaults, workspace layout, autosave and the tool belt. Loading validates untrusted JSON, migrates it through a total migration chain and refuses saves from newer builds with a clear error. Every document round-trips losslessly through JSON (fast-check property tests). Fixtures for every version must keep loading, and JSON Schema exports are checked in and kept in sync by a test. Saving and loading in the game arrive with the `.ctrl` container (F1.8b).

### Changed

- **The world document gained `fixtures` (F1.9, still `schemaVersion` 1):** the level's fixed geometry, by catalogue ref and string id, which no command moves or deletes. Because every world now serialises `"fixtures":[]`, every `world.hash` changed: an empty seed-0 world, the save-format fixtures and all scenario hashes were re-pinned together in `world-model`, `sim-cli` and `game-e2e`. The scenarios themselves (and the game behind the main menu) now start from the workshop at seed 0. [ADR 0007](docs/decisions/0007-world-document-v1.md#fixtures-and-levels-f19) records why fixtures are a separate list and not entities.
- **DIN rail modules are now 17.5 mm (DIN 43880), not 18 mm.** Slot `k` starts `round(k × 17.5)` mm from the rail end, so a box dragged onto DIN rail 1 at the mouse scenario's point now lands at x = -75 mm instead of -70.
- The demo panel (`DEMO_PANEL`, `demoPanelSnapTargets()`, `buildPanelScene()`, `PANEL_ROOM_BOUNDS`) is gone: the backplate and rails are fixtures of the workshop level, in the same place. Scripts snap with `worldSnapTargets(game.world())`. Walking is bounded by the level's floor.
- Selection cycling on the workshop starts at the backboard; the viewport still starts focused on the backplate.
- A new view command, `console.toggle` (no world change; like `palette.open` it stays out of the replay log), is bound to backtick as a global binding, so the backtick key can't be typed in text fields while the console is available unless you rebind it. `@controls/commands` gains `consoleFields(schema)`, which lists the flags a command accepts (completion and `help` use it, so they match the console's argument mapping exactly). The workspace's bottom panel now lays its content out as a column so the console fills it.
- The snap maths moved from the renderer to `@controls/world-model` (`snap/`), so the 90 % domain coverage gate and the determinism lint now cover it, and scripts snap exactly like the mouse.
- V and F are no longer input actions: they are the `view.mode.walk` / `view.mode.work` and `view.focus.selection` bindings of the new commands. If you had rebound `input.toggleMode` or `input.focusSelection`, that override is now ignored (it stays in your settings file); rebind under View in Settings → Key bindings. Enter and M are new input actions for placing and picking up.
- Escape on the viewport now cancels a move or a placement before it clears the selection, and only then opens the menu.
- The scene-graph snapshot used by tests now includes each object's rotation in millidegrees.
- The renderer's default input-action keys now come from a shared table in `@controls/commands` (`INPUT_ACTIONS`), and `CommandDef.keybinding` accepts a list of chords. A new `CommandDef.globalKeybinding` flag lets the palette and console toggle work while typing. The settings `controls.keybindings` record now also holds fixed-argument and input-action bindings; its shape is unchanged.
- The determinism lint (no `Math.random`, wall clock, `performance` or `crypto`) now also covers `apps/sim-cli` and its scenario scripts, and a test lints a probe file to prove `sim-cli` can't import a non-domain library.
- World snapshots from the session are now deeply frozen; code that mutated one now throws instead of silently corrupting history.
- Reset layout now runs the `view.resetLayout` command. The command is logged but doesn't change the world hash, so the palette, keybindings and console will be able to reset the layout too. The HUD's Assisted badge now reads the world's `assisted` flag.
- The demo scene now has a floor, and the renderer is split into a GPU-free `ViewportController` (scene, cameras, input, picking) and a thin `ViewportRenderer` (GPU and frame loop), so disposal and picking are unit-tested.
- The about box moved from the top-left overlay into the main menu's About dialog. Its `about-*` test ids are unchanged.
- The 3D viewport component moved from `apps/game` to `@controls/feature-workspace`. Its mode and selection readout moved into the shell HUD (same `viewport-status` test id); the frame-time dev HUD and the walk-mode crosshair stay in the viewport. The canvas is the viewport's only focus target, and its focus ring uses the theme's focus colour.
- The F1.7 viewport e2e tests start a sandbox first, because the game now boots to the main menu with the viewport inert behind it.
- Domain libs are now provably framework-free and deterministic. Lint bans framework and UI packages (`@angular/*`, `rxjs`, `electron`, `three`, …) in `type:domain` libs, Node built-ins in domain source, and `Math.random`, `Date.now`, `new Date()`, `performance` and `crypto` in all domain code. Domain libs typecheck without the DOM lib or ambient Node types, via a shared `libs/domain/tsconfig.domain.json`. Before this, the boundary was only checked against workspace imports.
- `desktop-e2e:e2e` is explicitly never cached, so a packaged smoke run can't be replaced by a cached dev run.
- Toolchain patch updates at the Phase 1 kickoff: pnpm 11.15.0 → 11.28.8, electron-builder 26.18.0 → 26.18.1 and electron-updater 6.8.11 → 6.8.12. Nx 24.0.0 → 24.0.2 followed once it cleared pnpm's minimum release age (no `nx migrate` migrations).

## [0.1.0] - 2026-10-26

Phase 0, "Hello, panel": the cross-platform walking skeleton. Nothing playable yet.

### Added

- The first desktop build: an Electron 45 window titled "Controls" showing a 3D view of a white sub-panel with two TS35 DIN rails. The view is built procedurally, uses WebGPU when available and WebGL2 otherwise, can be orbited with the mouse, and resizes with the window.
- An about box showing the app version, platform (with the Electron version), active render backend (`webgpu` or `webgl2`) and whether the page is cross-origin isolated.
- Installers for Windows (NSIS), macOS (universal dmg and zip) and Linux (AppImage, deb, rpm). They are unsigned, and packaged builds check GitHub Releases for updates (not on macOS while builds are unsigned).
- Security hardening for the desktop shell. The game is served from a custom `app://` origin with COOP/COEP and a strict CSP (no `unsafe-eval`), path traversal is refused, and the sandboxed renderer has no Node access. Navigation, pop-ups, `<webview>` and permission requests are denied, and `https://` links open in the system browser. Electron Fuses disable RunAsNode, `NODE_OPTIONS` and the inspect flags, and turn on cookie encryption and ASAR integrity. Only one instance of the app can run at a time.
- A typed, Zod-validated IPC skeleton (`@controls/ipc-contract`). One `app:info` channel, which accepts calls only from the app's own origin, is exposed to the renderer as `window.controls.getAppInfo()`. The preload imports a narrow `@controls/ipc-contract/preload` entry, so Zod stays out of it.
- A browser dev harness (`pnpm start:web`) that runs the same Angular 22 zoneless app with `@controls/platform-web` instead of the Electron bridge.
- Developer workspace: Nx 24 + pnpm 11, TypeScript 6.0 strict, ESLint flat config with module-boundary tags (`type:app`, `type:feature`, `type:ui`, `type:domain`, `type:rendering`, `type:platform`, `type:contract`, `type:e2e`), Prettier, and Node 24 pinned in `.nvmrc`.
- `pnpm verify`, which runs exactly what CI runs: Prettier check, lint, typecheck, unit tests, build and the version-sync check. `pnpm version:sync` copies the root version into the desktop app and `@controls/units`.
- End-to-end tests: `apps/game-e2e` (Playwright against the web harness, including a check that the viewport isn't blank) and `apps/desktop-e2e` (an Electron smoke suite that runs against the built app, or against a packaged binary via `CONTROLS_E2E_EXECUTABLE`).
- GitHub Actions: `pr.yml` (verify and both e2e suites on Linux), `main.yml` (the same on Windows, macOS and Linux) and `release.yml` (on a `v*.*.*` tag: check the tag matches the version, verify, package each OS, smoke-test the packaged app, and only then upload it to a **draft** GitHub Release with `latest*.yml`). All three share the `.github/actions/setup` composite action.
- Documentation skeleton: README, this changelog, the docs hub, architecture overview, caveats, ADRs 0001–0004, glossary, history, new-developer and releasing guides, `THIRD_PARTY_NOTICES.md` and the MIT licence.
- Claude Code setup: `CLAUDE.md`, the `docs-keeper`, `version-keeper`, `release-engineer`, `electron-platform-engineer` and `test-engineer` agents, and the `/verify`, `/docs-sync` and `/release` skills.
