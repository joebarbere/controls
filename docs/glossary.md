## Electrical trade

| Term                       | Meaning                                                                                                                                                                                                                                                                                                                                                 |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **AFCI**                   | Arc-fault circuit interrupter. A breaker that trips on arcing signatures. Abstracted in the game as a probabilistic trip (realism charter §3.2).                                                                                                                                                                                                        |
| **Ampacity**               | The current a conductor can carry continuously without exceeding its temperature rating. Taken from cited published data, never copied NEC tables.                                                                                                                                                                                                      |
| **AWG**                    | American Wire Gauge. Display-only in the game; geometry and physics use SI (mm², metres).                                                                                                                                                                                                                                                               |
| **CAT rating**             | A meter's overvoltage category (CAT II–IV). Part of the instrument's tool state; using a low-CAT meter on service equipment is a safety violation.                                                                                                                                                                                                      |
| **EGC**                    | Equipment grounding conductor: the bare or green wire that bonds metal parts so a fault trips the breaker. A lost EGC leaves an enclosure live during a fault.                                                                                                                                                                                          |
| **FLA**                    | Full-load amps, from a motor nameplate. Overload relays are set to FLA, not to the breaker rating.                                                                                                                                                                                                                                                      |
| **GEC**                    | Grounding electrode conductor: connects the service to the ground rod or other electrode.                                                                                                                                                                                                                                                               |
| **GFCI**                   | Ground-fault circuit interrupter. Trips when residual current exceeds about 5 mA (NEC profile).                                                                                                                                                                                                                                                         |
| **Ghost voltage**          | A misleading reading on a high-impedance (10 MΩ) meter caused by capacitive coupling to an open conductor. Emerges from the solver because the meter is stamped into the circuit.                                                                                                                                                                       |
| **LoZ**                    | Low-impedance meter mode (about 3 kΩ) that loads the circuit and makes ghost voltage disappear.                                                                                                                                                                                                                                                         |
| **LOTO**                   | Lockout/tagout: isolating, locking and verifying zero energy before work. A mechanic, not a cutscene.                                                                                                                                                                                                                                                   |
| **Live–dead–live**         | Testing a meter on a known live source, then the de-energised circuit, then the live source again. Tracked by the safety system.                                                                                                                                                                                                                        |
| **MWBC**                   | Multiwire branch circuit: two hots sharing one neutral. Losing the neutral causes overvoltage on one leg.                                                                                                                                                                                                                                               |
| **NEC**                    | National Electrical Code (NFPA 70), the US installation code. The game paraphrases requirements and cites article numbers; it never reproduces NEC text or tables.                                                                                                                                                                                      |
| **OCPD**                   | Overcurrent protective device: a breaker or fuse.                                                                                                                                                                                                                                                                                                       |
| **Melting I²t**            | A fuse's melting integral, ∫I² dt in A²·s: the heat that melts its element when the current is so large that nothing is lost to cooling. From the datasheet; the bench fuse's is 0.7 A²·s.                                                                                                                                                              |
| **Minimum fusing current** | The smallest current that eventually melts a fuse (I_min); below it the fuse carries current indefinitely. Given as a ratio to the rating, between 1 and 1.35.                                                                                                                                                                                          |
| **Ultimate trip ratio**    | The smallest multiple of a breaker's rating that trips it thermally at all (k_u, 1.25 for the bench breaker); it carries anything below indefinitely.                                                                                                                                                                                                   |
| **Magnetic pickup**        | The current above which a breaker's magnetic element trips it instantly. Published as a band (8 to 12 × the rating for the bench breaker); each breaker in the game draws its own from its seeded stream.                                                                                                                                               |
| **Trip / reset**           | A breaker trips when its thermal or magnetic element opens it, leaving the handle where it was. Reset by turning the handle off, then on again to close it.                                                                                                                                                                                             |
| **Single-phasing**         | A three-phase motor losing one phase. It hums, draws high current on the remaining phases and should trip its overload.                                                                                                                                                                                                                                 |
| **RMS**                    | Root mean square: the steady value that dissipates the same power in a resistor as the waveform. Nominal AC voltages are RMS (a 120 V supply peaks at about 170 V), and the AC solver's phasors are RMS magnitudes (ADR 0011 §5.3).                                                                                                                     |
| **Split-phase**            | The residential US service: 120/240 V from a centre-tapped transformer. Each line is 120 V from the neutral (the centre tap) and the two lines are 180° apart, so they are 240 V from each other. The neutral carries the phasor sum of the line currents: zero when the two sides are balanced. `RegionProfile.splitPhase` (`@controls/catalog`).      |
| **Wye**                    | A three-phase connection with each phase from a common star point, usually the grounded neutral: 208Y/120 V or 480Y/277 V. Phases are 120° apart, so line to line is √3 times line to neutral (120 × √3 = 207.85 V, named 208). A balanced wye load returns no current on the neutral. `RegionProfile.threePhaseCommercial` and `threePhaseIndustrial`. |
| **Test lead**              | A flexible lead with a clip or probe at each end, used to join terminals on a bench or to a meter. In the game a test lead is a connection between two terminals (`lead.connect`, P2), whose resistance is derived from copper's resistivity, its length and its cross-section.                                                                         |

## Controls and automation

| Term                  | Meaning                                                                                                      |
| --------------------- | ------------------------------------------------------------------------------------------------------------ |
| **4–20 mA**           | The analog current-loop standard. 4 mA is the live zero; a broken loop reads 0 mA.                           |
| **FBD**               | Function Block Diagram, an IEC 61131-3 language (P11).                                                       |
| **HMI**               | Human-machine interface: an operator screen bound to PLC tags (P12).                                         |
| **Ladder logic (LD)** | The relay-diagram-style PLC language, with instructions such as XIC, XIO, OTE and TON (P10).                 |
| **PLC**               | Programmable logic controller. Each simulated PLC runs in its own worker, scanning on sim-clock ticks (P10). |
| **PLCopen TC6 XML**   | The open interchange format for IEC 61131 programs; used for import/export.                                  |
| **PNP / NPN**         | Sourcing / sinking transistor sensor outputs. A PNP sensor on a sinking input card never turns the input on. |
| **SCADA**             | Supervisory control and data acquisition: plant-wide HMI, alarms and trends (P12).                           |
| **Scan cycle**        | A PLC's loop: read inputs → execute program → write outputs → housekeeping.                                  |
| **ST**                | Structured Text, the Pascal-like IEC 61131-3 language (P11).                                                 |

## Simulation

| Term                       | Meaning                                                                                                                                                                                                                                                                                                                                                                                      |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **gmin**                   | `GMIN_S`, 1e-12 S: a tiny conductance the solver puts from every node to its island's reference node, so every node has a defined voltage and the matrix is singular only for loops of ideal sources. A numerical setting, not an electrical one; its losses count in the power balance.                                                                                                     |
| **Reference node**         | The node an island's voltages are measured against, eliminated from its MNA system: the negative end of the island's first voltage source, or its smallest node if it has none. Its own voltage is 0.                                                                                                                                                                                        |
| **Region profile**         | `RegionProfile` in `@controls/catalog` (F2.2 part 2): a region's supply frequency and nominal system voltages, each with a source. NEC: 60 Hz, 120/240 V split-phase, 208Y/120 V and 480Y/277 V.                                                                                                                                                                                             |
| **Singular island**        | An island whose MNA matrix has no unique solution: in DC, exactly when zero-ohm voltage sources form a loop. The solver flags it `singular` and reports every value as 0, never NaN.                                                                                                                                                                                                         |
| **Branch**                 | One element between two nodes in the netlist: a lead, a battery cell, a lamp filament. Each lead is exactly one branch; a closed switch is a join, not a branch. Numbered entity elements first (entity id, then part), then connections by id.                                                                                                                                              |
| **Ideal join**             | Terminals a device connects with zero resistance (a closed switch's two terminals): merged into one node by union-find, with no branch.                                                                                                                                                                                                                                                      |
| **Island**                 | A set of nodes connected to each other but not to the rest of the circuit, solved separately. Classified by its sources: `dc`, `ac`, `empty` (unpowered) or `mixed` (reported as a diagnostic in P2). Numbered by its smallest node.                                                                                                                                                         |
| **MNA**                    | Modified nodal analysis: circuit equations as one matrix, with node voltages plus voltage-source currents as unknowns and KCL plus source equations as rows. Controls uses real-valued MNA for DC (`DcSolver`, F2.2) and complex phasor MNA for 60 Hz AC.                                                                                                                                    |
| **Netlist**                | The electrical graph (nodes and branches) compiled from the physical as-built wiring.                                                                                                                                                                                                                                                                                                        |
| **`netlist.dump`**         | A read-only console query (F2.6): `formatNetlist` plus one `solve island` line per island (status, flags, iterations, reference, unknowns, nominal band, and the unvalued branches or mixed sources of an unsolved one). A pure function of the materialised world, so the same bytes headless and in the game.                                                                              |
| **Netlist compiler**       | `compileNetlist(world, catalog)` in `sim-core` (F2.1): turns entities, catalogue terminals, connections and device state into nodes, branches and islands, union-finding ideal joins. `NetlistCompiler` recompiles incrementally.                                                                                                                                                            |
| **Node**                   | A set of terminals joined ideally, one voltage in the solver. Numbered by its smallest member terminal (entity id, then terminal id), so the numbering is a pure function of the world.                                                                                                                                                                                                      |
| **Oracle corpus**          | 500 DC and 500 AC seeded random circuits under `libs/domain/sim-core/oracle/`: SPICE decks plus ngspice 47's results, checked in. `pnpm verify` reads only the files; `pnpm sim oracle regen` refreshes them. See [ADR 0012](decisions/0012-oracle-corpus.md).                                                                                                                               |
| **Oracle test**            | A test comparing `sim-core` results with the oracle corpus (P2): each node voltage and branch current within ADR 0012's tolerance.                                                                                                                                                                                                                                                           |
| **Phasor**                 | A complex number for a sinusoid at a fixed frequency: its RMS magnitude and its phase, V∠θ = re + j·im. The phasor solver (`AcSolver`, F2.2 part 2) solves AC islands as phasors at the region frequency instead of time-stepping. Source angles are restricted to 0°, 180° and ±120°, whose cosines and sines are exact constants (D6).                                                     |
| **Phasor solver**          | `AcSolver` in `sim-core` (F2.2 part 2): MNA in complex arithmetic for `ac` islands at ω = 2π f, with complex dense or sparse LU. Inductors and capacitors are AC stamp modes (admittances −j/(ωL) and jωC) on `resistor` elements.                                                                                                                                                           |
| **Quasi-static**           | Solving steady-state phasors at each update rather than a full time-domain transient. See [ADR 0002](decisions/0002-simulation-architecture.md).                                                                                                                                                                                                                                             |
| **Stamp**                  | An element's contribution to the MNA matrix and right-hand side: a resistor's conductance, a voltage source's row, a current source's injection (`DcBranchValues`). Meters are stamped too, which is why readings are truthful.                                                                                                                                                              |
| **AMD**                    | Approximate minimum degree: a fill-reducing ordering of a sparse matrix's columns (Amestoy, Davis and Duff, 1996). `amdOrder` in `sim-core` reimplements it from the paper; sparse LU eliminates in its order (F2.2 part 3).                                                                                                                                                                 |
| **Calibration loop**       | `sim bench`'s fixed reference workload (F2.2 part 3b, `apps/sim-cli/src/bench/calibration.ts`): float, integer and object work that shares no code with the simulator. Timed beside each re-solve run, it scales the run to the reference machine (`CALIBRATION_REFERENCE_MS`), so the 2 ms budget gates the same ratio on every runner.                                                     |
| **Factorisation cache**    | `FactorisationCache` in `sim-core` (F2.2 part 3): an island's symbolic factorisation, kept by `topologyHash`, island and stamp modes in a 16-topology LRU, so a value change or a return to an earlier switch state skips rebuilding it. Results never depend on its state.                                                                                                                  |
| **Fill-in**                | Entries that LU factorisation creates where the matrix had zeros. A good ordering (AMD) keeps it small; a radial plant island of 250 unknowns gets about 970 L+U entries in AMD order, against about 22 000 in natural order.                                                                                                                                                                |
| **`nonConverged`**         | `ISLAND_FLAG_NON_CONVERGED` (2): the island flag the nonlinear outer loop sets when its iterate is still moving after `OUTER_LOOP_MAX_ITERATIONS` solves. The values are then the last linear solve's, self-consistent and so plausible-looking: the flag is the only sign, so every player-facing readout of such an island must show it as unsettled (planned for F2.4 and P5).            |
| **Outer loop**             | `DcSolver.solveNonlinear` (F2.2 part 3): repeated linear solves of an island, with a value hook per iteration (a lamp's R(T), a supply's CV/CC mode), a warm start, damping and an iteration cap, until the solution stops moving.                                                                                                                                                           |
| **Sparse LU**              | LU factorisation that stores and computes only non-zero entries. `SparseLu` in `sim-core` is Gilbert–Peierls left-looking LU with threshold partial pivoting, used for islands of at least 64 unknowns (`SPARSE_MIN_UNKNOWNS`).                                                                                                                                                              |
| **Symbolic factorisation** | The value-independent part of a sparse factorisation: the matrix pattern, the column ordering (AMD) and, in `sim-core`, the stamp program and slot map. It depends only on the topology and the stamp modes, so it is cached and reused while only values change.                                                                                                                            |
| **Threshold pivoting**     | Partial pivoting that keeps the diagonal pivot while it is at least a fraction u of the column's largest candidate trading a bounded growth (multipliers up to 1/u) for the ordering's sparsity. `PIVOT_THRESHOLD` is u = 1 since #51: plain partial pivoting, the diagonal winning ties, because u = 0.1's noise stalled the outer loop and u = 1 cost only 0.3 % more fill on MNA systems. |
| **Topology hash**          | `topologyHash`: SHA-256 of a canonical byte encoding of a netlist's structure (the node partition, and each branch's element, kinds and ends), without values. Keys the factorisation cache; persisted in `WorldV2.sim` and snapshots.                                                                                                                                                       |
| **Tick**                   | One integer step of sim time (1 kHz). Sim time is always an integer tick count for determinism.                                                                                                                                                                                                                                                                                              |
| **Engine loop**            | `SimEngine` in `sim-core` (F2.3a): the sim clock. Each tick it solves on the 10-tick cadence, then runs the discrete, continuous and protection layers; a command or a trip that changes the netlist is solved at once. It follows a world bus as its time host and exports sim bags plus the solution record.                                                                               |
| **Device bank**            | One model kind's netlisted devices inside the engine (`SimDeviceBank`, F2.3a): preallocated struct-of-arrays state and the kind's layer and value hooks, rebuilt from the devices' sim bags at every topology change.                                                                                                                                                                        |
| **Materialise**            | Write the engine's sim-owned state (each netlisted device's `sim` bag and the solution record) into the commanded world: `materialiseWorld` in `sim-protocol`. What a save writes and `world.hash` hashes.                                                                                                                                                                                   |
| **Snapshot**               | One slot of the sim's published state at a tick (ADR 0011 §5): node voltages, branch currents, islands and device records in a fixed little-endian layout. Its hashed bytes are byte-identical for the same seed and log in every runtime (`game.snapshot()`, `snapshotHash`).                                                                                                               |
| **Solution record**        | `WorldV2.sim`: the last electrical solution (its tick, `topologyHash`, node and branch values, island flags and iterations), persisted so a load continues bit-exactly; 0 iterations marks an island that wasn't solved.                                                                                                                                                                     |
| **Time host**              | What moves sim time for a command bus (ADR 0011 §3): headless, the in-process `SimEngine` (`replayEntries`' `time`, the scripting API); in the game, the sim worker's `SimHost` (`TimeHost`, `createGame({ time })`). It carries out `sim.step`.                                                                                                                                             |
| **SimHost**                | The main thread's side of the sim worker (`feature-session`, F2.3b): one worker per game, every logged entry and advance forwarded, pacing, the snapshot reader and listeners, `hashAt()` and save captures, suspend and hold, crash and watchdog.                                                                                                                                           |
| **Pacing**                 | Turning wall time into integer tick targets on the main thread (`Pacer`, ADR 0011 §2): `min(desired, progress + speed × MAX_LEAD_WALL_MS)`, with lost time dropped, so a slow plant runs at its achievable speed instead of spiralling.                                                                                                                                                      |
| **Effective speed**        | The achieved multiple of real time, Δtick ÷ Δwall over a 1 s window (`SpeedMeter`). Below 0.9 × the requested speed for two windows in a row the HUD says "falling behind"; one window at 0.97 × clears it.                                                                                                                                                                                  |
| **Suspended**              | The sim's status while the window is hidden: pacing stops (host state, not a command; the speed is unchanged) and resumes, re-anchored, when it is shown (ADR 0011 U1).                                                                                                                                                                                                                      |
| **Watchdog**               | `SimHost`'s crash detector: no snapshot published for `WATCHDOG_MS` (3 s) while the commanded tick is ahead of the worker's progress terminates the worker as crashed.                                                                                                                                                                                                                       |
| **Session seq**            | The first `seq` a session logs (`Session`, set at start or adopt): entries below it were carried over from a loaded log. Only commands at or above it make a game dirty.                                                                                                                                                                                                                     |
| **Sim crash**              | A worker error, `onerror`, `onmessageerror` or the watchdog: the worker is terminated, pacing stops, readers reset, the world and log stay intact, saving is refused, and `sim.restart` replays the log into a new worker.                                                                                                                                                                   |
| **Unmodelled island**      | An island holding an element no device model can value yet (every lamp in engines 3 and 4, before F2.5's filament model): not solved, recorded with 0 iterations and zeros, and read by `probe` as `unsolved`, never as 0 V.                                                                                                                                                                 |
| **Tombstone**              | A deleted device's sim state, kept by the engine (never persisted) while its id can't be reused, so undoing the delete restores it as it was (a blown fuse still blown).                                                                                                                                                                                                                     |
| **Ideal probe**            | `game.probe(a, b)` (F2.3a): V(a) − V(b) read from the solution, as an ideal voltmeter that doesn't load the circuit. A script and test query, not a player's meter (P5).                                                                                                                                                                                                                     |
| **Seqlock**                | A lock-free single-writer protocol over shared memory (ADR 0011 §6): the writer makes a slot's sequence word odd, writes, then makes it even; a reader copies the slot between two loads of the word and keeps the copy only if both were the same even value. The sim worker writes snapshots with it (`SnapshotWriter`), `SnapshotReader` reads them.                                      |
| **Topology descriptor**    | `TopologyDescriptor` (ADR 0011 §7): what a snapshot's indices mean for one topology generation (each node's member terminals, each branch's element and ends, the islands, and where each device's record is). Sent by message once per generation, before its first slot; a new object for each generation and each worker.                                                                 |
| **Topology generation**    | A count of topology changes since an engine started, in each slot's unhashed header, joining a slot to its descriptor. A restarted worker counts from 0 again, so readers key on the descriptor's identity, never the number.                                                                                                                                                                |
| **Snapshot reader**        | `SnapshotReader` in `sim-protocol` (F2.3b): copies the latest complete slot into a private buffer under the seqlock and returns the same `SnapshotView` every time; `SimHost` owns the one reader per worker.                                                                                                                                                                                |
| **Mirror bus**             | The sim worker's own world bus (ADR 0011 §1): it re-executes every logged entry the main thread sends, through `replayEntries`, so the worker's world matches main's; any refusal is a `desync` error.                                                                                                                                                                                       |
| **Fallback transport**     | The `postMessage` path (`?sab=0`, or a page that isn't cross-origin isolated): each snapshot is encoded into one of three pooled `ArrayBuffer`s and transferred, giving the same bytes as the shared buffer (ADR 0011 §8).                                                                                                                                                                   |
| **Idle publish**           | The unthrottled snapshot the worker publishes when it has handled every message and reached its target, so a paused sim always shows its exact tick.                                                                                                                                                                                                                                         |
| **Union-find**             | A disjoint-set structure used to merge terminals joined by wires and closed contacts before matrix assembly.                                                                                                                                                                                                                                                                                 |
| **CV/CC**                  | Constant voltage / constant current: a regulated supply holds its voltage setpoint until the load would draw more than its current limit, then holds the limit and lets the voltage fall. The crossover is at a load of about V/I. In `sim-core` the mode is decided in the outer loop with a 0.1 % hysteresis band, so it never chatters (F2.4).                                            |
| **Hiccup mode**            | An overload protection of switch-mode supplies: after a sustained overload the output switches off, waits, then retries, so a short makes the output pulse on and off instead of holding the current limit. The DIN PSU's period is `hiccupDetectMs` + `hiccupOffMs` ticks (F2.4).                                                                                                           |
| **Gassing voltage**        | The charge voltage at which a lead-acid cell starts to split water, about 2.4 V per cell (14.4 V for a 12 V battery). In `sim-core` a charging battery's EMF rises towards it as the battery fills, so charge current tapers (F2.4).                                                                                                                                                         |
| **Output resistance**      | How much a regulated output's voltage droops per amp of load, from its load-regulation figure (1 mΩ for the bench supply). Never 0 in `sim-core`, so paralleled supplies are never an ideal-source loop.                                                                                                                                                                                     |
| **State of charge (SoC)**  | How full a battery is, as a fraction of its rated capacity (0 to 1). The battery's EMF follows it, and the engine coulomb-counts it each tick into the battery's `stateOfCharge` sim key (F2.4).                                                                                                                                                                                             |
| **Validity rule**          | A device record's solved quantities (volts, amps) are a reading only on a `solved` island; its `status` field says which (`unsolved`, `solved`, `unsettled`, `singular`), and an `unsettled` value is never shown as steady (ADR 0011 §5.4, F2.4).                                                                                                                                           |
| **Bolted fault current**   | The current that flows when a source's terminals are joined by a connection of (nearly) zero impedance: the most the supply can deliver, V / \|Z\| of its source impedance. Protective devices must be able to interrupt it. In `sim-core` a split-phase service's is its L1–L2 fault, a three-phase one's the three-phase fault (F2.4).                                                     |
| **%Z (percent impedance)** | A transformer's (or an alternator's) impedance as a percentage of its own base impedance V² / S. With the kVA rating it gives the source impedance in ohms, and so the bolted fault current; the X/R ratio splits it into resistance and reactance (F2.4).                                                                                                                                   |
| **Range A / Range B**      | ANSI C84.1's steady-state voltage tolerance bands, at the service point and at the utilization point: A for normal operation, B for infrequent, short excursions. `RegionProfile.voltageRanges` holds them as fractions of nominal (F2.4).                                                                                                                                                   |
| **Inrush**                 | The surge a load draws when switched on before it settles. A cold tungsten filament is about a fifteenth of its hot resistance, so a lamp's first current is 10 to 15 times its running current. In the game it emerges from the lamp's model (F2.5), never scripted.                                                                                                                        |
| **Filament R(T)**          | The lamp's resistance as a function of its filament temperature: its rated resistance V_r² / P_r scaled by tungsten's resistivity at T over that at the rated temperature (Jones and Langmuir's data, piecewise linear). The temperature (`filamentTempK`) is the lamp's sim-owned state.                                                                                                    |
| **`lightOutputRel`**       | A lamp's light output relative to rated, in its device record: x^(17/8), x the filament's radiated power over rated (from L ∝ V^3.4 and P ∝ V^1.6). It follows the filament, so it is dark during the inrush and fades as the filament cools.                                                                                                                                                |
| **Display step**           | One step of an 8-bit display, 1/255. The bench-lamp scenario counts a lamp as out when its `lightOutputRel` is under one.                                                                                                                                                                                                                                                                    |
| **Continuous re-solve**    | A re-solve within the step, without a recompile, when a continuous layer says a value the last solve used has gone stale (`stats.continuousSolves`, F2.5): a heating lamp's R(T) moving more than 1 %.                                                                                                                                                                                       |
| **`overRated`**            | A resistor record's solved flag: I²R above its power rating. No damage follows in P2.                                                                                                                                                                                                                                                                                                        |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`commanded` hook**                   | `SimDeviceBank.commanded(index, state)` (F2.5 part 2): the engine calls it when a logged command replaces a netlisted device's commanded state, before the recompile, so the sim can resolve the command's effect on sim state (a breaker's handle turned off resets a trip) without the command reading sim state.                                                                          |
| **`meltFraction` / `thermalFraction`** | A fuse's element temperature rise as a fraction of the rise that melts it (1 blows it), and a breaker's bimetal state as a fraction of its trip point (θ / k_u²), in their device records.                                                                                                                                                                                                   |

## Game and codebase

| Term                            | Meaning                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Argument form**               | The palette's form for a command's arguments, generated from its Zod `args` through `z.toJSONSchema` (`buildArgForm` in `@controls/feature-palette`). **Arg hints** are `.meta()` keywords that only label or explain a field (`title`, `description`) or mark a reference (`x-controls-ref: entity`, which offers the selection); they never change what the schema accepts.                                                                                                                                      |
| **As-built**                    | The physical wiring the player (or job author) actually installed. The simulator runs the as-built, not the print.                                                                                                                                                                                                                                                                                                                                                                                                 |
| **Assisted**                    | A world flag set once a cheat command has run (palette, console or script). It persists in the save and is never cleared; assisted runs are excluded from career scoring.                                                                                                                                                                                                                                                                                                                                          |
| **Bench top**                   | A horizontal snap target (F1.9): props set on the workshop bench stand on its top on a 10 mm grid, turned so their depth points up (pitch -90°).                                                                                                                                                                                                                                                                                                                                                                   |
| **Autosave slot**               | One of N rotating autosave files (`saves/autosave/slot-1.ctrl` … `slot-N.ctrl`, N from settings `autosave.slotCount`). Main (or the web store) picks the slot: the one after the last written this session, else the lowest free, else the oldest. Slots above N are removed. [ADR 0009](decisions/0009-save-io-boundary.md). The game autosaves a game with **unsaved changes** every `autosave.intervalSeconds`, on return to the menu, before a load replaces it and before quit (F1.8b).                       |
| **BVH**                         | Bounding volume hierarchy: a tree of nested boxes that makes ray picking logarithmic instead of testing every triangle. The renderer uses three-mesh-bvh: an `ObjectBVH` over selectable objects, then a `MeshBVH` per geometry.                                                                                                                                                                                                                                                                                   |
| **Catalogue entry**             | One device definition in `content/devices/<id>.v<version>.json` (`DeviceDefinition` in `@controls/catalog`): id and version, a fictional brand and model name, category, size, terminals `{ id, label, positionMm }`, the model `{ kind, params }`, controls and `sources`. Every number has a source.                                                                                                                                                                                                             |
| **Catalogue reference**         | How a save points at a device or prop: `{ id, version }` (e.g. `prop.crate` at version 1), never an inlined copy, so catalogue fixes reach old saves.                                                                                                                                                                                                                                                                                                                                                              |
| **`catalogVersion`**            | Version of the device catalogue in `content/`. Versioned independently of the app.                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| **Command**                     | A registered, Zod-typed action (`entity.place`, `view.resetLayout`). The only way the world changes; shared by the palette, keybinds, console and scripting API. Its `run` is pure and returns an apply/invert pair, nothing, or a refusal ([ADR 0006](decisions/0006-command-system.md)).                                                                                                                                                                                                                         |
| **Command bus**                 | `CommandBus` in `@controls/commands`: runs commands by id, keeps the undo and redo stacks and appends each successful command to the replay log.                                                                                                                                                                                                                                                                                                                                                                   |
| **Command palette**             | The searchable list of every registered command (Ctrl+K or Ctrl+Shift+P, the `palette.open` command): fuzzy search over title, category and id, recent commands first, unavailable commands shown with the reason, and an argument form for commands that take arguments (F1.3).                                                                                                                                                                                                                                   |
| **Console line**                | One line of the dev console's `verb.noun --flag value` syntax (`entity.delete 3`, `entity.move 1 --positionMm.x 150 …`). Positional words fill a command's args in key order, dotted flags fill nested fields, and the command's Zod schema validates the result. A **console-line file** (`.console`) is a script made of them: data, so it runs in the game as well as in `sim-cli` ([ADR 0008](decisions/0008-console-and-scripts.md)).                                                                         |
| **Continue**                    | The main-menu action that resumes the game the player was last in: the **last-played save** if it loads, else the newest save in the save directory that loads (manual or autosave), skipping damaged ones with one warning. Disabled, with "No saved games yet.", until there is a save (F1.8b).                                                                                                                                                                                                                  |
| **Connection**                  | A two-ended link between two device terminals in the world document (`WorldV2.connections`, `{ id, ref, a, b }` with `a` and `b` each `{ entity, terminal }`): a test lead in P2, wires from P3. Ids come from `nextConnectionId`; deleting an entity removes its connections.                                                                                                                                                                                                                                     |
| **Context argument**            | A command argument a keybinding takes from a context key when the key is pressed (`entity.delete.selection` takes `id` from `selection.entityId`). The binding fires only while the key is set, and the log records the concrete value (ADR 0006, F1.7).                                                                                                                                                                                                                                                           |
| **Context expression (`when`)** | A small boolean expression on a command (`mode == 'work' && selection.kind == 'terminal'`) that tells the palette and keybindings whether to offer it. Parsed by hand (no `eval`); advisory, so `exec` never checks it (ADR 0006).                                                                                                                                                                                                                                                                                 |
| **`.ctrl`**                     | The save file: a ZIP of JSON documents with a manifest. See [ADR 0004](decisions/0004-save-format.md).                                                                                                                                                                                                                                                                                                                                                                                                             |
| **Dev console**                 | The in-game text surface for commands (`@controls/feature-console`, F1.5), docked in the workspace's bottom panel and toggled with backtick (`console.toggle`). Available in Sandbox and dev builds (the `console.available` context key). It runs console lines through the one registry, with Tab completion, history in settings, `help`, `world.hash` and `run` for console-line files ([architecture](architecture/console.md)).                                                                              |
| **Docking workspace**           | The in-game layout: the 3D viewport plus docked panels (inspector on the right, console at the bottom), resized with keyboard-operable splitters. Custom split panes, not dockview ([ADR 0005](decisions/0005-docking-workspace.md)).                                                                                                                                                                                                                                                                              |
| **`extensions` bag**            | A JSON object on the world, each entity, the manifest and settings for data the current schema doesn't model. It must round-trip untouched.                                                                                                                                                                                                                                                                                                                                                                        |
| **File commands**               | `file.save` (Mod+S), `file.saveAs` (Mod+Shift+S), `file.open` (Mod+O) and `file.load` (Mod+L): unlogged UI commands registered by the game host's `Session`, performed by `SaveGames` (`@controls/feature-saves`). Never in the replay log ([ADR 0006](decisions/0006-command-system.md#saving-and-loading-f18b)).                                                                                                                                                                                                 |
| **Fixture (level)**             | Fixed level geometry in a world's `fixtures` list (F1.9): the workshop's floor, stud wall, backboard, backplate, DIN rails and bench. Named by a string id (`stud-wall`), drawn by a procedural recipe for its `prop.*` ref, and never created, moved or deleted by a command. Not an entity: it takes no entity id.                                                                                                                                                                                               |
| **Fixture (save-format)**       | A checked-in example document for a given `schemaVersion` (`libs/domain/save-format/fixtures/`). Every fixture of every version must load forever.                                                                                                                                                                                                                                                                                                                                                                 |
| **Flush before quit**           | The handshake that keeps buffered writes (the settings debounce, autosave since F1.8b): main holds a window close or app quit, sends `app:flush-request`, and waits up to 2 s for `app:flush-ack` while the renderer runs every flush registered with `Platform.lifecycle.onBeforeQuit`. The web harness flushes on `pagehide`.                                                                                                                                                                                    |
| **Four-surface scenario**       | The P1 acceptance scenario (place, move, rotate, delete, undo, redo) driven through every surface and required to reach one pinned `world.hash`. Headless drivers (scripting API, TypeScript script, console-line file, replay) run in `sim-cli`'s tests; mouse, palette and console in `apps/game-e2e`.                                                                                                                                                                                                           |
| **Gesture intent**              | What the renderer emits at a gesture's commit point (`place`, `move`, `cancelPlacement`). `feature-workspace` executes each `place` or `move` as exactly one `entity.place` or `entity.move`; dragging produces none (F1.7).                                                                                                                                                                                                                                                                                       |
| **Ghost**                       | The translucent placement preview of the prop being placed or moved, at the snapped position. Renderer-local view state: not pickable, never in the world, and hidden when the cursor is on no valid snap.                                                                                                                                                                                                                                                                                                         |
| **HUD**                         | Heads-up display over the viewport: interaction mode, selection summary and the assisted badge.                                                                                                                                                                                                                                                                                                                                                                                                                    |
| **Input action**                | A rebindable, viewport-local input such as `input.moveForward`, `input.selectNext` or `input.commitPlacement`, keyed by physical key code and declared in `INPUT_ACTIONS` (`@controls/commands`). Handled by the renderer and never a Command, so per-frame input never enters the replay log (ADR 0006). Switching mode and focusing became Commands (`view.mode`, `view.focus`) in F1.7.                                                                                                                         |
| **Interaction mode**            | Walk (first-person), Work (focused orbit/pan with a cursor) or Editor (a 2D editor docked beside the viewport). Plan §4.9.                                                                                                                                                                                                                                                                                                                                                                                         |
| **Key chord**                   | Modifiers plus one key, written `Mod+Shift+Z`. `Mod` is Ctrl, or Cmd on macOS. The canonical form (`normaliseChord`) is what settings store and key presses resolve to (ADR 0006, "Keybindings").                                                                                                                                                                                                                                                                                                                  |
| **Keybinding**                  | A chord bound to a command (with fixed arguments, or arguments from context keys) or an input action, under a **binding id** (`edit.undo`, `toolbelt.select.slot3`, `view.mode.walk`, `entity.delete.selection`, `input.moveForward`). Defaults come from `CommandDef.keybinding`, `CommandDef.bindings` and `INPUT_ACTIONS`; player overrides live in settings `controls.keybindings`. Two bindings on one chord whose `when`s are not provably disjoint are a **conflict**, shown in the Key bindings dialog.    |
| **Device control**              | Something the player operates on a device (a switch's `closed`, later a supply's setpoint or a breaker's handle), declared in its catalogue entry as a toggle, setpoint or selector over one of its commanded state keys, and set with `device.operate`.                                                                                                                                                                                                                                                           |
| **Device state bag**            | One of an entity's two records of named device values (world v2): `state`, written only by commands (a switch's `closed`), and `sim`, written only by the simulator (a battery's `stateOfCharge`). Which keys a device has comes from its model kind (`MODEL_KINDS`), checked when a save loads.                                                                                                                                                                                                                   |
| **Last-played save**            | `settings.saves.lastPlayed` (settings v2): the save-directory entry, a manual save by name or an autosave slot, that holds the game the player was last in. Set when a game is loaded from or written to the save directory; `null` after opening a file from elsewhere until autosave copies it in. Continue tries it first. [ADR 0009](decisions/0009-save-io-boundary.md#continue-and-the-last-played-save).                                                                                                    |
| **Level**                       | A world document in `content/levels/` (F1.9) that new games start from: fixtures, optionally starting entities, and default seed and difficulty. New sandbox loads the workshop.                                                                                                                                                                                                                                                                                                                                   |
| **Main menu**                   | The start screen (New sandbox, Continue, Load, Settings, About, Quit; Resume and Save game while a game runs), drawn over the live 3D viewport. Escape in the workspace returns to it.                                                                                                                                                                                                                                                                                                                             |
| **Model kind**                  | The electrical model a catalogue entry uses (`battery`, `switch.spst`, `lamp.incandescent`, `lead`), declared in `MODEL_KINDS` (`@controls/catalog`): its parameters, its terminals and every state key with its owner (commanded or sim), schema and initial value. A new kind needs no `schemaVersion` bump; changing an existing kind's keys does.                                                                                                                                                              |
| **Migration chain**             | The pure `n → n+1` steps that upgrade any older document to the current `schemaVersion`. Total: every known version reaches the current one.                                                                                                                                                                                                                                                                                                                                                                       |
| **New-game dialog**             | What New sandbox opens (F1.9): the level, a fresh random seed (drawn by the UI, never by domain code) or one you type (0–4294967295), and Start. The same seed on the same level gives the same starting world.                                                                                                                                                                                                                                                                                                    |
| **OPFS**                        | Origin-private file system (`navigator.storage.getDirectory()`): per-origin files invisible to the user. The web harness keeps its saves there; `createWritable()` commits on `close()`, the browser's equivalent of temp-and-rename (ADR 0009).                                                                                                                                                                                                                                                                   |
| **Print**                       | A schematic, wiring diagram or panel layout. A separate document that may be wrong.                                                                                                                                                                                                                                                                                                                                                                                                                                |
| **Realism charter**             | Plan §3: simulate what can be measured, abstract what can't, cite a `source` for every constant.                                                                                                                                                                                                                                                                                                                                                                                                                   |
| **Region profile**              | The bundle of voltages, frequency, sizing units, colours, symbols and rules for a code region. NEC only through 1.0.                                                                                                                                                                                                                                                                                                                                                                                               |
| **Replay log**                  | The ordered list of successfully executed commands (`seq`, `tick`, `id`, `args`), including undo, redo and view commands. Replaying it from its initial world through a fresh bus reproduces the session's world hash exactly.                                                                                                                                                                                                                                                                                     |
| **Reticle**                     | The screen-centre aim point: the walk-mode crosshair, and the ghost's aim whenever the mouse pointer isn't over the canvas, so placement works from the keyboard (Enter commits).                                                                                                                                                                                                                                                                                                                                  |
| **`schemaVersion`**             | Integer version of the save format, driving the migration chain.                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| **Save directory**              | `<userData>/saves/` on desktop (OPFS `saves/` in the web harness): manual saves as `<name>.ctrl`, autosaves under `autosave/`. Owned by main; the renderer never sees its path (ADR 0009).                                                                                                                                                                                                                                                                                                                         |
| **Save handle**                 | The opaque token (22 base64url characters, 128 random bits) the renderer gets for a save instead of a path. Main maps it to a location for the window it was issued to; Open gives read-only handles, Save As write-only ones (ADR 0009).                                                                                                                                                                                                                                                                          |
| **Save name**                   | The name of a manual save, chosen in the Save game dialog (1–64 letters, digits, spaces and a few punctuation marks; `SaveNameSchema`). A game saved or loaded under a name keeps it, so Mod+S saves over it without asking.                                                                                                                                                                                                                                                                                       |
| **Scripting API**               | `@controls/scripting-api`: the typed `Game` object (`exec`, `world()`, `hash()`, `on()`, `replayLog()`) over the one command registry. `sim-cli` scripts drive it and the UI's `Session` wraps it, so both run identical code. `probe` (P2) and `tag` (P10) are reserved.                                                                                                                                                                                                                                          |
| **Selection**                   | The object the player has picked in the viewport (`selection.kind` is its kind). Renderer/UI state, not world state: never saved or logged.                                                                                                                                                                                                                                                                                                                                                                        |
| **Settings document**           | The player's preferences (graphics, audio, controls, units, default difficulty, region, theme, workspace layout). Separate from saves, with its own `settingsVersion` (F1.8a).                                                                                                                                                                                                                                                                                                                                     |
| **`settingsVersion`**           | Integer version of the settings document, independent of the save's `schemaVersion`.                                                                                                                                                                                                                                                                                                                                                                                                                               |
| **Snap target**                 | A surface placement can snap to: a DIN rail (17.5 mm DIN 43880 modules), a backplate grid (5 mm), a stud wall (16 in centres) or a bench top (10 mm, F1.9). The maths lives in `@controls/world-model` (`snap/`), takes and returns integer mm, and returns the footprint's lower-left anchor, which becomes the entity's `positionMm`. A world's targets come from its fixtures (`worldSnapTargets`). `snapToBest` picks the most specific target under the cursor (rail, then plate, then wall, then bench top). |
| **Stream key**                  | The stable label (`command:<seq>`, `entity:<id>`) mixed with the world seed to derive an independent sfc32 random stream, so no generator state is ever saved (ADR 0006, ADR 0007).                                                                                                                                                                                                                                                                                                                                |
| **Tool belt**                   | Nine slots, each holding a placeable prop in P1 (settings `toolBelt.slots`). Keys 1–9 run `toolbelt.select {slot}`, a view command; the active slot is UI state, shown in the HUD and published as the `toolbelt.slot` context key. The viewport places the active slot's prop (F1.7); Escape puts the tool away without a command.                                                                                                                                                                                |
| **Unsaved changes**             | A game the save directory doesn't hold as it is: its world hash differs from the one it was last saved to or loaded from the directory with, or started with (per session), or it was opened from a file outside the directory. View commands, an undone change and an untouched New sandbox aren't unsaved changes; Save As to a file doesn't clear them. Only a game with unsaved changes is autosaved (F1.8b).                                                                                                  |
| **Undo stack**                  | The apply/invert pairs of undoable commands, newest on top. `edit.undo` moves the top change to the redo stack; any new world change clears redo. Never saved: a loaded game starts with an empty history.                                                                                                                                                                                                                                                                                                         |
| **View command**                | A command that never changes the world or its hash (`view.resetLayout`, `toolbelt.select`, `view.mode`, `view.focus`, `palette.open`). Usually logged (`view.mode` and `view.focus` are: they change what the player sees); UI chrome such as `palette.open` is `logged: false` and never enters the replay log (an **unlogged command**). Declared in domain code so headless replay knows it; the UI applies its effect when the session reports it ran.                                                         |
| **Walk mode**                   | First-person camera: WASD plus mouse look with pointer lock (Esc releases it), clamped to the room at eye height. Entered with `view.mode walk` (V).                                                                                                                                                                                                                                                                                                                                                               |
| **Web harness**                 | The browser build of `apps/game` (`pnpm start:web`) using `@controls/platform-web`. For development and Playwright, not a shipped product.                                                                                                                                                                                                                                                                                                                                                                         |
| **Work mode**                   | Focused camera: orbit and pan with limits around a backplate, rail, wall or bench (`view.focus --target <id>`, F), with a pointer for picking, placement and drag-to-move.                                                                                                                                                                                                                                                                                                                                         |
| **Workshop**                    | The P1 sandbox level (`content/levels/workshop.json`, F1.9): an open 2×4 stud wall at 16 in centres, a plywood backboard with a 600 × 800 mm backplate and two TS35 DIN rails, and a workbench, on a 5 × 3.7 m floor.                                                                                                                                                                                                                                                                                              |
| **World document**              | The persistent, serialisable game state (physical model, prints, PLC and HMI documents).                                                                                                                                                                                                                                                                                                                                                                                                                           |
| **World hash**                  | `world.hash`: SHA-256 (pure TypeScript, from FIPS 180-4) of the canonical JSON (sorted keys, normalised `-0`) of the world document, as lower-case hex. The same commands from any surface give the same hash, in Node and Chromium alike (ADR 0007).                                                                                                                                                                                                                                                              |

## Workspace and tooling

| Term                      | Meaning                                                                                                                                                                                                                                       |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **ADR**                   | Architecture decision record, in [`docs/decisions/`](decisions/).                                                                                                                                                                             |
| **`app://`**              | The custom Electron protocol serving the Angular build. Used instead of `file://` so it can send COOP/COEP and CSP headers.                                                                                                                   |
| **CDP attach**            | How `apps/desktop-e2e` tests a packaged build: it starts the binary with `--remote-debugging-port` and connects over the Chrome DevTools Protocol, because the Fuses block Playwright's `_electron`. Selected with `CONTROLS_E2E_EXECUTABLE`. |
| **COOP / COEP**           | Cross-Origin-Opener-Policy and Cross-Origin-Embedder-Policy headers. Together they make a page `crossOriginIsolated`.                                                                                                                         |
| **`crossOriginIsolated`** | A browser flag that must be true for `SharedArrayBuffer` to exist.                                                                                                                                                                            |
| **DoD**                   | Definition of Done: the checklist every feature PR meets (plan §9.1, [`CLAUDE.md`](../CLAUDE.md)).                                                                                                                                            |
| **electron-builder**      | Packages the app into installers (NSIS, dmg/zip, AppImage/deb/rpm) and writes `latest*.yml` update metadata.                                                                                                                                  |
| **electron-updater**      | Reads `latest*.yml` from GitHub Releases and applies updates.                                                                                                                                                                                 |
| **Fuses**                 | Electron build-time switches (`@electron/fuses`). Controls disables RunAsNode, `NODE_OPTIONS` and the Node CLI inspect flags, and enables cookie encryption, embedded ASAR integrity and OnlyLoadAppFromAsar.                                 |
| **Module boundaries**     | Nx lint rule `@nx/enforce-module-boundaries` checking imports against project tags (`type:domain` etc.).                                                                                                                                      |
| **`pnpm verify`**         | The one command that runs exactly what CI runs (CI then also runs the e2e suites).                                                                                                                                                            |
| **Preload entry**         | `@controls/ipc-contract/preload`: the narrow import for the sandboxed preload, with channel names and the bridge type only (no Zod).                                                                                                          |
| **SAB**                   | `SharedArrayBuffer`: memory shared between the renderer and workers; used for sim snapshots (P2).                                                                                                                                             |
| **`sim-cli`**             | `apps/sim-cli` (`scope:headless`): runs the game headless in plain Node. `pnpm sim run <script>` (a TypeScript module or a console-line file), `pnpm sim replay <log>` and `pnpm sim hash <world>` print `world.hash`.                        |
| **Smoke test**            | `apps/desktop-e2e`: launches the real Electron app and checks `app://`, the version, cross-origin isolation, the CSP, the sandbox and that the viewport starts.                                                                               |
| **Zoneless**              | Angular without zone.js. Change detection runs only when signals change.                                                                                                                                                                      |
