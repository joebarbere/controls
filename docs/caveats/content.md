# Content caveats

**Load this when:** adding or changing anything in `content/` (devices, tables, from P3 conductors, cables, tools, accessories, and from P4 the inspector rule sets in `content/rules/`) or the catalogue format in `libs/domain/catalog` (`DeviceDefinition`, the families, tables, registries, the gauge table, source coverage, the region's colour rules). Decisions: [ADR 0016](../decisions/0016-catalogue-format-v2.md) (catalogue v2), [ADR 0020](../decisions/0020-catalogue-format-v3.md) (catalogue v3: roles, contacts, outlets and plugs, rule sets). Workflow: [authoring guide](../guides/authoring-content.md). Save-side rules for the catalogue: [save-format caveats](save-format.md#the-device-catalogue-p2-kickoff-catalogue-v1).

- **`terminals` in `covers` is only the layout.** Every other path covers its descendants (`jacket` covers `jacket.widthMm`), but the bare `terminals` path never covers a termination spec. That is deliberate: P2's layout sources are game-design, and a method's torque must not inherit that silently. Cover methods with `terminals.<id>.methods.<method>[.<field>]` (or `terminals.*.…`).
- **A device's mount declarations are `fits.<type>`, an enclosure's mounts are `mounts.<id>`.** Both live on a device entry (`mounts[]` and `enclosure.mounts[]`), so their coverage paths differ.
- **AWG is an integer designation, and smaller means thicker.** 1/0 = 0, 2/0 = −1, 3/0 = −2, 4/0 = −3; `awgRange.smallest` is the thinnest conductor, so `smallest ≥ largest` numerically. Never compare areas: they are rounded, and computing them needs a fractional power the D6 lint forbids in simulator code.
- **The gauge table is code, not content** (`AWG_GAUGES` in `gauge.ts`). Its areas are the AWG formula rounded to six significant figures; `gauge.spec.ts` recomputes them. The test lead's `conductorAreaM2` is the 18 AWG row to 1e-5.
- **Insulation thickness is per conductor entry**, never a column of the insulation table: a size-to-thickness column would mirror UL 83 and the NEC's Chapter 9 tables (pre-audit). Diameters are derived per entry.
- **Aluminium building wire is the AA-8000-series alloy at 61.0 % IACS** (`materials` row `aluminiumAa8000`), not "EC-grade". Don't call it EC anywhere.
- **The linear-α clamp is 200 °C for copper (NBS Handbook 100) and assumed for aluminium** (game-design, unverified). The test lead's doc comment still says the linear model holds to about 150 °C; the materials table is the reference.
- **The XLPE thermal conductivity (0.29 W/(m·K)) is unverified** and labelled game-design (its citation starts `game-design: unverified`); replace it with a verified figure as a new insulation table version.
- **A shipped document keeps its values; `shipped.spec.ts` checks it.** `libs/domain/catalog/fixtures/shipped/<release>.json` freezes what each release shipped (written once in the release commit, never regenerated); every shipped entry (devices, tools, cables, accessories) and table version must still resolve and, with fields the release's own format lacked and prose (`title`, citations) masked, deep-equal what shipped, and every shipped source keeps its id, kind and covers. A catalogue-2 or later list must carry `tools`, `cables` and `accessories` (saves pin cables and accessories by ref); a catalogue-1 list (0.3.0) holds none.
- **Every release in `CHANGELOG.md` from 0.3.0 needs its frozen list, and nothing else may have one.** The required set is the changelog's dated `## [x.y.z] - YYYY-MM-DD` headings (in the repo, so offline; CI's shallow checkout has no tags), so 0.4.0 is required from the release commit that rolls `[Unreleased]`, never before. In that commit run `pnpm catalog:freeze` (`tools/freeze-shipped-catalogue.mjs`: every `content/` family in file-name order, `CATALOG_VERSION` from `builtin.ts`, Prettier-formatted; `--stdout` previews). It refuses a version without a dated section and one that already has a list. Never create a list for an unreleased version: it would freeze provisional content. The catalogue test reads `CHANGELOG.md`, so it is in the `catalog:test` Nx inputs (`libs/domain/catalog/project.json`).
- **Colour ids are append-only, display values aren't.** `parseCatalog` refuses a colour table version that drops an id of the version before. The `srgb` values are display only and never in any check, so they may change in a new table version.
- **`bare` is a colour id, valid only on an uninsulated conductor**, and an uninsulated conductor is made in `bare` only (both load-checked).
- **Region colour rules are rules, not products.** `NEC_REGION.conductorColours` says what P4's inspector accepts; it never decides what a conductor entry is made in (`conductor.colours`) and is never in the load check. Ungrounded colours are labelled **convention**; only 200.6, 200.7, 250.119 and 110.15 are code. Cite NFPA 70-2023 (the 2026 numbering wasn't checked).
- **The utility service's screw terminals are a stand-in** (D12): the split-phase entry stands in for P4's load centre, so its `l1`, `l2` and `n` take one 14–10 AWG conductor with the breaker class's values, labelled game-design. It has no EGC terminal. _Decided in the acceptance PR (no content change):_ the lamp circuit's bare EGC lands on the panel's ground block (`tb.quennick-pe4`) and is spliced in the junction box, but stays folded back at the lamp box (the keyless holder has no grounding terminal), and the ground block isn't bonded to the stand-in, which has nothing to bond it to. P3 has no grounding rules and an EGC carries no current in any P3 circuit, so the stand-in gains no ground terminal: adding one would change a shipped entry (catalogue 1, `shipped.spec.ts`) for no simulated effect. P4's service and load centre bond it.
- **The breaker's DIN width is its base's 40 mm** (game-design), not a real DIN breaker's one 18 mm module per pole: resizing the base would be a new entry version, which a future DIN breaker entry may take.
- **The breaker's line terminal is a stand-in.** Its terminal values follow the panelboard (plug-on, bolt-on) branch-breaker class, whose line side is a bus stab, not a wire screw; so only the load screw cites that class, and the line screw is game-design, standing in for the bus until P4's panel. It does not follow the DIN-rail (UL 489 box-terminal) class.
- **Aluminium building wire starts at 12 AWG** (NFPA 70-2023 Art. 310.3(A), by number): author no 14 AWG aluminium conductor (F3.1).
- **NM-B's 90 °C is its conductors' rating.** The `nmbJacket` row carries the cable's rating; NM-B's ampacity is limited to the 60 °C rating by Art. 334.80 (by number), so derived ampacity (D6) never uses 90 °C for NM-B.
- **`catalogVersion` 2 changed which fixtures verify.** `engineCompatible` compares the catalogue by equality, so every catalogue-1 save (all of 0.3.0's, and the `-engine-6.ctrl` fixtures) loads as `engine-changed`. Fixtures written under catalogue 2 are `<scenario>-engine-N-catalog-C.ctrl` (`apps/sim-cli/src/testing/fixtures.ts`); bumping the catalogue again means writing the next set, never regenerating these.
- **The lead kind's ten sim keys exist before any save holds them.** World v2 connections carry no bags, so between this PR and world v3 the keys are declared and exported (`connection-state.lead.schema.json`) but unused; world v3's migration gives migrated leads the kind's initial bag as a frozen constant in `from-v2.ts` (ADR 0015), which must equal `initialBags(MODEL_KINDS.lead).sim`.
- **Box trade designations are outside sizes** (`3 × 2 × 2-1/2`, `4 in square`, `4 in round`; electrical-realism-reviewer, 2026-11-12): `sizeMm` is the designation and the inside is it less the drawn walls (2 mm steel, 3 mm PVC). The boxes' size sources stay `game-design` (unverified against a specific drawing); the panel's class and the 2-gang box's gang spacing are `real-world` (product class, read 2026-11-12).
- **A two-gang (or any) device box must be tall enough inside for a wiring device's 3-9/32 in (83.3 mm) mounting-screw spacing**; the 2-gang box is 86 mm inside, and its two 46 mm gangs (1-13/16 in, NEMA WD 6 by number) are centred in its width.
- **`interiorVolumeMm3` is the geometric volume of the inside dimensions, never a marked volume and never a code table** (the P3 source pre-audit): a plain rectangular volume (the round box: π r² h, rounded to a whole mm³). It is **above** the class's marked volume (1-gang about +2.4 %, 4 in square +6.1 %, 2-gang +8 to 15 %, 4 in round +17.5 % for its tapered walls) and **must not be used unchanged as the box-fill allowance**. Don't write a steel box's marked volume into content either: those numbers coincide with the code table's. **P4 open question:** a separate marked-volume field sourced from manufacturer markings, or a stated rule. `enclosures.spec.ts` holds the hand calculations.
- **The P2 breaker's 40 mm base is about twice a real single-pole DIN breaker** (one 17.5 to 18 mm module); P4's panel work may add a one-module entry version.
- **Entry positions are on the outside wall face, and `axis` points in** (a top-wall entry is at y = height with axis `-y`). The renderer centres each entry's disc or tab half a wall inward. A clamp or pryout has no trade size and `internalClamp: true`; a knockout or drill site has a trade size and no clamp (`enclosures.spec.ts`).
- **A box's yoke origin is its inside back-lower-left corner** (the gang), facing out (+z): a wiring device fills the gang from the back wall. P4's devices are sized to that, or a new box version moves the mount.
- **The enclosure kinds have no terminals** (`enclosure.box`, `enclosure.panel`; their netlist model is empty). A box's ground screw (and a panel's ground bar) arrives with P4's grounding; adding a terminal to a kind means every entry of the kind gains it.
- **Test catalogues need the v2 fields too.** Every terminal needs `methods` (`[]` for a clip) and every device `mounts`, `enclosure` and `conductor`; the helpers in `sim-core/src/testing/` and the specs show the minimal shape.
- **A conductor entry stores only product data and its lay factor.** Everything electrical comes from its gauge (`AWG_GAUGES`) and pinned rows; `model.params` is `{ layFactor }` (1 solid, 1.02 stranded, `conductors.spec.ts` checks the pairing), and the cut length is the world's. Resistance, diameter and ampacity are derived (`conductorPhysics`, `conductorResistanceOhm`, `derivedAmpacityA`), never stored.
- **The jacket layer is its own thickness.** `conductor.jacketThicknessMm` (the nylon on THHN) is non-null exactly when the pinned insulation row has a jacket conductivity (load-checked), and the outer radius may be at most 8 × the conductor's (`MAX_INSULATION_RADIUS_RATIO`, the range `lnRatio` is pinned over).
- **Specification sheets with ampacity columns are not sources.** Several makers' aluminium XHHW-2 sheets reprint the NEC ampacity table beside their construction data; that makes the whole sheet an NEC table for us (pre-audit). The XHHW-2 entries cite a datasheet with no ampacity column; check every new sheet for one before reading values from it, and keep makers' names out of `content/` (the citations describe the sheet instead).
- **An id must never be a prefix of another's id before a `-`.** `builtin.spec.ts` checks that the files sort as the ids do; `conductor.x-al-4` sorts before `conductor.x-al-4-0` as an id but after it as a file name (`-` sorts before `.`). Give such sizes a suffix (`-al-4-compact`, `-al-4-0-compact`).
- **Colours are what the sheet lists, not what the code allows.** THHN lists the eleven colour ids its sheet names (its tan has no id; stripes are left out), MTW's palette is game-design (the sheets read don't list colours), and the aluminium XHHW-2 is black only. A conductor's colours never come from `NEC_REGION.conductorColours`.
- **MTW 18 AWG is partly game-design.** The MTW sheet read lists 16–10 AWG; 18 AWG's 30 mil wall and 16 strands are assumed (its citation says so). Replace with a read figure as an entry change before v0.4.0 ships, or as a new entry version after.
- **Test catalogues built from the built-in devices need the tables too.** Since the conductor entries pin table rows, `catalogOrThrow(v, [...BUILTIN_CATALOG.devices, …])` fails; pass `{ devices: [...], tables: BUILTIN_CATALOG.tables }` (as `sim-core`'s `TEST_CATALOG` and `ENGINE_TEST_CATALOG` now do).
- **Tool hole and die ids are save format per tool entry version** (a termination records them). Stripper holes are `sol<awg>` and `str<awg>`, one per marking: each physical hole carries a solid size and the stranded size of the next even size, two AWG numbers smaller, because a 7-strand concentric conductor of equal area is 3/√7 ≈ 1.134 × the solid diameter (stranded 12 AWG ≈ 2.33 mm, between solid 11 at 2.30 and solid 10 at 2.59 mm; NBS Handbook 100 formula, recomputed in `tools.spec.ts`). The crimper's dies are `red`, `blue`, `yellow`. `tools.spec.ts` pins them: renaming or removing one is a new entry version.
- **`nickBase` (`termination/resolve.ts`) treats `str14` and `sol12` as different holes**, although on the tool they are the same physical hole, and it gives a solid 14 AWG conductor stripped in `str14` a 5 % nick. That is an abstraction of the per-marking hole model, left for F3.3 part 1 (`sim-engine-engineer`, ADR 0018) to keep or change.
- **Jacket stripping is its own tool.** The general strippers (`tool.veltmark-ws-1018`) can't `stripJacket`; the NM cable stripper (`tool.veltmark-ws-nm12`: 12–14 AWG solid, 14–16 AWG stranded, jacket slots for 12/2 and 14/2) can.
- **Which tool values are verified** (`real-world`, read by `electrical-realism-reviewer`, 2026-11-12): the general strippers' hole pattern, the NM stripper class, both torque screwdrivers' ±6 % (ISO 6789-1:2017 Type II Class D, from the lowest marked value to the maximum; the old "20 % to 100 %" band was the superseded 2003 edition) and their ranges, the insulated-terminal colour code (red is 22–16 at some makers), the screwdriver's tip forms and the nut driver's #10 hex-washer fit (its ASME B18.6.3 number unverified). Still `game-design`: the cutters' 8 AWG cap (unverified class figures), every capability's size limit, the torque drivers' bit set, and all terminal screw drives (the DIN supply's slotted + Pozidriv unverified). No UL 486A-B torque table anywhere: a terminal's torque is its device's marking.
- **Drive types are checked, sizes aren't** (`DRIVE_TYPES`, ADR 0016 amendment): a tool's `drives` must share a type with the screw's (`wrong-drive`), so a nut driver never lands a terminal screw and `suggestTermination` never picks it. A Phillips #1 tip on a #2 screw isn't modelled (game-design).
- **Every marked torque must be reachable by a torque driver** (`tools.spec.ts`): the 0.3–1.2 N·m driver covers the DIN supply's 0.5 N·m, the 1–5 N·m one the breaker's 4 N·m. A new device whose marking falls outside both needs another driver entry.
- **The torque draw's uniform shape is game-design** (`resolveTermination`): ISO 6789-1 gives only a maximum permissible deviation, not a distribution.
- **Brands for tools:** Veltmark (hand tools), Calderyn (torque tools), Penmarrow (label printers); see the authoring guide's brand table.
- **NM-B's conductors are their own entries, not the THHN ones.** The Sorrelby NM conductors pin the same `thhnThwn2` row and walls as the Tallowmere THHN of their size (`cables.spec.ts` checks the walls match), but NM-B's 8 and 6 AWG are 7-strand where THHN is 19, and they come in black, white and red only. Change one, check the other.
- **The 30 m 14/2 golden reads the NM conductor.** `conductor.sorrelby-nm-14-solid` derives exactly the plan's 0.248565 Ω per 30 m; the voltage-drop acceptance (`apps/sim-cli/src/voltage-drop.spec.ts`) will pin it. A changed 14 AWG wall doesn't move it, a changed material or lay factor does.
- **NM-B sheets with ampacity columns are the norm.** Most makers' NM-B sheets reprint the NEC 60 °C column; the one cited (a 2019 sheet with no ampacity column) gives construction, EGC sizes, strand counts, jacket colours and outer sizes but no jacket wall, so the 30 mil wall is game-design. The jacket colours by size (white 14, yellow 12, orange 10, black 8 and 6) are shared convention; one maker's distinct three-conductor colours are not used.
- **Cable outer sizes are product data, checked against geometry.** Flat sizes are height × width, round ones the diameter in both. The sheet's sizes include paper wraps the model doesn't carry, so they sit 3–19 % above the conductors' geometric minimum (`cables.spec.ts` bounds it at 20 %).
- **The cable geometry check takes stranded conductors at their solid diameter** (`cables.spec.ts`, the same abstraction as `conductorPhysics`). With a real 7-strand outer diameter (3/√7 × d, 4.666 mm at 6 AWG) the 6/3 minimum with the 30 mil jacket is 15.41 mm, above the sheet's 14.605 mm: the game-design 30 mil wall is likely too thick for the large round cables (the sheet's real walls there are thinner, or the conductors nest closer). If conductor entries ever move to real stranded diameters, that test fails for 8/3 and 6/3 until the jacket wall is revisited (realism review O2, 2026-11-12).
- **The bare 10 AWG EGC of 8/3 and 6/3 is solid by assumption** (game-design): the sheet gives its size, not its stranding.
- **Ferrules list a die no tool carries yet.** Ferrule `dies` is `["square"]` for a self-adjusting square-profile ferrule crimper that isn't in `content/tools/` (the F3.4 part 1 crimper is for insulated terminals: dies `red`, `blue`, `yellow`). Until one is added, a ferrule crimped with the CR-2210 is an under-crimp. `accessories.spec.ts` checks the lug dies against the crimper once the crimper is in the catalogue.
- **Lug barrel lengths are an interpretation.** The terminal sheet read gives a 0.394 in (red, blue) and 0.512 in (yellow) sleeve dimension without naming it in its drawing; the entries take it as the barrel length (game-design).
- **Wire nuts are devices, not accessories** (ADR 0018 §4.4): a `splice.twistOn` device whose terminal's `twistOn` method carries `combination` bounds in integer `areaUm2`. Both the kind and the fields are F3.3 part 1's; author the wire nuts there, from public packaging data under a fictional brand, never a reproduced chart.
- **Every termination method spec carries ADR 0018 §8's clamp fields** (`clampType`, `clampDepthMm`, `contactOhm`, `heatPathWPerK`, `hotSpotHeatCapacityJPerK`, `combination`), each with a source. `clampType` must be one the method allows (`screw`: `bindingScrew`, `pressurePlate` or `boxLug`; the others one each); `clampDepthMm` is at most the nominal strip length (author it at most nominal − tolerance, so every in-tolerance strip seats fully); `combination` is non-null exactly for `twistOn`, its `maxConductors` equals the method's, its AWG range lies inside the method's, and its `totalAreaUm2.min` is at most `minConductors` × the thinnest size's `areaUm2` (the minimum total is only checked once a splice holds `minConductors`, so a higher minimum would make refusals depend on landing order). They count as electrical after v0.4.0.
- **Only a binding screw splays bare strands.** Choosing `clampType` changes physics: a bare stranded conductor under a `bindingScrew` seats like half torque (1.41 R₀); a `pressurePlate`, `boxLug` or spring cage holds strands. Pick what the product really has.
- **The DIN supply's contact values are the screw class's, applied as game-design.** BSS 103 measured branch-circuit wiring-device terminals, not a supply's box clamps; its `contactOhm` and `heatPathWPerK` say so, and its clamp heat capacity (0.5 J/K) is a smaller physics estimate.
- **A twist-on splice is a `splice.twistOn` device, category `splice`,** with one `splice` terminal whose only method is `twistOn` (load-checked). Its combination bounds are integer µm² from `AWG_GAUGES[n].areaUm2`; write them as sums of rows (2 × 14 AWG = 4 161 820) so a reviewer can recompute them. Set `ratedConductors` equal to `maxConductors`: the contact model's count factor applies above `ratedConductors`, and a wire nut's rating is its combination.
- **The Corvelle wire-nut bounds are game-design.** They are a simplified envelope in the general class of UL 486C twist-on connectors; no maker's combination chart was read, and none may be reproduced. Replace them with bounds paraphrased from read packaging data (citations updated, same entry version while catalogue 2 is provisional) before v0.4.0 if a source is read.
- **`nickBase` now caps at the hole's geometric reach** (F3.3 part 1), 1 − (d_hole/d_cond)² with stranded diameters 3/√7 × solid. The stranded 14 AWG hole on a solid 14 AWG conductor (physically the solid 12 AWG hole) now nicks nothing, which resolves the earlier `str14`/`sol12` abstraction note for nicks; the two markings stay separate hole ids.
- **Ferrules list a die id that no crimper has yet.** Ferrule entries from another PR name a `square` die, but no ferrule crimper tool ships until the tools PR: until then a ferrule can't be crimped in the game, only in TEST-ONLY catalogues.
- **The catalogue refuses a thermal time constant under 1 s** (F3.6 part 1, ADR 0018 §3.4): a conductor whose C′ · R′_ins (or, bare, C′ / G′ at its linear-α top) is under `THERMAL_MIN_TAU_S`, a lead likewise from its six thermal params, and a terminal method whose `hotSpotHeatCapacityJPerK / (heatPathWPerK + the largest fin conductance of any conductor it admits)` is. A very thin insulation wall on a light conductor, or a tiny `hotSpotHeatCapacityJPerK`, fails it. The check runs only on an otherwise valid catalogue, and its bounds are conservative (the built-in entries pass with large margins: 14 AWG THHN 2.79 s, the lead 2.34 s).
- **A lead entry needs six thermal params** (D2, ADR 0018 §8, required `LeadParams` fields since F3.6 part 1): `linearAlphaMaxK`, `densityKgM3`, `specificHeatJPerKgK` (its metal, citing the materials table's sources), `insulationThicknessMm` (one wall; at most 8 × the conductor's radius over it, `lnRatio`'s range), `insulationConductivityWPerMK` and `surfaceEmissivity` (citing the insulation table's). The built-in lead gained them at entry version 1 while catalogue 2 is provisional; `shipped.spec.ts` ignores exactly these six on a catalogue-1 release's lead and nothing on a catalogue-2 release.
- **The D12 demo loads are stand-ins with real ratings** (`lamp.lumivane-120v-60w`, `heater.hearthvale-120v-1500w`): a lamp in a keyless holder and a bare heater element on bases, until P4's lampholders and devices. The lamp's holder screws are `bindingScrew` (a bare stranded conductor seats like half torque there, as on a real side-wired holder) and take one 14 or 12 AWG copper conductor; all their values are game-design. The heater's pressure-plate terminals are game-design throughout, their torque chosen inside the same range. Both torques are game-design anchored to one lampholder maker's published 14–18 lb·in (several of its products' pages). Neither terminal's contact or heat-path values were measured on such a product: they are the screw class's (BSS 103, the ADR 0018 §11 calibration).
- **The 120 V lamp's 2700 K is a 1928 figure.** Holladay (JOSA 1928) gives gas-filled 50 W and 75 W lamps 2685 K and 2735 K; 60 W interpolates to about 2705 K. Its 60 W row is a vacuum lamp at 2465 K, from an era when 60 W lamps were vacuum: don't use it. The lamp model is a vacuum lamp: gas loss is folded into the one linear conduction term (f = 0.05), an abstraction the entry's citation states. **Its cool-down likely errs slow** against a real gas-filled lamp, whose gas carries heat away faster than 5 % of rated power at the rated point implies as the filament cools: a re-strike within about 1 s of switch-off really draws somewhat less inrush than the model's (`electrical-realism-reviewer`, 2026-11-12). Holladay's Tables 3 and 5 (emissivity, gas-filled temperatures) were read by the content author and judged plausible by the reviewer, not independently verified.
- **A 1500 W heater on a 15 A circuit is the demo's choice, not a code-compliant one** (12.5 A continuous); P3 checks no branch-circuit sizing rules, and P4's inspector will. Its citation makes no code claim (the fixed-heater sizing article's number wasn't checked against NFPA 70-2023).
- **What F3.5 part 2 verified and what stays game-design** (electrical-realism-reviewer, 2026-11-12). `real-world` (makers' datasheets read that day): the EMT outside diameters, walls and 10 ft sticks; the 90° elbows' centreline radii (102, 114, 146 mm) and straight legs (64, 64, 76 mm); the duct sections (25 × 40, 40 × 60, 60 × 80 mm, 2 m) and the published slot patterns (narrow 4 / 6 mm, wide 8 / 12 mm, about 2 mm walls); the 4 mm² screw block's size (6.2 × 47.7 × 47.5 mm, drawn 6 × 48 × 47) and rating class (26–10 AWG, 9 mm strip, M3 at 0.6–0.8 N·m); the 2.5 mm² spring-cage block's size band and rating class. `game-design`: which section gets which slot pattern, the connector bodies (picked inside makers' ranges), the cage depths, the strip tolerances, the 1-rated / 2-fit rule, the terminal layout and entry points, the screw drives (unverified), the contact, heat-path and heat-capacity values (anchored to a terminal-block voltage-drop acceptance, standards cited by number only) and every default and minimum cut.
- **EMT dimensions cite ANSI C80.3 / UL 797 by number and makers' sheets, never a NEC Chapter 9 table** (its Table 4 has EMT inside areas, Table 2 minimum bend radii). The elbows' radii and legs are makers' standard 90° elbow product data; that a radius coincides with a code table's minimum is fine (like the outside diameters), as long as the citation is the maker's sheet and the standards by number, never the table.
- **A conduit part's body diameter is its tube's rounded up to an even whole mm** (18, 24, 30 for 17.93, 23.42, 29.54 mm), so its ends are whole millimetres; the drawn tube uses the published diameter. A stick's `sizeMm.widthMm` is the uncut 10 ft stick, a duct's the 2 m stock: the placed body is the cut `lengthMm`.
- **Terminal-block widths are rounded down** (6.2 → 6, 5.2 → 5 mm), so ten blocks take 60 mm, not 62. Their `crossMm` centres them on the rail (45 − ⌊height / 2⌋); `builtin.spec.ts` checks the rule.
- **Two conductors under a 4 mm² screw cage is an abstraction** (follow-up). The real class allows two conductors only of equal size and only up to 1.5 mm² (about 16 AWG); the game's `maxConductors: 2` lets two of any size up to 10 AWG land and shares the clamp force (ADR 0018 §4.3). Catalogue v3 adds the cap (`multiConductor`, ADR 0020): `tb.quennick-st4@2` takes two only of equal size up to 16 AWG, and `@1` keeps the abstraction for 0.4.0 saves (`supersededBy` `@2`). The ground block `tb.quennick-pe4@1` still has it (raised for the plan, not versioned in PR 6). `wire.land` enforces the cap from the commands PR.
- **The ground block is electrically a feed-through in P3.** Its foot doesn't bond to the rail until P4's grounding; it is its own kind (`terminalBlock.ground`) so P4 can add that without touching the feed-through entries.
- **Drill bits and hole saws are capped at 35.56 mm for boring studs** (F3.2 part 4, IRC R602.6 by number: 40 % of a 2×4's 88.9 mm depth for an exterior or bearing wall with single studs, which every P3 wall is taken to be; a non-bearing or doubled stud would take 60 %). A tool entry with a larger `boreDiameterMm` loads, but `checkTool(…, 'bore')` refuses it as `beyond-tool-capacity` for a stud bore and the snapper won't propose a bore with it. A bit over 1 in (25.4 mm) leaves less than 31.75 mm to the stud face at the 44.45 mm mid-depth and needs a nail plate (`boreNeedsNailPlate`, a warning): F3.4 part 2's drill entries include 3/4, 7/8 and 1 in (none needs a plate), 1-1/8 in (needs one) and, as the over-cap case, the 1-3/4 in hole saw.
- **A bit or hole saw is one tool entry per size** (ADR 0015: a bore waypoint's `tool` names the hole). The Corriden ids count sixteenths of an inch (`sa-12` is 3/4 in, `hs-22` is 1-3/8 in), so no id is a prefix of another before a `-`. Their `boreDiameterMm` is the nominal inch size × 25.4 exactly (19.05, 22.225, 25.4, 28.575, 34.925, 44.45), never a measured product diameter.
- **Wood bits can't open entries; hole saws do both.** A ship auger has `bore` only; a bi-metal hole saw has `bore` and `openEntry` (the class cuts steel and bores a 2×4 in one pass, both read on makers' pages). A `drillSite` opens by `openEntry` only, so a wood bit there is `wrong-tool`, not a size problem.
- **`KNOCKOUT_HOLES` descriptions name the trade size only** ("the hole of a 3/4 in conduit-size punch"): the source gives the hole in decimal inches, not a fractional nominal, so don't write one (review N3).
- **Knockout hole sizes are punch product data, not a code or UL table** (`KNOCKOUT_HOLES`: 0.885, 1.115, 1.362, 1.701, 1.951, 2.416 in for 1/2 to 2, one maker's standard round punch catalogue, read 2026-11-15; another maker's 1 in die page agrees). Cite punch catalogues, never UL 514A's knockout table. Values are stored in inches as published and converted by `knockoutHoleMm`.
- **The hole-saw fit tolerance (1/16 in) is game-design.** It is inclusive and compared in whole tenths of a micrometre (`holeFitsTradeSize`), so K ± 1.5875 mm fits and K ± 1.5885 mm doesn't on every size. It is chosen so each electrician's saw (7/8, 1-1/8, 1-3/8, 1-3/4 in) fits exactly one trade size (1/2, 3/4, 1, 1-1/4); `tools.spec.ts` checks that no saw fits two sizes. A new hole saw entry must keep that true or the check fails.
- **A tool that can `openEntry` declares its holes**: `punches` (a punch) or `boreDiameterMm` (a hole saw), never both (load-checked). A screwdriver opens knockouts by `drive`, so it needs neither.
- **The fish tape's 360° is game-design, anchored on a code rule by number.** The tape's `pull.maxBendDeg` equals the most bend an EMT run may have between pull points (NFPA 70-2023 Art. 358.26, cited by number), but it is the tape's reach, not a code check; P3 checks no conduit rule and no conduit fill (P4's inspector). Its 50 ft (15 240 mm) is product data.
- **A pull's run is measured, its bends counted** (`pullRun`): the length is the stored polyline from the first to the last conduit waypoint, except that where two consecutive conduit waypoints are exactly the two ports of one elbow (in world integer mm), the elbow's centreline replaces the chord: add `elbowArcExcessMm(L, R)` = (2L + πR/2) − (R + L)√2 from the elbow's own `legLengthMm` and `bendRadiusMm` (the chord alone under-measured by about 18 %: 1/2 in 288.2 vs 234.8 mm, 3/4 in 307.1 vs 251.7, 1 in 381.3 vs 314.0; electrical-realism review N1). Two waypoints on an elbow that aren't both its ports stay a chord. The bends are 90° per distinct elbow host. A future elbow of another angle needs a bend param on its kind (and `ELBOW_BEND_DEG` and the πR/2 term replaced by it).
- **Brands for the F3.4 part 2 tools:** Corriden (drill bits and hole saws); Veltmark makes the knockout punch set and the fish tape (`tool.veltmark-fr-1524`, model FR-1524: not FT-50, which is too close to real tapes' model numbers).
- **The bad-termination heater is a D12 test-bench load, not good practice** (`apps/sim-cli/scenarios/bad-termination.console`): two single THHN conductors run out of an open junction box to a 1500 W heater element, about 12.5 A continuous on a 15 A circuit. Single conductors leaving a box outside a cable or raceway, a fixed heater's share of a branch circuit and its continuous-load sizing are all things a real installation gets wrong here (NFPA 70 Art. 300.3(A), 210.23 and 424.4, by number only). It is there to put §7's current through the loose screw; P4's inspector should flag it.
- **A wire nut, the lamp's keyless holder and the heater have no mount, so nothing puts them inside a box** (the P3 acceptance scenarios): `entity.place` refuses any body inside an enclosure's except what is mounted in it (F3.5), so `lamp-circuit` places its nuts at the junction box's opening (touching its front face, as a splice is made before it is folded in) and the lamp on the lamp box's opening. A box-mounted lampholder or a splice mount is P4 content (with box fill); until then a scenario author places these on the opening.

## Catalogue v3 (P4 PR 6, [ADR 0020](../decisions/0020-catalogue-format-v3.md))

- **Terminal `role` and `side` are for the inspector only.** The compiler joins what is landed whatever a terminal is called, so a wrong role never changes a simulation; it only changes what the inspector says. Every shipped terminal has `role: null` and `side: null`.
- **`access` follows the methods, both ways:** `land` exactly when a terminal has methods. A methodless terminal is `clip` (a lead's clip fits) or `none` (a plug blade, a slot behind a face): only `none` makes `lead.connect` refuse (`inaccessible`, from the commands PR).
- **`fits.<type>` covers only a fit's layout, like `terminals`.** A `fits.e26` source never covers `fits.e26.contacts.shell.contactOhm`: cover each contact resistance with its own source (it is a measurement or game-design in its own right).
- **A device contact names its host contact (`host`), not just a terminal.** `host` must be one of the mount type's `hostContacts` (`MOUNT_TYPES`); the host's mount maps it to a host terminal, or, on a bus, `bus.legs[k mod 2]`. A contact on a host that doesn't offer it adds nothing (a yoke on a nonmetallic box), by design.
- **Bus legs alternate by row within a column**, from stab 0 (ADR 0019 deviation 6): spaces 1 and 2 are L1, 3 and 4 L2. A column counted the other way lists its `legs` the other way round; there is no "reversed" flag.
- **A lampholder isn't an enclosure.** Its `e26` socket is in `hostMounts`; `enclosure !== null` still means "an enclosure" to every reader (routes, entries, the renderer). Read offered mounts through `offeredMounts(device)`.
- **The single-mount anchor isn't read yet.** `alongMm` and a single mount's `crossMm` load, but `checkMount` and snapping read them from the commands PR; until then no entry may declare a non-zero one on a single mount (`builtin.spec.ts`).
- **`markedVolumeMm3` is the maker's marking, `interiorVolumeMm3` the drawn box.** Neither is a box-fill allowance, and no per-gauge allowance or fill percentage goes anywhere in `content/` (P4 Q1: fill is reported, not judged; the pre-audit holds those numbers are the code table however they are cited).
- **`material` is required on every enclosure.** The shipped boxes and panel gained theirs from their own product-class sources, as data only (no version change, masked for 0.4.0).
- **A two-blade 1-15P enters a 5-15R and a 5-20R** in `NEMA_CONFIGS` (ADR 0020 deviation 10, accepted by the realism review 2026-11-17); a plug's pins are always a subset of the receptacle's slots, so each pin meets a slot.
- **The 1-15P is modelled polarised.** Its two pins are `hot` and `neutral`, so it enters a 5-15R or 5-20R one way only. A real non-polarised 1-15P (two equal blades) goes in either way round, swapping hot and neutral; that is not modelled (the realism review, 2026-11-17, accepted the 1-15P rows on this basis).
- **`tb.quennick-pe4@1` still lets two conductors of any size under one clamp.** The 4 mm² ground block has the same two-of-any-size abstraction `tb.quennick-st4@1` had; only the feed-through block got a version 2 in PR 6 (the plan versions only it). A `pe4@2` with the same cap needs the plan first.
- **The st4 cap doesn't tell solid from stranded or twin ferrules.** `multiConductor` caps size and equal size only; a real class rule may differ for two stranded conductors or a twin ferrule, which the format can't say.
- **An entry with a plug fits no mount** (ADR 0019's relaxable rule): relaxing it later changes no old save.
- **Rule paraphrases are ours, short, and never the code's text** (at most 300 characters); an article is a number only (`ARTICLE_PATTERN` refuses `Art. 240.4` and `Table 310.16`). A rule the inspector can't check yet keeps `check: null`, and the seed `nec.v1.json` has only those until PR 20 adds check kinds.
- **Rule ids are append-only across a rule set's versions**, and a shipped rule-set version keeps every rule's article, severity and check (its prose may be corrected): a changed rule is a new rule-set version.
- **GFCI limit points are computed offline.** `NEC_REGION.protection.gfci.tripTimeLimit` stores t = (20 mA / I)^1.43 at eight points, rounded to four significant figures (each within 0.15 %), because sim code may not call `Math.pow` (D6); `catalog-v3.spec.ts` recomputes them.

## The service and plug-on breakers (P4 PR 14, F4.2 part 2)

- **A plug-on breaker is 25 mm per pole along its bus column, so a two-pole one is 50 mm.** `checkMount` compares widths along the column, so a two-pole breaker of one pitch's width would leave its second stab free for a one-pole breaker to share. "Breaker widths are at most the smallest step" (ADR 0019) is about a single pole.
- **Instantaneous bands are absolute amperes read from a curve, per rating, and the family is a composite.** 15 and 20 A keep the pre-audit's vetted 240–400 A (one maker's curve); 30, 40 and 50 A carry 300–950, 300–950 and 350–930 A, read for PR 14 from another maker's 30–40 A and 50–70 A curve sheets (300 dpi drawings, log-axis readings good to about ±15 %). Each band's top is where the bimetal law meets that rating's maximum-clearing curve (about 969, 953 and 935 A, rounded down), so no drawn pickup leaves a current the curve clears in one cycle to a 0.2 s bimetal; `plug-on-entries.spec.ts` holds the read curve points at 15, 20 and 25 ×. A second maker's 15–25 A sheet reads wider (about 225–860 A) than the vetted band; the vetted band stays, because the bolted-short scenario's margin is set against its 400 A top. Never scale a band by the rating.
- **The pole resistance and the stab jaw add up to the watts loss.** `contactResistanceOhm` is the pole and the busStab contact (0.1 mΩ) is the jaw, in series, so their sum is what the watts-loss anchors bound (2.0 W at 15 and 20 A, 3.7 W at 30 A, 4.0 W at 40 A, 4.5 W at 50 A). Don't put a published whole-pole figure on both.
- **A stab jaw is a `clip` terminal, never a wire terminal.** The breaker's line side reaches the bus through its mount contact; a probe or a bench lead may clip it, so the bench goldens can feed a breaker without a load centre.
- **The GFCI and AFCI pigtail is a landable terminal.** The factory pigtail is modelled as a terminal plus a short white conductor the player lands on the neutral bar (ADR 0019's review note), with the load-neutral terminal's class.
- **`hex` is a nut driver's head; a lug's Allen screw is `hexSocket`.** The meter base's 2 AWG–4/0 lugs take a hexagon-socket set screw at 31 N·m, reached by the 5–70 N·m click wrench with hex bits (`tool.calderyn-tw-70`, kind `torqueDriver`: drive and torque are what count). `tools.spec.ts` checks every marked torque has a torque tool whose range covers it **and** whose drives fit the screw. Drive ids live only in catalogue entries and tools, never in saves; the tool schema keeps its file name (`tool.v2.schema.json`) and gains the value under catalogue 3.
- **Stripping and cutting service-entrance sizes has no tool yet.** The strippers stop at 10 AWG and the diagonal cutters at 8 AWG, so a 2 AWG or 4/0 conductor can be placed but not cut or stripped with a catalogue tool; a cable cutter and a large-conductor stripper are carried in the plan.
- **The 15 and 20 A plug-on load terminals aren't aluminium-rated here.** The class takes two copper 14–10 AWG conductors or one aluminium 12–8 AWG; one method can't say both, so the aluminium option is left out (labelled in the entries).
- **The drop's neutral is at the line conductors' 1350 resistivity.** A real messenger is 6201 alloy, ACSR or aluminium; the service kind has one resistivity for its drop (labelled in the entry).
- **A spec sheet with an ampacity column may still be read for construction.** The 2 AWG aluminium entry's strand count and wall come from a sheet that also reprints an ampacity table; the column is not used and no value from it is stored. Say so in the source.
