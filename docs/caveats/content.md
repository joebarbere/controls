# Content caveats

**Load this when:** adding or changing anything in `content/` (devices, tables, and from P3 conductors, cables, tools, accessories) or the catalogue format in `libs/domain/catalog` (`DeviceDefinition`, the families, tables, registries, the gauge table, source coverage, the region's colour rules). Decision: [ADR 0016](../decisions/0016-catalogue-format-v2.md). Workflow: [authoring guide](../guides/authoring-content.md). Save-side rules for the catalogue: [save-format caveats](save-format.md#the-device-catalogue-p2-kickoff-catalogue-v1).

- **`terminals` in `covers` is only the layout.** Every other path covers its descendants (`jacket` covers `jacket.widthMm`), but the bare `terminals` path never covers a termination spec. That is deliberate: P2's layout sources are game-design, and a method's torque must not inherit that silently. Cover methods with `terminals.<id>.methods.<method>[.<field>]` (or `terminals.*.…`).
- **A device's mount declarations are `fits.<type>`, an enclosure's mounts are `mounts.<id>`.** Both live on a device entry (`mounts[]` and `enclosure.mounts[]`), so their coverage paths differ.
- **AWG is an integer designation, and smaller means thicker.** 1/0 = 0, 2/0 = −1, 3/0 = −2, 4/0 = −3; `awgRange.smallest` is the thinnest conductor, so `smallest ≥ largest` numerically. Never compare areas: they are rounded, and computing them needs a fractional power the D6 lint forbids in simulator code.
- **The gauge table is code, not content** (`AWG_GAUGES` in `gauge.ts`). Its areas are the AWG formula rounded to six significant figures; `gauge.spec.ts` recomputes them. The test lead's `conductorAreaM2` is the 18 AWG row to 1e-5.
- **Insulation thickness is per conductor entry**, never a column of the insulation table: a size-to-thickness column would mirror UL 83 and the NEC's Chapter 9 tables (pre-audit). Diameters are derived per entry.
- **Aluminium building wire is the AA-8000-series alloy at 61.0 % IACS** (`materials` row `aluminiumAa8000`), not "EC-grade". Don't call it EC anywhere.
- **The linear-α clamp is 200 °C for copper (NBS Handbook 100) and assumed for aluminium** (game-design, unverified). The test lead's doc comment still says the linear model holds to about 150 °C; the materials table is the reference.
- **The XLPE thermal conductivity (0.29 W/(m·K)) is unverified** and labelled game-design (its citation starts `game-design: unverified`); replace it with a verified figure as a new insulation table version.
- **A shipped document keeps its values; `shipped.spec.ts` checks it.** `libs/domain/catalog/fixtures/shipped/<release>.json` freezes what each release shipped (taken from its tag, never regenerated); every shipped entry must still resolve and, with fields a later format added and prose (`title`, citations) masked, deep-equal what shipped, and every shipped source keeps its id, kind and covers. A release appends its own file (0.4.0: its entries, table versions and colour ids).
- **Colour ids are append-only, display values aren't.** `parseCatalog` refuses a colour table version that drops an id of the version before. The `srgb` values are display only and never in any check, so they may change in a new table version.
- **`bare` is a colour id, valid only on an uninsulated conductor**, and an uninsulated conductor is made in `bare` only (both load-checked).
- **Region colour rules are rules, not products.** `NEC_REGION.conductorColours` says what P4's inspector accepts; it never decides what a conductor entry is made in (`conductor.colours`) and is never in the load check. Ungrounded colours are labelled **convention**; only 200.6, 200.7, 250.119 and 110.15 are code. Cite NFPA 70-2023 (the 2026 numbering wasn't checked).
- **The utility service's screw terminals are a stand-in** (D12): the split-phase entry stands in for P4's load centre, so its `l1`, `l2` and `n` take one 14–10 AWG conductor with the breaker class's values, labelled game-design. It has no EGC terminal; the demo's bare conductor needs somewhere to land (F3.1 part 2 / the acceptance PR decides).
- **The breaker's DIN width is its base's 40 mm** (game-design), not a real DIN breaker's one 18 mm module per pole: resizing the base would be a new entry version, which a future DIN breaker entry may take.
- **The breaker's line terminal is a stand-in.** Its terminal values follow the panelboard (plug-on, bolt-on) branch-breaker class, whose line side is a bus stab, not a wire screw; so only the load screw cites that class, and the line screw is game-design, standing in for the bus until P4's panel. It does not follow the DIN-rail (UL 489 box-terminal) class.
- **Aluminium building wire starts at 12 AWG** (NFPA 70-2023 Art. 310.3(A), by number): author no 14 AWG aluminium conductor (F3.1).
- **NM-B's 90 °C is its conductors' rating.** The `nmbJacket` row carries the cable's rating; NM-B's ampacity is limited to the 60 °C rating by Art. 334.80 (by number), so derived ampacity (D6) never uses 90 °C for NM-B.
- **`catalogVersion` 2 changed which fixtures verify.** `engineCompatible` compares the catalogue by equality, so every catalogue-1 save (all of 0.3.0's, and the `-engine-6.ctrl` fixtures) loads as `engine-changed`. Fixtures written under catalogue 2 are `<scenario>-engine-N-catalog-C.ctrl` (`apps/sim-cli/src/testing/fixtures.ts`); bumping the catalogue again means writing the next set, never regenerating these.
- **The lead kind's ten sim keys exist before any save holds them.** World v2 connections carry no bags, so between this PR and world v3 the keys are declared and exported (`connection-state.lead.schema.json`) but unused; world v3's migration gives migrated leads the kind's initial bag as a frozen constant in `from-v2.ts` (ADR 0015), which must equal `initialBags(MODEL_KINDS.lead).sim`.
- **Test catalogues need the v2 fields too.** Every terminal needs `methods` (`[]` for a clip) and every device `mounts`, `enclosure` and `conductor`; the helpers in `sim-core/src/testing/` and the specs show the minimal shape.
- **A conductor entry stores only product data and its lay factor.** Everything electrical comes from its gauge (`AWG_GAUGES`) and pinned rows; `model.params` is `{ layFactor }` (1 solid, 1.02 stranded, `conductors.spec.ts` checks the pairing), and the cut length is the world's. Resistance, diameter and ampacity are derived (`conductorPhysics`, `conductorResistanceOhm`, `derivedAmpacityA`), never stored.
- **The jacket layer is its own thickness.** `conductor.jacketThicknessMm` (the nylon on THHN) is non-null exactly when the pinned insulation row has a jacket conductivity (load-checked), and the outer radius may be at most 8 × the conductor's (`MAX_INSULATION_RADIUS_RATIO`, the range `lnRatio` is pinned over).
- **Specification sheets with ampacity columns are not sources.** Several makers' aluminium XHHW-2 sheets reprint the NEC ampacity table beside their construction data; that makes the whole sheet an NEC table for us (pre-audit). The XHHW-2 entries cite a datasheet with no ampacity column; check every new sheet for one before reading values from it, and keep makers' names out of `content/` (the citations describe the sheet instead).
- **An id must never be a prefix of another's id before a `-`.** `builtin.spec.ts` checks that the files sort as the ids do; `conductor.x-al-4` sorts before `conductor.x-al-4-0` as an id but after it as a file name (`-` sorts before `.`). Give such sizes a suffix (`-al-4-compact`, `-al-4-0-compact`).
- **Colours are what the sheet lists, not what the code allows.** THHN lists the eleven colour ids its sheet names (its tan has no id; stripes are left out), MTW's palette is game-design (the sheets read don't list colours), and the aluminium XHHW-2 is black only. A conductor's colours never come from `NEC_REGION.conductorColours`.
- **MTW 18 AWG is partly game-design.** The MTW sheet read lists 16–10 AWG; 18 AWG's 30 mil wall and 16 strands are assumed (its citation says so). Replace with a read figure as an entry change before v0.4.0 ships, or as a new entry version after.
- **Test catalogues built from the built-in devices need the tables too.** Since the conductor entries pin table rows, `catalogOrThrow(v, [...BUILTIN_CATALOG.devices, …])` fails; pass `{ devices: [...], tables: BUILTIN_CATALOG.tables }` (as `sim-core`'s `TEST_CATALOG` and `ENGINE_TEST_CATALOG` now do).
- **Tool hole and die ids are save format per tool entry version** (a termination records them). Stripper holes are `sol<awg>` and `str<awg>`, one per marking: each physical hole carries a solid size and the stranded size of the next even size, two AWG numbers smaller, because a 7-strand concentric conductor of equal area is 3/√7 ≈ 1.134 × the solid diameter (stranded 12 AWG ≈ 2.33 mm, between solid 11 at 2.30 and solid 10 at 2.59 mm; NBS Handbook 100 formula, recomputed in `tools.spec.ts`). The crimper's dies are `red`, `blue`, `yellow`. `tools.spec.ts` pins them: renaming or removing one is a new entry version.
- **`nickBase` (`termination/resolve.ts`) treats `str14` and `sol12` as different holes**, although on the tool they are the same physical hole, and it gives a solid 14 AWG conductor stripped in `str14` a 5 % nick. That is an abstraction of the per-marking hole model, left for F3.3 part 1 (`sim-engine-engineer`, ADR 0018) to keep or change.
- **Jacket stripping is its own tool.** The general strippers (`tool.veltmark-ws-1018`) can't `stripJacket`; the NM cable stripper (`tool.veltmark-ws-nm12`: 12–14 AWG solid, 14–16 AWG stranded, jacket slots for 12/2 and 14/2) can.
- **Which tool values are verified** (`real-world`, read by `electrical-realism-reviewer`, 2026-11-12): the general strippers' hole pattern, the NM stripper class, both torque screwdrivers' ±6 % (ISO 6789-1:2017 Type II Class D, from the lowest marked value to the maximum; the old "20 % to 100 %" band was the superseded 2003 edition) and their ranges, the insulated-terminal colour code (red is 22–16 at some makers), the screwdriver's tip forms and the nut driver's #10 hex-washer fit (its ASME B18.6.3 number unverified). Still `game-design`: the cutters' 8 AWG cap (unverified class figures), every capability's size limit, the torque drivers' bit set, and all terminal screw drives (the DIN supply's slotted + Pozidriv unverified). No UL 486A-B torque table anywhere: a terminal's torque is its device's marking.
- **Drive types are checked, sizes aren't** (`DRIVE_TYPES`, ADR 0016 amendment): a tool's `drives` must share a type with the screw's (`wrong-drive`), so a nut driver never lands a terminal screw and `suggestTermination` never picks it. A Phillips #1 tip on a #2 screw isn't modelled (game-design).
- **Every marked torque must be reachable by a torque driver** (`tools.spec.ts`): the 0.3–1.2 N·m driver covers the DIN supply's 0.5 N·m, the 1–5 N·m one the breaker's 4 N·m. A new device whose marking falls outside both needs another driver entry.
- **The torque draw's uniform shape is game-design** (`resolveTermination`): ISO 6789-1 gives only a maximum permissible deviation, not a distribution.
- **Brands for tools:** Veltmark (hand tools), Calderyn (torque tools), Penmarrow (label printers); see the authoring guide's brand table.
