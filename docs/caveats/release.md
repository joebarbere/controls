# Release caveats

**Load this when:** bumping the version, running `/release`, editing `tools/check-version-sync.mjs`, `apps/desktop/electron-builder.config.cjs` or `.github/workflows/release.yml`, touching electron-updater, or making signing decisions.

- **Releases are drafts built by CI from a `v*` tag on `main`.** Never upload locally built artifacts as the release. The user publishes the draft; agents never do.
- **Never push a tag or publish without explicit user confirmation in the current conversation.** `/release` stops and asks.
- **Version sources move in lock-step:** root `package.json` (the source of truth), `apps/desktop/package.json` (read by electron-builder), the generated `libs/domain/units/src/lib/version.ts` (`APP_VERSION`: the web-harness about box, later the save manifest; the Electron about box reads `app.getVersion()`, which comes from `apps/desktop/package.json`), `CHANGELOG.md`, the README badge/status and the `CLAUDE.md` status line. `pnpm version:sync` writes the two generated ones from the root. `node tools/check-version-sync.mjs` (part of `pnpm verify`) fails if either generated file disagrees, or if a non-`0.0.0` version has no `## [x.y.z]` CHANGELOG section. **It doesn't check the README badge or the `CLAUDE.md` status line**, so `version-keeper` has to update those by hand.
- **`pnpm verify` mirrors CI exactly, including `prettier --check`.** jansky-observe shipped an inert release because CI's format check wasn't in local verify. Run `pnpm verify` before tagging, not just the tests.
- **Builds are unsigned until a decision before P13.** macOS: Gatekeeper warns and **macOS auto-update does not work** (Squirrel.Mac requires a signed app). Windows: SmartScreen warns; NSIS auto-update works. Linux: AppImage auto-update works unsigned. Document the workarounds in the README, don't hide them.
- **Targets:** NSIS (Windows), dmg + zip universal (macOS; the zip is what electron-updater uses on macOS), AppImage + deb + rpm (Linux). deb/rpm don't auto-update; that's expected.
- **Check `latest.yml`, `latest-mac.yml` and `latest-linux.yml`** on every draft: they must exist, reference files present in the release, and carry the new version. A missing or wrong one silently breaks auto-update for that OS.
- **electron-updater is a no-op in dev** (`app.isPackaged === false`). Test updates only with a packaged build against a real (draft or prerelease) GitHub Release.
- **The packaged app has no `node_modules`.** `app.asar` holds only `main.cjs`, `preload.cjs`, `package.json` and `renderer/`; esbuild bundles every main-process dependency, electron-updater included (`main.cjs` requires only Node built-ins and `electron`). If a packaged build crashes on launch with "Cannot find module", a main-process dependency was left external in esbuild (see [electron caveats](electron.md)). Check with `node node_modules/.pnpm/@electron+asar@*/node_modules/@electron/asar/bin/asar.js list dist/release/linux-unpacked/resources/app.asar`.
- **`beforeBuild: async () => false` in the electron-builder config is load-bearing.** Up to v0.2.0, every build packed about 31 MB of unused `node_modules` (the root `dependencies`: Angular, three, three-mesh-bvh, zod, rxjs, CodeMirror, fflate) into `app.asar`. electron-builder 26 searches the app dir, then the project dir and then the workspace root for node modules. `dist/apps/desktop` has none, so it fell back to the root, and since `apps/desktop/package.json` declares no `dependencies` it accepted any non-empty tree. It also ran `@electron/rebuild` on the workspace. Resolving `beforeBuild` to `false` tells electron-builder that node modules are handled externally, so it skips both collection and the rebuild. Don't also set `npmRebuild: false`: that returns before `beforeBuild` runs and brings the bloat back. The fix took `app.asar` from 34.3 MB to 2.9 MB and the Linux AppImage from 132.1 MB to 126.2 MB.
- **Changing the app id or product name after users install breaks their update path** and userData location. Treat `appId` in the electron-builder config as frozen once v0.1.0 ships.
- **Local deb/rpm builds on Fedora** fail with `ruby: … libcrypt.so.1` (electron-builder's bundled fpm) and need `rpmbuild` for rpm: `sudo dnf install libxcrypt-compat rpm-build`. The AppImage builds without them. Ubuntu CI runners have libcrypt; `release.yml` installs `rpm`.
- **No app icon yet:** builds use electron-builder's default Electron icon until `apps/desktop/build-resources/icon.png` (1024×1024) is added.
- **macOS universal** builds download both x64 and arm64 Electron; `CSC_IDENTITY_AUTO_DISCOVERY=false` in `release.yml` keeps the runner from trying to sign with a stray identity.
- **Packaged smoke tests: one launch per file, fresh profile per launch.** A second launch of the packaged app in the same CI job never came up on macOS or Windows (`connectOverCDP … ECONNREFUSED` / timeout), even after waiting for the first process to exit. The launcher now gives every launch its own `CONTROLS_USER_DATA_DIR` (separate single-instance lock and profile), and `smoke.spec.ts` launches once in `beforeAll`. Rehearse packaging changes with **Actions → release → Run workflow** (`workflow_dispatch`): it packages and smoke-tests all three OSes and uploads nothing.
- **Attach to the packaged app only once it lists its page.** The v0.2.0 release run hung on macOS and Linux: `connectOverCDP` connected its WebSocket, then never finished attaching, and used its whole 30 s timeout (so the retry loop never retried). Attaching while the app is still creating its window is racy. `launch.ts` now polls the plain-HTTP `/json/list` until the `app://game/` page is listed (failing fast if the process exits), then attaches with a 10 s timeout per attempt. Don't attach earlier to save time.
- **`gh release delete <tag> --cleanup-tag` can leave a draft behind.** Clearing the partial v0.2.0 draft removed the tag but not the draft release. Check `gh release list` afterwards, and delete a leftover draft by id through the API (`gh api repos/{owner}/{repo}/releases --jq '.[] | select(.draft) | {id, tag_name}'`, then `gh api -X DELETE repos/{owner}/{repo}/releases/<id>`) before re-cutting the tag.
- **`release.yml` is read-only by default; only the `build` job gets `contents: write`**, because `electron-builder --publish always` creates and updates the draft release. The `verify` job runs `pnpm verify` (every dependency's install scripts and the whole test suite) with a read-only token. Give any new job the least it needs at job level; never widen the workflow-level `permissions`.
- **`release.yml` installs dependencies without the pnpm store cache** (`uses: ./.github/actions/setup` with `cache: 'false'`). It is the only workflow with a `contents: write` token and it publishes what players install, so it doesn't restore a cache another run wrote (setup-node's cache-poisoning advice). Each OS pays for a full install from the registry; the lockfile's integrity hashes still apply.
- **Checkout in `release.yml` doesn't persist credentials.** electron-builder publishes through the REST API with `GH_TOKEN`, not git. If a step ever needs `git push` (for example tagging from CI), opt that one checkout back in.
- **Failure artifacts:** `release-logs-<os>-<run_id>-<attempt>` holds `dist/.playwright` (needs `include-hidden-files: true`, because it's a dot-directory) and `dist/release/builder-debug.yml`. Before October 2026 only `builder-debug.yml` was uploaded (the v0.1.0 run's macOS artifact was 610 bytes). Action pinning and update procedure: [workspace caveats](workspace.md).
- **Action bumps reach `release.yml` untested** until the next tag, because PR CI never runs it. After changing an action or the setup composite, run **Actions → release → Run workflow** on the branch (`gh workflow run release.yml --ref <branch>`): it runs the same verify, setup, package and smoke steps on all three OSes. It skips only the tag/version check and `--publish always` (both `if: github.event_name == 'push'`), so it uploads nothing.
