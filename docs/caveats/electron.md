# Electron caveats

**Load this when:** touching `apps/desktop` (main, preload, protocol, window creation, updater), `apps/desktop-e2e`, `libs/platform/electron`, `libs/ipc-contract`, the CSP, or Electron Fuses.

- **Content is served from `app://`, never `file://`.** The protocol handler serves the Angular build and adds `Cross-Origin-Opener-Policy: same-origin`, `Cross-Origin-Embedder-Policy: require-corp` and the CSP to every response. Without COOP/COEP the page isn't `crossOriginIsolated`, `SharedArrayBuffer` is undefined, and the sim worker (P2) has no fast path. F0.2 requires an automated check that `crossOriginIsolated === true`; never remove it.
- **The CSP** is `script-src 'self' 'wasm-unsafe-eval'; worker-src 'self' blob:` (plan §4.11). Angular needs `style-src 'self' 'unsafe-inline'` unless nonces are used (tech-stack research §7). Never add `'unsafe-eval'`: the PLC runtime compiles to closures or a VM, never `eval`.
- **Security posture is non-negotiable:** `contextIsolation: true`, `sandbox: true`, `webSecurity: true`, `nodeIntegration: false`. `will-navigate` and `setWindowOpenHandler` deny by default. Fuses (`electronFuses` in `electron-builder.config.cjs`) disable RunAsNode, `NODE_OPTIONS` and the Node CLI inspect flags, and enable cookie encryption, embedded ASAR integrity validation and OnlyLoadAppFromAsar. Check them in a packaged build with `npx @electron/fuses read --app <path>`.
- **IPC:** the preload exposes a narrow typed API through `contextBridge`, never raw `ipcRenderer`. Use `invoke`/`handle`. Every payload is parsed with the Zod schema from `@controls/ipc-contract` in main, and `event.senderFrame` is checked. Define the schema first, then the handler, then the preload export, then the `platform-electron` consumer. Handlers live in `apps/desktop/src/ipc-handlers.ts` with no `electron` import (they take a sender-like object and injected dependencies), so the origin check and validation are unit-tested; `ipc.ts` only wires them to `ipcMain`. Errors carry a reason code, never the payload (`settings:set refused (invalid).`).
- **Channels today:** `app:info`, `settings:get`, `settings:set` and `app:quit`; the bridge keys are asserted in `smoke.spec.ts`, so update that list with a new channel. `settings:set` serialises the payload, caps it at `MAX_SETTINGS_JSON_LENGTH` (1 MiB), re-parses the JSON text and requires a valid **current-version** document via `migrateSettings` (which also rejects `"__proto__"` keys and deep nesting). Main never migrates on write. `app:quit` calls `app.quit()`, so Quit works on macOS, where closing the last window doesn't end the app.
- **Main and preload are bundled by esbuild, including all their dependencies.** The packaged app directory `dist/apps/desktop` gets a generated `package.json` and **no `node_modules`**. Marking a runtime dependency as `external` works in dev and crashes the packaged app on launch. Only `electron` itself is external.
- **The preload runs sandboxed**, so it can only `require` Electron's sandbox-safe modules. Keep it a thin bridge; put logic in main or in the renderer.
- `apps/desktop/package.json` holds the app version that electron-builder reads. It is written by `pnpm version:sync`; don't edit it by hand (see [release caveats](release.md)).
- **WebGPU on Linux depends on drivers and Vulkan.** `WebGPURenderer` falls back to its WebGL2 backend on its own when WebGPU is unavailable; the about box shows which backend is active. `?renderer=webgl2` forces the fallback (`forceWebGL`), and `apps/game-e2e` asserts that path on every run, so keep the query param working.
- **`pnpm e2e:desktop` runs against the built app**, not a dev server (the Nx target builds first). It uses Playwright's `_electron.launch()`, which needs Node's `--inspect`. **The release Fuses disable `--inspect`**, so `_electron` hangs on a packaged binary: with `CONTROLS_E2E_EXECUTABLE=<binary>` the launcher in `apps/desktop-e2e/src/launch.ts` starts the binary itself with `--remote-debugging-port` and attaches over CDP. Keep both paths working; `release.yml` smoke-tests the packaged app this way.
- **`CONTROLS_USER_DATA_DIR`** overrides Electron's `userData` path before the single-instance lock is taken (`apps/desktop/src/main.ts`). The e2e launcher uses it for a throwaway profile per launch; it also lets a dev build run beside an installed one.
- **Settings file:** `settings.json` in `userData`, so `CONTROLS_USER_DATA_DIR` moves it too. `SettingsFile` writes atomically (`writeFileAtomic`: temp file in the same directory, `fsync`, `rename`; the temp file is removed on failure) and serialises writes so the last one wins. Reads never throw: a missing file is a first run (no warning), and a file that is oversized (checked with `stat` before reading), unreadable, not JSON, foreign or newer than the build gives defaults plus a `fallbackReason`. The file is not rewritten until the player changes a setting, so a newer build's file survives a downgrade until then.
- **Relaunch tests run against the dev build only.** `settings-persistence.spec.ts` launches twice with one `userDataDir` (`createProfile()`, passed to `launchControls({ userDataDir })`, which then doesn't delete it) and skips itself when `CONTROLS_E2E_EXECUTABLE` is set, because packaged builds get one launch per file ([release caveats](release.md)). `quit.spec.ts` is a single launch in its own file, so it also runs packaged.
- Locally on a desktop session, `CONTROLS_E2E_HEADLESS=1` adds `--ozone-platform=headless` so no window pops up (renders via WebGL2/SwiftShader). CI uses `xvfb-run` instead. **Use it for the packaged (CDP) path on a Linux desktop session.** Without it, `connectOverCDP` intermittently connects to the websocket and then times out (seen on Fedora 44 with both electron-builder 26.18.0 and 26.18.1; one windowed run passed, two failed). Headless runs passed every time.
- **`desktop-e2e:e2e` is never cached** (`"cache": false` in its `project.json`). It tests a binary outside Nx's inputs: `CONTROLS_E2E_EXECUTABLE` can point at a packaged build that was rebuilt at the same path, so env inputs alone would still allow a false cache hit. Every run launches the app; `--skip-nx-cache` is not needed. (An earlier note here claimed the target was cached; Nx's task history shows it never was, but the explicit `false` keeps a future `targetDefaults` or plugin change from turning caching on.) `game-e2e:e2e` is inferred by `@nx/playwright` and _is_ cached.
- **Angular's critical-CSS inlining is off** (`optimization.styles.inlineCritical: false` in `apps/game/project.json`): it emits an inline `onload` handler that the CSP's `script-src 'self'` blocks.
- **The preload imports `@controls/ipc-contract/preload`**, a narrow entry with only channel names and types. Importing the package index pulls Zod into the preload (≈450 KB instead of <1 KB), since the schema modules have top-level side effects.
- **Path traversal:** `resolveAppPath` relies on the URL parser collapsing `..`/`%2e%2e`, then a containment check against the renderer root catches encoded separators (`..%2F`). Both are unit-tested in `app-protocol.spec.ts`; keep the containment check even if it looks redundant.
- Electron is listed in `pnpm-workspace.yaml` `allowBuilds`; if its postinstall is skipped, the Electron binary is missing and launch fails with a confusing path error.
