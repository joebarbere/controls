# Electron caveats

**Load this when:** touching `apps/desktop` (main, preload, protocol, window creation, updater), `apps/desktop-e2e`, `libs/platform/electron`, `libs/ipc-contract`, the CSP, or Electron Fuses.

- **Content is served from `app://`, never `file://`.** The protocol handler serves the Angular build and adds `Cross-Origin-Opener-Policy: same-origin`, `Cross-Origin-Embedder-Policy: require-corp` and the CSP to every response. Without COOP/COEP the page isn't `crossOriginIsolated`, `SharedArrayBuffer` is undefined, and the sim worker (P2) has no fast path. F0.2 requires an automated check that `crossOriginIsolated === true`; never remove it.
- **The CSP** is `script-src 'self' 'wasm-unsafe-eval'; worker-src 'self' blob:` (plan §4.11). Angular needs `style-src 'self' 'unsafe-inline'` unless nonces are used (tech-stack research §7). Never add `'unsafe-eval'`: the PLC runtime compiles to closures or a VM, never `eval`.
- **CodeMirror 6 (the F1.5 console) runs under the CSP unchanged.** It never evaluates code, but it styles itself: `style-mod` writes its rules into a `<style>` element in `<head>` (constructable stylesheets are used only in a shadow root) and the editor sets `style` attributes such as `tab-size`. Both rely on the same `'unsafe-inline'` as Angular. Dropping `'unsafe-inline'` for nonces would need `EditorView.cspNonce` for the `<style>` element and a plan for the `style` attributes ([ADR 0008](../decisions/0008-console-and-scripts.md#codemirror-6-in-the-in-game-console-f15)). The editor is a lazy chunk served from `app://` like the rest (`script-src 'self'`). `smoke.spec.ts` opens the console under the real CSP, runs `world.hash` and asserts no `securitypolicyviolation`; keep it.
- **Security posture is non-negotiable:** `contextIsolation: true`, `sandbox: true`, `webSecurity: true`, `nodeIntegration: false`. `will-navigate` and `setWindowOpenHandler` deny by default. Fuses (`electronFuses` in `electron-builder.config.cjs`) disable RunAsNode, `NODE_OPTIONS` and the Node CLI inspect flags, and enable cookie encryption, embedded ASAR integrity validation and OnlyLoadAppFromAsar. Check them in a packaged build with `npx @electron/fuses read --app <path>`.
- **IPC:** the preload exposes a narrow typed API through `contextBridge`, never raw `ipcRenderer`. Use `invoke`/`handle`. Every payload is parsed with the Zod schema from `@controls/ipc-contract` in main, and `event.senderFrame` is checked. Define the schema first, then the handler, then the preload export, then the `platform-electron` consumer. Handlers live in `apps/desktop/src/ipc-handlers.ts` with no `electron` import (they take a sender-like object and injected dependencies), so the origin check and validation are unit-tested; `ipc.ts` only wires them to `ipcMain`. Errors carry a reason code, never the payload (`settings:set refused (invalid).`).
- **Channels today:** `app:info`, `settings:get`, `settings:set`, `app:quit`, `app:flush-ack`, `save:list`, `save:read`, `save:write`, `dialog:open`, `dialog:saveAs`, and `app:flush-request`, the one main → renderer channel (`webContents.send`, no handler in main). The bridge keys (`getAppInfo`, `getSettings`, `setSettings`, `quit`, `onFlushRequest`, `ackFlush`, `listSaves`, `readSave`, `writeSave`, `showOpenDialog`, `showSaveAsDialog`) are asserted in `smoke.spec.ts`, so update that list with a new channel. `settings:set` serialises the payload, caps it at `MAX_SETTINGS_JSON_LENGTH` (1 MiB), re-parses the JSON text and requires a valid **current-version** document via `migrateSettings` (which also rejects `"__proto__"` keys and deep nesting). Main never migrates on write. `app:quit` calls `app.quit()`, so Quit works on macOS, where closing the last window doesn't end the app.
- **Flush before quit.** Angular's `DestroyRef.onDestroy` does **not** run when Electron closes the window or quits, so a renderer that buffers writes (the 300 ms settings debounce, F1.8b's autosave in part 3) loses them unless main waits. `QuitGuard` (`apps/desktop/src/flush-before-quit.ts`, electron-free and unit-tested) prevents the window's `close` and the app's `before-quit` once, sends `app:flush-request { requestId }`, waits for `app:flush-ack { requestId, ok }` or `FLUSH_BEFORE_QUIT_TIMEOUT_MS` (2 s, in `@controls/ipc-contract`), then repeats the close or quit, which passes. `before-quit` covers the menu's Quit (`app:quit` → `app.quit()`), Cmd+Q, the Dock and `window-all-closed`; the window's `close` covers the title-bar button. A close during a quit shares the quit's flush. The outcome is never an error: `failed` (the renderer already told the player), `timeout` (logged) and `gone` (destroyed or crashed `WebContents`, no wait) all close or quit.
  - **The ack is checked three ways:** `senderFrame` is `app://`, the payload passes `FlushAckSchema`, and the request id is pending **for that `WebContents` id**. A forged, late or cross-window ack is refused (`app:flush-ack refused (unknown-request).`) and never settles anything.
  - **The preload forwards the payload only**, never the `IpcRendererEvent`, so `event.sender` can't reach the page. `ElectronAppLifecycle` (`platform-electron`) subscribes when the platform is created, so main gets an ack even with nothing registered; it validates the request with `FlushRequestSchema` and ignores a bad one (main times out). Main owns the deadline; there is no renderer-side timeout.
  - **Features register through `Platform.lifecycle.onBeforeQuit(flush)`** (Angular: the `APP_LIFECYCLE` token in `feature-shell`), never by talking to IPC. A flush must also wait for writes already in flight: an invoke that main hasn't finished when the ack arrives is cut off by the quit.
  - **Playwright's `ElectronApplication.close()` is `app.quit()`** followed by waiting for the process to exit, so it goes through `before-quit` and the handshake like a player's Quit. `LaunchedControls.closeWindow()` runs `BrowserWindow.close()` in main for the window path (dev build only: a packaged build has no inspector). `settings-persistence.spec.ts` changes a setting and quits, or closes the window, inside the debounce; both failed before the handshake. The packaged CDP path ends the app with a signal, which bypasses `before-quit`; that is a test harness exit, not a player one.
- **Save I/O (F1.8b, [ADR 0009](../decisions/0009-save-io-boundary.md)).** Main owns `<userData>/saves/` (`SaveStore`, electron-free and unit-tested); the renderer gets **opaque handles**, never paths, and save bytes are opaque (the `.ctrl` codec is `save-format`'s).
  - **Handles** are 22 random base64url characters in `SaveHandleTable`, scoped to the `WebContents` that received them (`event.sender.id`) and dropped when it is destroyed. A handle from another window or a guessed one is `unknown-handle`; one that isn't 22 base64url characters is `invalid`. Open gives a **read-only** handle, Save As a **write-only** one, and autosave slots are read-only (only `write({ kind: 'autosave' })` writes them). Never persist a handle: they die with the window.
  - **Names, not paths:** a manual save is `SaveNameSchema` (no separators, no Windows device names, no trailing dot or space) → `<name>.ctrl`; `pathOf` still checks the result is a direct child of its directory. `..` is a legal name (`...ctrl` in the save directory); that is fine.
  - **Reads** `lstat` (regular file only, size ≤ `MAX_SAVE_BYTES`, 64 MiB) then open with `O_NOFOLLOW` and `fstat` again. Windows has no `O_NOFOLLOW` (`constants.O_NOFOLLOW` is undefined there), so the `lstat` is what refuses a symlink. **Writes** replace a symlink rather than follow it. The `autosave/` subdirectory must be a real directory; a symlink there refuses autosaves and hides them from the list (manual saves still list).
  - **Atomic writes** are `writeFileAtomic` (`atomic-write.ts`, shared with settings): temp file in the same directory opened `wx` 0600, write, `fsync`, `rename`, then `fsync` the directory (POSIX, best effort: the rename already happened). `save-store.spec.ts` fails the write at open, half-way through the data, at `fsync` and at the rename, and checks the old file's bytes and that no temp file is left. All writes are serialised, so autosave slot choice can't race.
  - **Errors** are `<channel> refused (<code>).` with a `SaveIoErrorCode`; file-system errors are `io`, and main logs only the errno code (an `EACCES` message contains the path). `platform-electron` turns the message back into `SaveIoError.code` with `saveErrorCodeOf`, which copes with Electron's `Error invoking remote method '…': Error: …` wrapper.
  - **Dialogs** are one at a time per window (`busy`). `ipc.ts` looks up `dialog.showOpenDialog` / `showSaveDialog` on each call, so `desktop-e2e/src/saves.spec.ts` can stub them with `LaunchedControls.evaluateMain` (dev build only; that test skips on a packaged build). Save As appends `.ctrl` when the player leaves it off. Never return the picked path: the response is a handle plus the base name.
  - **The bytes cross `contextBridge` as `Uint8Array`** and arrive in main as one. Check them with `isUint8Array` (realm-independent), not `instanceof`.
  - **The contract suite** (`describeSaveIoContract`, `@controls/platform-api/testing`) runs in `apps/desktop/src/save-io-contract.spec.ts` against `ElectronPlatform` over an in-process bridge that structured-clones payloads like IPC. A behaviour change on one platform must change the suite, which then fails on the other until it matches.
- **Main and preload are bundled by esbuild, including all their dependencies.** The packaged app directory `dist/apps/desktop` gets a generated `package.json` and **no `node_modules`**. Marking a runtime dependency as `external` works in dev and crashes the packaged app on launch. Only `electron` itself is external.
- **The preload runs sandboxed**, so it can only `require` Electron's sandbox-safe modules. Keep it a thin bridge; put logic in main or in the renderer.
- `apps/desktop/package.json` holds the app version that electron-builder reads. It is written by `pnpm version:sync`; don't edit it by hand (see [release caveats](release.md)).
- **WebGPU on Linux depends on drivers and Vulkan.** `WebGPURenderer` falls back to its WebGL2 backend on its own when WebGPU is unavailable; the about box shows which backend is active. `?renderer=webgl2` forces the fallback (`forceWebGL`), and `apps/game-e2e` asserts that path on every run, so keep the query param working.
- **`pnpm e2e:desktop` runs against the built app**, not a dev server (the Nx target builds first). It uses Playwright's `_electron.launch()`, which needs Node's `--inspect`. **The release Fuses disable `--inspect`**, so `_electron` hangs on a packaged binary: with `CONTROLS_E2E_EXECUTABLE=<binary>` the launcher in `apps/desktop-e2e/src/launch.ts` starts the binary itself with `--remote-debugging-port` and attaches over CDP. Keep both paths working; `release.yml` smoke-tests the packaged app this way.
- **`CONTROLS_USER_DATA_DIR`** overrides Electron's `userData` path before the single-instance lock is taken (`apps/desktop/src/main.ts`). The e2e launcher uses it for a throwaway profile per launch; it also lets a dev build run beside an installed one.
- **Settings file:** `settings.json` in `userData`, so `CONTROLS_USER_DATA_DIR` moves it too. `SettingsFile` writes atomically (`writeFileAtomic`: temp file in the same directory, `fsync`, `rename`; the temp file is removed on failure) and serialises writes so the last one wins. Reads never throw: a missing file is a first run (no warning), and a file that is oversized (checked with `stat` before reading), unreadable, not JSON, foreign or newer than the build gives defaults plus a `fallbackReason`. The file is not rewritten until the player changes a setting, so a newer build's file survives a downgrade until then.
- **Relaunch tests run against the dev build only.** `settings-persistence.spec.ts` launches twice with one `userDataDir` (`createProfile()`, passed to `launchControls({ userDataDir })`, which then doesn't delete it) and skips itself when `CONTROLS_E2E_EXECUTABLE` is set, because packaged builds get one launch per file ([release caveats](release.md)). `quit.spec.ts` is a single launch in its own file, so it also runs packaged.
- Locally on a desktop session, `CONTROLS_E2E_HEADLESS=1` adds `--ozone-platform=headless` so no window pops up (renders via WebGL2/SwiftShader). CI uses `xvfb-run` instead. **Use it for the packaged (CDP) path on a Linux desktop session.** Without it, `connectOverCDP` intermittently connects to the websocket and then times out (seen on Fedora 44 with both electron-builder 26.18.0 and 26.18.1; one windowed run passed, two failed). Headless runs passed every time.
- **`desktop-e2e:e2e` is never cached** (`"cache": false` in its `project.json`). It tests a binary outside Nx's inputs: `CONTROLS_E2E_EXECUTABLE` can point at a packaged build that was rebuilt at the same path, so env inputs alone would still allow a false cache hit. Every run launches the app; `--skip-nx-cache` is not needed. (An earlier note here claimed the target was cached; Nx's task history shows it never was, but the explicit `false` keeps a future `targetDefaults` or plugin change from turning caching on.) `game-e2e:e2e` is inferred by `@nx/playwright` and _is_ cached.
- **Angular's critical-CSS inlining is off** (`optimization.styles.inlineCritical: false` in `apps/game/project.json`): it emits an inline `onload` handler that the CSP's `script-src 'self'` blocks.
- **The preload imports `@controls/ipc-contract/preload`**, a narrow entry with only channel names and types. Importing the package index pulls Zod into the preload (≈450 KB instead of <1 KB), since the schema modules have top-level side effects.
- **Path traversal:** `resolveAppPath` relies on the URL parser collapsing `..`/`%2e%2e`, then a containment check against the renderer root catches encoded separators (`..%2F`). Both are unit-tested in `app-protocol.spec.ts`; keep the containment check even if it looks redundant.
- Electron is listed in `pnpm-workspace.yaml` `allowBuilds`; if its postinstall is skipped, the Electron binary is missing and launch fails with a confusing path error.
