# Scripting caveats

**Load this when:** working on `libs/domain/scripting-api`, the console-line parser in `libs/domain/commands/src/lib/console/`, `apps/sim-cli` or its scenarios, writing a scenario script, or changing a command's args shape. Decisions: [ADR 0008](../decisions/0008-console-and-scripts.md). Architecture: [scripting](../architecture/scripting.md). How-to: [scripting guide](../guides/scripting.md).

- **Args key order is console grammar.** Positional console words fill a command's args keys in declaration order (`entity.delete 3` → `{ id: 3 }`). Reordering the keys of an args `z.strictObject` silently changes what existing `.console` files mean (replay logs are unaffected). Treat it as a breaking change with a CHANGELOG line.
- **The console mapping types words; Zod validates them.** `consoleArgs` only decides number versus string versus boolean from the leaf schema and rejects unknown flags with a column. Bounds and required fields come from `exec`. Don't add validation to the mapping, or the console and the palette will disagree.
- **New Zod wrapper kinds need a look at `unwrap()`** in `console/args.ts` (it strips optional, default, prefault, nullable, readonly, catch, nonoptional and pipe input). An unrecognised wrapper falls back to the word's lexical type, which may turn `"12"` into a number for a string field.
- **Arrays have no console syntax.** `formatConsoleLine` throws `ConsoleFormatError` for arrays and empty objects, so `toConsoleScript` throws for a log containing one. The first command with an array arg must extend the grammar (ADR 0008).
- **`Game.world()` snapshots are deep-frozen, in place.** `createGame({ world })` freezes the world you pass (it keeps the object, so `Session.world()` is still that object), and every later state is frozen as it's committed. Code that mutated a world document worked by accident before; now it throws in strict mode. Copy first.
- **`Session` must not touch the bus.** It drives a `Game` (`createGame`, `game.on('executed')`); don't reach past it to a `CommandBus`, or the UI and scripts stop running identical code.
- **The renderer never loads scripts.** Only `apps/sim-cli` bundles and imports TypeScript, with esbuild, in Node. Never add a loader to a library or the game, and never relax the CSP's eval ban to run one. In-game, `run <file>` takes console-line files only.
- **esbuild is a run-time dependency of `sim-cli` only**, loaded with `import('esbuild')` when a module script runs and kept external in the bundle. `replay`, `hash` and console-line runs must keep working without it.
- **Script imports are allow-listed** (relative, `type:domain` aliases read from `tsconfig.base.json`, `zod`). A new domain lib is allowed automatically once its path is in `tsconfig.base.json` under `libs/domain/`. `@controls/save-format/testing` is allowed but needs fast-check, which isn't, so it fails to bundle.
- **`pnpm sim` rebuilds the bundle each time** (`bin/sim.mjs`) instead of going through Nx, so stdout stays data-only. Use `pnpm --silent sim …` to also drop pnpm's script banner when piping.
- **Relative paths resolve against `INIT_CWD`**, the directory `pnpm sim` was typed in, not the repository root pnpm switches to.
- **The palette scenario hash is pinned too** (`PALETTE_PLACE_UNDO_HASH` in `apps/sim-cli/src/palette-place-undo.spec.ts` and `apps/game-e2e/src/palette.spec.ts`). `scenarios/palette-place-undo.console` must list exactly the logged commands the palette e2e runs (the e2e compares its replay log's ids with the file); `palette.open` is unlogged, so it isn't in either. Change the file, both literals and the e2e steps together.
- **The four-surface hash is pinned** (`FOUR_SURFACE_HASH` in `apps/sim-cli/src/four-surface.spec.ts`). It changes only if the scenario, a command's semantics or the world hash changes; the game-e2e drivers (F1.3, F1.5, F1.7) must assert the same value, so change them together. `apps/game-e2e/src/console.spec.ts` runs `four-surface.console` through the in-game console's `run` and asserts it.
- **The console place-then-undo hash is pinned too** (`CONSOLE_PLACE_UNDO_HASH` in `apps/sim-cli/src/console-place-undo.spec.ts`, for `scenarios/console-place-undo.console`: one place, then undo). Undoing the place restores the world exactly, so it equals the empty seed-0 world's hash. `apps/game-e2e/src/console.spec.ts` types those lines and asserts the literal, and also types the lines of F1.3's `palette-place-undo.console` from a fresh session and asserts `PALETTE_PLACE_UNDO_HASH`: the direct console-versus-palette cross-check. Change the literals in both e2e files and the sim-cli specs together.
- **`consoleFields` shares `unwrap()` with `consoleArgs`** (`console/args.ts`), so completion and `help` offer exactly the flags the mapping accepts. Change both together, and keep the spec that maps every listed field.
- **`sim-cli`'s `test` target depends on `build`** and lists the root `eslint.config.mjs` and `tsconfig.base.json` as inputs (the boundary test lints with the real config, and the script loader reads the aliases). Keep both, or Nx can replay a stale pass.
- **The determinism lint covers `apps/sim-cli`** (including `scenarios/`), not just `libs/domain/`. A scenario that reads the clock can't be re-run to the same hash.
- **Scenarios start from the workshop level (F1.9).** Every `apps/sim-cli/scenarios/*` file and its spec runs with `--world content/levels/workshop.json` (in-process: `createGame({ world: workshopWorld() })` from `src/testing/workshop.ts`), because New sandbox with seed 0 starts from exactly that world, so the game-e2e drivers and the headless drivers share golden hashes. `CONSOLE_PLACE_UNDO_HASH` therefore equals the workshop's own hash (`WORKSHOP_HASH`, pinned by `src/workshop.spec.ts`, which also runs `sim hash content/levels/workshop.json`). A level edit moves every scenario golden: re-pin them all, in sim-cli and game-e2e, together.
- **`--world <file> --seed N`** starts a new game on that level with seed N (`newGameWorld`, what New sandbox does); `--world` alone runs the document as it is, and `--seed` alone seeds an empty world. Before F1.9 the two flags were mutually exclusive.
- **Scripts snap against `worldSnapTargets(game.world())`**, the world they were given, not a fixed table. The pre-F1.9 `demoPanelSnapTargets()` is gone.
